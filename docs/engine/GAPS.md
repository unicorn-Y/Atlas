## Component comparisons

Each section records behavior found in the complete relevant upstream directory, Atlas behavior before this change, changes made, and behavior intentionally left out with its reason.

### 1. Turn loop and state (`core/atlas/kernel/loop.py`, `state.py`)

**Upstream and prior gap.** Codex's `session/` turn driver and helpers, together with ZCode's `agent/` turn machine/state, split model streaming, tool scheduling, approval, aggregation, compaction, interruption and completion into explicit lifecycle boundaries. Atlas previously had only coarse phases around streaming/tools/compaction. The loop forwarded text deltas, but did not keep attempt-scoped reasoning/refusal/tool-call fragments in run state; its phase graph also skipped the separate model-wait, tool-scheduling and result-aggregation boundaries. Context-window errors had no forced-compaction recovery path, and a PreToolUse `ask` decision was treated as a rejection.

**Added.** `RunPhase` now models awaiting-model, scheduling-tools and aggregating-results transitions and rejects invalid phase changes. Per-attempt stream state collects text, reasoning, refusal and indexed tool-call fragments while preserving the existing `chunk` event for user-visible text; canonical model responses still drive tool dispatch, and the new item types do not alter the public event dictionary. Retry/usage records include purpose, model/provider, category/status, attempt, delay/retry-after/kind, request token estimates, provider usage and per-run totals. A single provider context-window failure can force compaction and retry once; repeated overflow or a blocked/no-op compaction returns the original failure. Immediate steers cancel the in-flight model request, persist the steer, preserve partial assistant output, refresh canonical session history and resume; queued steers are applied at the existing safe point. Cancellation preserves partial text/refusal and repairs outstanding calls with a result that distinguishes calls not started (safe to retry) from started calls (outcome unknown, inspect before retry). Tool approvals use the existing approval callback/event; `updatedInput` is applied before dispatch. SessionStart additional context is inserted into the rebuilt system prompt. PostToolUse output/context updates feed the recorded tool result, PostToolBatch feedback is queued, and a blocked batch ends with a persisted assistant reason instead of raising a runtime error. A Stop block requests one corrective response and is ignored if it repeats; stuck detection nudges once, then halts a repeated pattern.

**Intentionally retained / not ported.** Streamed reasoning and tool fragments stay internal and are not exposed as new wire events; partial persistence remains limited to assistant text/refusal, with reasoning/tool fragments represented in repair telemetry. Atlas keeps its existing session database, tool scheduler, model transport, event dictionaries and bounded turn limit rather than adopting Codex/ZCode runtime types. PreToolUse `defer` returns a denied tool result because Atlas has no durable suspend/resume approval protocol. The loop consumes SessionStart `additional_context`; other normalized hook metadata such as watch paths or reload-skills is not given new runtime side effects here. If PreCompact blocks, compaction is skipped; a provider overflow can therefore still fail because the same oversized context must be retried. Durable background task controls and provider-specific transport/session mechanisms remain at their existing Atlas owners.

### 2. Model calls (`core/atlas/kernel/model_call.py`)

**Upstream and prior gap.** Codex's retry/client/request code classifies provider failures, honors server delay headers, distinguishes connection retries from general retries, filters duplicate partial output, and emits retry telemetry. Claude Code v2.1.296 public env-var docs expose a default retry limit of 10, an opt-in capacity watchdog, an optional maximum wait, and a configurable 529 backoff base. Atlas previously had a small status/text classifier, a hard retry cap of eight, numeric-only `Retry-After` capped at 60 seconds, no stable context-window/filter/auth/billing categories, and only text deltas.

**Added.** Stable categories now cover context-window overflow (terminal for this layer), content filter, billing, authentication, model-not-found, rate limit, overload, timeout, connection, invalid request, and malformed response; status 413 also maps to context overflow. `Retry-After` accepts seconds and HTTP dates, wrapped headers and Codex's “try again in” text; rate-limit reset timestamps are read for 429/529 where available. Ordinary retry uses Codex's 200 ms exponential backoff with ±10% jitter. 529 uses its own 500 ms exponential base up to 300 seconds. With the documented watchdog opt-in, 429/529 capacity failures retry until the optional aggregate wait limit; absent explicit retry count, other transient errors use the documented 300-attempt watchdog default. Without watchdog, retry count defaults to 10 and honors the documented 15 maximum for the Claude environment override. The watchdog is off by default. Codex connection failures use the 5/10/20/40/60-second sequence and retry by default outside Bedrock. A stream ending without a terminal marker is a retryable connection failure; content-filter finish reasons add the upstream recovery guidance. Each success/failure attempt reports retry kind, count, delay and status through the internal callback. The old `on_text` callback remains; optional `on_event` carries text, reasoning, refusal and indexed tool-call fragments. The loop turns provider context overflow into one forced compaction attempt before retrying.

**Intentionally not ported.** Atlas keeps its existing Chat-completions transport and fallback-model chain. Codex Responses SSE/WebSocket switching, credential refresh and session-source-specific retry exclusions need client/session fields this API does not expose. Claude's closed-source fallback trigger threshold for 529 is not specified publicly, so no threshold is invented. The new internal stream items do not change Atlas's external event dictionaries.

### 3. Tool orchestration (`core/atlas/kernel/tools.py`)

**Upstream and prior gap.** Codex's tool orchestrator and ZCode's scheduler/executor distinguish argument decoding, per-call execution, cancellation, approval/retry, and result delivery. Atlas previously treated cancellation largely as a batch exception and did not normalize all malformed tool-call shapes or `success: false` results.

**Added.** Malformed/non-object function payloads now produce a deterministic failed result instead of aborting the whole batch. A tool result with `success: false` is treated as failure. Cancellation preserves one result per original call: already-started calls carry their actual result/duration; calls not started receive a cancelled result with zero duration; no new calls launch after cancellation. Unknown tools remain serial. The parallel-safe set now includes the verified read-only `read_office`, `coding.repo_map`, `coding.ast_grep.run`, and local file read/list/glob/search/stat operations. Existing dispatch remains responsible for approval, escalation/retry, and output truncation/reference behavior.

**Intentionally retained.** Atlas's existing event/result dictionaries and tool bodies were not changed. Tool-specific approval and retry remain at the existing dispatch seam rather than duplicating them in the scheduler. The parallel allowlist stays explicit; unknown or mutating tools are not assumed safe.

### 4. Process execution (`core/atlas/kernel/exec.py`)

**Upstream and prior gap.** Codex's complete `unified_exec/` directory has a shared process manager, unified output buffer, Windows polling/yield handling and process soft limit. ZCode's bash timeout policy uses a 120-second default and 600-second cap, with explicit auto-on-timeout handoff. Atlas previously used a per-kernel-run manager and had inconsistent timeout/background lifecycle handling.

**Added.** Atlas now applies the ZCode 120-second default and 600-second maximum while retaining its seconds-based argument interface. `action=start` and detached launches have no implicit process lifetime timeout; an explicit Atlas timeout still applies. Timeout results use `timed_out` and exit code 124; user cancellation uses `cancelled`. Status polling, stdin writes, and output reads share an interaction lock. `background` is mapped to native `detached` before dispatch. Detached work survives manager shutdown/run cancellation; non-detached work still goes through the existing process-tree cancellation path. Shell selection, PowerShell fallback, UTF-8 setup, and tree termination remain delegated to `local_process`.

**Intentionally not ported / integration gap.** ZCode auto-background-on-timeout requires a durable cross-run task registry and native handoff, neither of which the per-run manager can provide safely. A later manager cannot restore a prior manager's output buffer or output reference. Atlas stores stdout/stderr separately, so its concatenation cannot reproduce Codex's unified chronological output. Codex's Windows initial-yield, 64-process soft cap, and shared polling policy require a session-level manager. The file's 1 MiB limit is overridden at the loop callsite by Atlas's explicit 10,000-byte default.

### 5. Context compaction (`core/atlas/kernel/context.py`)

**Upstream and prior gap.** Codex computes a token budget from model window, output reserve and buffer and caps preserved recent user messages at 20,000 tokens. ZCode adds age/pressure-based microcompaction and preserves recent tool/user groups. Atlas previously used a default 0.8 ratio and did not include an explicit provider-overflow force path.

**Added.** The default budget now uses the full model window subject to output reserve and buffer, while explicit ratio/cap overrides remain supported. Microcompaction triggers only after 60 minutes of inactivity, keeps the latest five groups, protects errors and non-text results, and requires at least 256 tokens saved; Atlas's output references and head/tail excerpts remain intact. Summary prompts now retain goal/constraints, plan/progress, files/evidence, errors/fixes, unfinished work, and tool-call IDs/completion state. Recent user-message preservation follows the 20,000-token cap. `prepare(..., force=False)` is backward compatible; `force=True` runs the existing pre-compact callback and bypasses the under-budget early return for a bounded provider-overflow recovery.

**Intentionally retained / not ported.** Atlas's copy-on-success behavior and three-consecutive-failure circuit breaker remain. Flow-specific streaming-to-nonstream fallback, remote history truncation, provider cache markers, plan-file reinjection, agent lists, and read-state reminders require model/session data structures this module does not own; the loop/model-call integration handles the single forced compaction attempt.

### 6. Prompt construction (`core/atlas/kernel/prompt.py`)

**Upstream and prior gap.** Codex and ZCode search project instruction files through their directory builders and maintain stable versus dynamic prompt sections. Claude documents project/user memory and skills. Atlas previously loaded only a narrower instruction set and had no optional dynamic environment section.

**Added.** Ancestor and project `AGENTS.md` instructions are merged with bounded total size (32 KiB default); `AGENTS.override.md` supersedes its corresponding file. Claude user memory and project `.claude/CLAUDE.md`, `CLAUDE.local.md`, and `.claude/AGENTS.md` are included in deterministic order. An optional trailing `env_info` argument adds dynamic environment facts after the stable prefix, preserving old positional calls and output shape when omitted. Skill content remains outside this builder.

**Intentionally not ported.** Project-root marker fallback, Claude `@` imports/path-specific and managed policies, child-agent dynamic loading, and ZCode date/meta-user sections have no equivalent interface here. Atlas continues merging both AGENTS and CLAUDE instruction families. The caller must supply environment facts; this module does not probe the machine.

### 7. Edit and patch behavior (`core/atlas/kernel/edit.py`)

**Upstream and prior gap.** Codex's patch crate defines Add/Delete/Update/Move, multiple context hunks and EOF behavior. ZCode has a sequence of exact and progressively weaker matchers plus file-state checks. OpenCode's edit matcher normalizes Unicode quotes/dashes/spaces and trailing whitespace. Atlas already supported the patch grammar and stronger byte snapshots, but Move rejected an existing target and the matchers lacked OpenCode's punctuation normalization and some recovery details.

**Added.** Invalid hunk headers now explain legal syntax. Context/expected-line failures identify the path and failed excerpt and tell the model to reread/correct. Move can replace an existing target only after that target has been read and passes stale-snapshot checks. Empty replacement consumes the following newline when required; an exact no-op patch returns a corrective error. OpenCode's smart-quote/dash/special-space and per-line trailing-whitespace matching was added, with offsets mapped back to original text and unique-match enforcement. Existing `apply_chunks(..., path=None)` remains compatible.

**Intentionally retained.** Atlas still rejects ambiguous matches rather than accepting Codex's first match, preserves a missing final newline, validates all operations before writing, and uses per-file atomic replacement and byte-level stale checks. Its encoding/BOM/mixed-newline handling, authorization-path checks and environment routing guard are stricter. Ellipsis normalization and OpenCode's lack of read snapshots were not adopted. Environment-specific patch selection still belongs to the caller before `EditManager`.

### 8. Plan mode (`core/atlas/kernel/plan.py`)

**Upstream and prior gap.** Codex's Plan preset inherits the selected model and uses Medium reasoning effort; its explicit Plan handler rejects the TODO-style `update_plan` tool. Claude Plan mode permits exploration through read operations and shell commands, then exits Plan mode when approval switches to the selected permission mode. Atlas previously had no Codex-compatible default planning effort.

**Added.** When no existing planning-specific model/reasoning setting or reasoning-stage override is set, Atlas uses Medium effort and inherits the active model. Existing explicit planning settings remain authoritative. No execution-model setting was added.

**Intentionally retained / safety boundary.** Atlas keeps its narrower read-only tool allowlist. Although Claude documents exploratory shell use, the kernel dispatch path is not proven to run Hermes's command-parameter guard, so enabling terminal now could bypass that guard. Neither cited upstream explicitly lists Atlas's `web_extract` tool. Atlas `update_plan()` persists an Atlas plan object and is not the Codex checklist tool, so it remains. Approval still enters through the existing API flow; `PlanMode.approve()` itself has no caller in this checkout. WebSearch registration in Codex is capability/configuration-based, not a Plan-only allowlist.

### 9. Subagents and workflow (`core/atlas/kernel/subagents.py`, `workflow_tool.py`, `core/atlas/workflow/`)

**Upstream and prior gap.** Codex exposes task spawn/send/wait/close/interruption through an agent registry; ZCode has async subagent/workflow lifecycle and journaled DAG execution. Atlas already had isolated synchronous subtask delegation, a per-workflow concurrency semaphore, durable SQLite journal, pause/resume, retry counts and terminal events, but did not expose a generic background-task control API. Workflow node metadata and `changed_files` were previously dropped from results.

**Added.** Workflow node metadata now persists in graph snapshots, appears in `node_completed`, and is returned in tool/group results; `changed_files` are collected from subtask results. Scheduler cancellation/early exit now drains active node tasks to avoid orphan work. Planner preserves an explicit `engine.model_retries` value; when absent it passes `None` so model-call defaults and `CLAUDE_CODE_MAX_RETRIES` apply (10 by default).

**Intentionally not ported / integration contract.** Subtasks continue to wait synchronously for terminal completion and preserve Atlas's explicit-context isolation, permission propagation and cancellation events. The SQLite journal still resets interrupted active nodes to pending while retaining completed results. ZCode's phase-level retry command is absent because Atlas has no matching public operation. A Codex-style background control API needs a shared task-control port from loop/runtime for spawn/send/wait/interrupt/close and stable task IDs/events; `DelegationService` currently owns background/status/steer behavior outside this module. There is no global agent-capacity limit across workflows; that requires a shared runtime gate.

### 10. Repair, stuck detection, and hooks (`core/atlas/kernel/repair.py`, `stuck.py`, hook call sites)

**Upstream and prior gap.** DeepSeek Harness repairs dangling tool calls from turn history; Codex's turn lifecycle distinguishes calls that started from those that did not; OpenHands detects repeated action/observation, repeated identical errors, monologue and alternating loops in a bounded window. Claude Code v2.1.296 documents command-hook matchers, JSON input/output, event-specific decisions and exit-code behavior; Codex `hook_runtime.rs` provides the corresponding event dispatch and payload/result protocol. Atlas already synthesized a tool result for dangling calls and had windowed stuck detection, but its repeated-error predicate accepted different error observations for the same action. Claude hook `ask` was treated as a block, outputs such as updated tool input/output and additional context were not fully applied, and the kernel's direct lifecycle callbacks could duplicate Claude aliases emitted by the existing tool bridge.

**Added.** Repair continues to append exactly one synthetic result per unpaired call: a call with no durable `tool_start` is marked safe to retry, while a call that started is marked outcome-unknown and directs the model to inspect current state. Stuck error detection now requires the same action and the same error observation, matching OpenHands; the bounded scan, one corrective nudge, user-input reset, repeated-call/result, monologue and alternating-pattern checks remain. Hook declarations and matcher fields cover the Claude v2.1.296 event set. The result adapter handles PreToolUse allow/deny/ask/defer and updated input, PermissionRequest decisions, PostToolUse updated output/context/feedback, PostToolUseFailure recovery feedback, SessionStart context, PostToolBatch continuation, Stop retry, PreCompact blocking, worktree/elicitation decisions, and Codex-compatible command exit outcomes. The loop routes `ask` through PermissionRequest and the existing approval callback; tool updates reach dispatch/result persistence. PostToolBatch block/continue=false ends the turn with a final response. A private bridge marker disables only the duplicate `tool.before`/`tool.after` to Claude alias during kernel-owned tool dispatch; Atlas hook commands still run, while the loop owns the one Claude lifecycle invocation. Session IDs are included in hook payloads.

**Intentionally retained / not ported.** Many documented Claude events are recognized by the hook registry but have no matching Atlas runtime lifecycle point in this checkout (for example Setup, InstructionsLoaded, MessageDisplay, Notification, CwdChanged, DirectoryAdded, FileChanged, SessionEnd and Elicitation); declaring an event does not synthesize a trigger. SessionStart currently consumes additional context, not session title/watch-path/skill-reload side effects. PreCompact denial skips compaction, leaving a later provider overflow possible. Existing Atlas repair metadata, event dictionaries, HookStore and tool execution remain authoritative; no new public hook API or tool body was introduced. Source headers now point to the pinned DeepSeek Harness, OpenHands and Codex commits; Claude behavior is tied to the plan's documented v2.1.296 references.

### 11. Rewind and repository map (`core/atlas/rewind/`, `core/atlas/repomap/`)

**Upstream and prior gap.** The latest OpenCode snapshot/revert files moved to `packages/core/src/snapshot.ts` and `packages/core/src/session/revert.ts`. Atlas's V2-A rewind already has byte-copy checkpoints, preview plus `code`/`conversation`/`both` modes, truncation callbacks and router redo. For repository maps, Aider uses PageRank plus bundled tree-sitter pack queries and falls back to legacy queries by exact language filename; Atlas's 31 pack queries matched current Aider, but unsupported/no-query files were dropped from path ranking and eight runtime-supported legacy grammars were missing.

**Added.** Atlas now includes Aider HEAD's exact fallback queries for Fortran, Haskell, HCL, Kotlin, PHP, Scala, TypeScript and Zig. The existing 31 language-pack query files were compared to Aider's same-name files and remain byte-content equivalent after normalization. Legacy-only files with unsupported parser/query nodes are not loaded: Julia's query fails against the pinned runtime grammar, `ql` has no current parser, and the legacy `c_sharp` filename does not match the runtime `csharp` identifier used by Aider's exact-name lookup. Repo-map ranking now retains all Git-visible paths as file-only candidates, so focus/mentioned hints can target unsupported files; it excludes its own `data/repomap/` cache to avoid listing `tags.sqlite3`. Existing symbol ordering remains intact. Aider's important-file prefix is not made unconditional: its source only adds missing important files on the PageRank zero-division fallback, while Atlas now retains every path in the ordinary ranking. Atlas's deterministic alphabetical tail remains more stable than Aider's set-derived remainder.

**Rewind comparison / intentionally retained.** No rewind behavior change was needed after comparing the latest OpenCode snapshot/revert lifecycle. Atlas keeps its existing byte-copy store and three rewind modes. OpenCode's Git-only cached snapshot repository, ignored/untracked size gates, object-pack layout and event-bus stage/clear/commit lifecycle are not imported because they would replace Atlas's existing checkpoint/API contract. Codex baseline continues to provide file-change status and unified diff behavior; no Git subprocess is needed because Atlas's byte snapshot store remains authoritative. The OpenCode and Codex source headers now point at the pinned latest SHAs.
