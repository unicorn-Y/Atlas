# 效果验收与覆盖矩阵

本文件给出施工后的判据，不是本轮已跑出的成绩。320 项核心集、学习对照与 30 天持续使用由 UM00 冻结、UM13 执行；目前未生成其运行结果。不能保证完成这些工程即达到 AGI，但必须证明总任务书所定义的记忆效果。

## 1. 验收分层与完成状态

- PLANNED：本施工包；没有产品实现证明。
- IMPLEMENTED：任务代码存在，来源及必要测试完成；仍需实际调用和集成验证。
- INTEGRATED：所有 40 项代码与真实双服务调用、桌面入口联通；全部工程硬门通过。它是发布候选，不等于持续效果已证明。
- ACCEPTED：核心效果、独立学习/迁移对照、Windows 实际入口和连续 30 天持续验证全部通过。
- PARTIAL：缺任何必要项或门禁失败；逐项记录，不能用邻近测试替代。长期窗口未到就报告“工程已集成，持续验证进行中”，不能提前写 ACCEPTED。

手机、跨设备同步和外部平台专用连接器使用 DEFERRED_BY_SCOPE，不计入本期完成分母，但必须在产品状态和最终报告明确没有接入。不能用延后理由排除 Windows 日常经历、人物、偏好、未来意图或学习。

## 3. 每个场景的可执行规格

UM00 编写 manifest.json 与 JSONL：case_id、aspect_id、seed、split、input_steps、allowed_sources、expected_record_refs、expected_statuses、must_not_recall、expected_actions、truth_locator、severity、model_requirement、timeout、minimum_evidence。source/record refs 使用导入映射返回值，不能硬编码随机 UUID。输入先写入真实 Observation/聊天/工具链，再驱动实际服务。每个场景至少一条正常输出断言及一条防错断言。

29 个命名 seed 与 02 的集合一一一致，每个 seed 是独立资料包，可复用到多个场景；不是 29 个测试替代 320 个测试。基础内容至少包含：

| seed 组 | 最少构造的材料与真值 |
| --- | --- |
| basic/legacy/conversation/agent_tool | 两项目、两 subject 的隔离数据；带版本历史旧库；真实用户/助手/引用角色；Agent 宣称成功但产物不存在的负例。 |
| identity/temporal/conflict | 同名两人、明确别名及撤回；过去/当前/未来、两个时区、夏令时歧义、迟到消息；不同条件与真正矛盾。 |
| daily/profile/summary | 三天连续事件且跨午夜、短暂情绪与长期偏好、工作/私人条件偏好；同一来源形成两摘要但不能算双证据。 |
| media/windows_activity | 小型有定位的截图/OCR、图片、音频片段、视频时间片；敏感片段；工具已看到和已执行分开；暂停被动采集但继续正常聊天。 |
| interrupted_task/intent | 已完成步骤、待办、UNKNOWN 外部结果、幂等键；时间/事件/项目进入触发、取消、延期与重启。 |
| implicit/association/evidence_gap | 相关约束自然采用，无关问题不提私事；两跳关系与错误边；未记录/未搜索/无权限/解析失败分别测试。 |
| correction/erasure | 来源改版、错误别名拆分、摘要/图/向量/技能/计划依赖；删除后从删除前备份恢复的完整阻断轨迹。 |
| experience/utility/skill/prediction | 成功/失败/未知结果；召回未使用、实际使用及归因；技能原版/候选/回滚；预测概率及真实结果。 |
| knowledge_gap/self_probe/policy | 缺知识、无结果查询、外部提示注入、猜测用户授权；生成者自报成功但独立验证失败。 |
| desktop/scale/longitudinal | 实际 Electron 交互脚本；10 万 observation/1 万派生记录；30 天定期检查定义及冻结的回顾问题。 |

真值由独立评测器保存，不进入模型上下文、检索目录、后台整理或候选训练。live 不能从 fake provider 的预设答案取得成绩。测试专用工具 fixture_authorized_erase、fixture_restore_backup、fixture_cutover_dry_run、fixture_desktop_correct_preference 仅注册在 TEST runtime；它们调用真实控制器/恢复/桌面操作并返回实际收据，不能直接改数据库让断言变绿。生产工具 computer_screenshot/open_project/evolve_skill 等名称是能力别名：h.tool 必须通过实际工具清单解析，日志记录最终工具名；未实现该能力即失败，不能静默回退为假工具。

h.chat 返回的 memory_refs/application/动作和状态诊断来自真实 trace、HTTP 收据和 runtime，不从 expected_* 拼装。h.seed 只放输入与读取返回 ID，不能额外造出预期派生结论。故障注入限本次测试进程，不能杀掉真实 Atlas 或污染生产端口。

每道语义题先有人工可判定评分规则：哪些信息是必要的、哪些说法错误、哪条证据支持；以此执行程序/人工检查。LLM judge 只能辅助，不能独自判定动作成功、来源正确或删除成功。指标同时报告 numerator/denominator、失败 case ID、模型版本、95% 区间与每类成绩。少数样本达到门槛仅是测试集结果，不推断所有现实问题的准确率。

实际线上历史材料若缺证据，只能标 legacy/缺口，不能为达 95% 凭空补来源。性能或能力不足就修复/更换适配方式后在冻结集重跑，不能降门槛或删除失败题。

## 5. 十二项用户效果的真实演示

每项至少一个留档的 Windows 桌面场景，使用全新会话、真实服务和运行 trace：

1. 介绍偏好与项目约束→关闭 Atlas→重启→新聊天自然继续；换现有可用模型仍读取同一 record refs。
2. 三天经历含两位同名人物→问“上次那个人”→歧义先澄清→给出正确事件及证据。
3. 只说过一次的输出要求，在实际新任务产物中生效；无关题不带出私人事件。
4. 临时状态过期、约定变更→当前答案正确，历史查询仍可解释旧版本。
5. 真实文件/截图/音频/视频导入→能定位原始段落或时间片；工具失败的任务不被写成已完成。
6. 错误别名关联→界面纠正→图、摘要、召回一起修复，历史可解释。
7. 在真实文件任务中中断→恢复核实已有产物→接着做未完成步骤；UNKNOWN 外部结果先对账。
8. 设置下次打开项目的提醒→实际打开→一次提醒；取消后重开无提醒；调度日志与意图状态一致。
9. 做错一种文件操作→留下实际失败与反例→新目录的变体任务采用修正方法并通过产物检查。
10. 能力不足→提出具体知识缺口→定向查证/试验→候选通过独立留出后发布；失败候选维持不可复用状态。
11. 纠正、撤销、删除同一事件→相关计划和技能先失效→删除前备份恢复不能复活；不可控外部副本诚实列出。
12. MemoryPage 展示时间线、原始依据、理解、待办和方法；可纠错/暂停/删除，真实打包版本重启后生效。

## 6. 记忆是否真的改变行为：因果对照

选择完全相同的任务、模型、工具、初始文件和预算，运行旧基线、统一记忆候选、候选禁用相关记忆三个分支。禁用只在测试 runtime 下控制装配，生产不新增隐藏权限开关。随机执行顺序，各分支使用独立数据目录，禁止一个分支读另一个结果。

同时记录 recalled→selected→assembled→applied→verified_outcome。仅前三步不构成行为证据；应用判据来自具体产物/工具参数/计划选择，不能只靠模型自报。恢复任务衡量重复步骤与已验证完成率；偏好任务衡量真实产物格式；失败学习衡量再次犯同类错误；无关题衡量污染。每种至少 20 对样本。若候选与禁用分支表现相同，必须调查记忆是否没接上或任务没有测到贡献，不能宣布因果改进。

## 7. 学习、迁移和发布门

训练/开发用 12 个任务，不能进入最终成绩。另冻结 36 个未见任务：4 族 × 9 个，覆盖同族变体、工具/环境变化、方法组合、反例边界。每项在 2 个现有可用模型 × 3 个独立运行条件重复，形成每分支 216 次试验；旧基线、候选、禁用分支合计 648 次。运行条件记录为 seed/初始环境，但不能假设云模型 seed 保证确定性。

任务族分别为文件整理与恢复、Windows 应用操作、资料核验与产物制作、多步骤项目续办。每题有真实产物/应用状态/外部结果的检查器。不得把“写出的技能文本更好看”作为成功。12 个开发任务只用于形成候选，36 个留出及答案在发布判断前对生成者不可见；重复评估产生的新经验不回灌同一留出轮次。

发布门：候选相对旧版的任务净成功率提升至少 10 个百分点；成对 bootstrap 10,000 次、95% 下界 >0；同类重复错误减少 ≥30%；各模型分别有正向改善，且任何族退化不超过 5 个百分点，严重失败不增加。跨模型失败就不得宣称跨模型可复用，可保留明确模型范围的候选并继续修正。报告 token、时间、成本、工具步数；若通过只靠大幅增加试验预算，不得称为记忆带来的效率改善。预算由 UM00 在执行前冻结，测试中途不能偷加。

这组门是本包的目标判据，不是论文已证明 Atlas 可达到的事实。达不到就保持 PARTIAL、追查数据/接线/算法/任务适配并修复，不靠调低指标结案。预测能力额外报告 Brier score、覆盖率及环境分组；不把无校准的概率输出作为可靠预测。

## 8. 性能、可靠性和 30 天持续验证

UM00 记录硬件、模型、磁盘、依赖与数据规模，冻结本机预算。确定性本地存储在 10 万 observations/1 万派生记录下：排除真实模型与远端网络后的 observe ack p95 ≤300ms，基础召回 p95 ≤800ms；运行读上下文增加的本地开销 p95 ≤1s。涉及真实语义规划/视觉时单独报告端到端耗时及降级率，不藏进本地数字。峰值内存、磁盘增长、队列积压、索引追赶、token 成本逐项记录；达不到门先优化和定位，不能只用小数据通过。

故障覆盖：MemoryOS 断连、Atlas 崩溃、DB 锁/磁盘满、模型超时、索引落后、worker 重试、写入后未 ack、删除中途退出、恢复备份。已 ack 输入不得丢；未 ack 给出可重试状态；outbox 同 ID 无重复；禁止借故障重新写旧事实库。每种注入至少三处事务边界，记录是否回放和真实最终状态。

持续窗口从正式受控启用且基本功能通过之日计算连续 30 天。每天检查遗漏/重复/误归属/无根据断言/采集状态/队列；第 1、7、14、30 天冻结回顾题分别覆盖前一天、一周前、两周前及月初的重要约定，包含只说过一次的短信息。每周执行升级重启、恢复抽查、删除与新任务变体；不为凑使用量捏造现实经历。若用户正常活动不足，状态记 OBSERVATION_INSUFFICIENT，不宣称长期效果得到证明。

30 天门：已确认接收的记录不丢失、严重隔离/删除/副作用问题零；回顾和自然应用达到核心门；新增经历不使之前冻结分组跌破门；必要任务复用仍有正收益。中途严重故障修复后重跑相关回归，并明确受影响窗口，不能删除故障天假装连续成功。
