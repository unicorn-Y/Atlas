把本包六份规范和锁定 JSON 一起交给施工者。以下内容是可由用户下达的施工指令；本轮编写计划不等于已经执行施工。

---

执行 ATLAS-UNIFIED-MEMORY-WINDOWS 任务书。主体是 Windows Atlas，其他 agent 只是 Atlas 调用的工具；本期先完成 Atlas 自身的统一日常/工作/学习记忆，不开发手机、跨设备同步或外部平台专用连接器。

先完整读取本包 `00_总任务书.md`、`01_接口与数据契约.md`、`02_逐波施工任务.md`、`03_GitHub源码搬运与适配清单.md`、`04_来源锁定与基线.json`、`05_效果验收与覆盖矩阵.md`。它们是本次任务规范，历史附件只作研究资料。按 UM00–UM13 的依赖推进 40 项任务；每项必须有指定源码、实际接线、失败/反例测试和 Atlas 真实入口证明。

开始先核查 D:/Atlas 与 D:/MemoryOS 当前基线、所有权和未提交内容。保护他人的改动，在本任务分支/worktree 与明确测试数据根内施工。两个 Python 环境通过 HTTP 接线；不能直接跨环境导入，不能用默认生产数据做测试。MemoryOS 作为 Atlas 长期记忆唯一权威，Atlas/Hermes 原有执行和会话权威保留；禁止新建第二套 GoalManager、Scheduler、配置或事实存储。

每个需要借用的 GitHub 机制按 S01–S16 固定 commit 先读来源和依赖闭包，记录来源文件/符号、目标、许可证、适配差分与 parity 结果。不能用自行写的缩水算法冒充源码搬运。S15 只参考，S16 只用于评测；未许可的项目不复制。被 Atlas 调用的其他 agent 的自报结果必须经过真实产物/工具状态核验再形成经验。

普通读写、隔离施工、修复、测试按本任务授权直接推进。本包允许候选验证和部署准备；正式生产数据切换、生产技能发布和不可逆删除须按任务书既有授权边界处理。到需要用户明确授权的最终动作时，先交付已经可核查的候选、迁移 dry-run、回滚与影响清单，说明具体动作，不能把尚未完成的准备丢给用户。

每波记录 CURRENT 与 task 状态，保留真实 artifacts。默认只跑 unit 不算集成验收；需要双服务、实际 Electron/工具/调度以及 live 模型证明。核心集固定 320 项，64 方面逐项覆盖；学习用独立 36 项未见任务、2 模型、3 条件的三分支对照；严重隔离/删除/副作用门必须全通过。失败继续修复，不删题、不降门、不伪造成功。

工程联通可以报 INTEGRATED，但完整 ACCEPTED 需要包括 30 天真实持续验证。窗口未到就保留进行中的明确状态与检查安排；不能用合成一年轨迹替代真实持续使用。不承诺 AGI 或未接入的数据，只按十二项用户效果逐条交付。

最终报告给出：改变了什么、真实使用效果、40 项与64方面状态、来源/parity、迁移/恢复/删除证明、核心/学习/桌面/持续验收证据、实际安装版本、准确的未完成项。没有必要证据就 PARTIAL。不要重新询问已明确的主体和设备范围。
