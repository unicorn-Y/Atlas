## 2. F2-A 观察者健壮性（产品缺陷，不只是评测问题）

所有权：Atlas `core/atlas/memory/observer.py`、`observer_prompt.py`。
1. **逐条校验，不整批作废**：模型输出中某一条不合 schema（未知 facet、缺 evidence、evidence 不在本批），只丢弃这一条，并计数 `item_rejected{reason}`；其余合格条目照常提交。整批只有在 JSON 根本解析不了时才失败（失败后按现有重试逻辑处理）。
2. **提问不是记忆**：**不得**把 `QUESTION` 加入 facet 枚举。在提示词里加入明确规则和中文示例："用户的提问、请求、指令本身不记录；只有提问中透露出的事实（例如'我女儿 6 岁了，她该上几年级？'中的'女儿 6 岁'）才记录。"保留 Mastra 原有"陈述 vs 提问"的条目。
3. **模型变体**：查明反代对 `gemini-3.8-flash` 的实际路由（是否被改写成 `-high`，是否开启 thinking）。为观察者和反思者选定一个明确的变体（建议 `gemini-3.8-flash-low`，或在请求里关闭 thinking），写入 Atlas `memory_model` 设置，并在 Atlas 侧的生产配置中生效，不只在评测的隔离配置里生效。修改 `D:\Atlas\data\user-settings.json` 前先备份；只能改 `memory_model` 这一项。
4. 超时：`memory_observe` / `memory_reflect` 的超时在产品配置中设为合理值（建议 120 秒），而不是只在评测脚本里设。
- 完成判据：用 10 段含大量提问的中文对话，真实模型跑 3 次。提问被记成事实 = 0；因单条不合格而整批丢失 = 0；附带 `item_rejected` 统计和单批耗时 p50 / p95。
