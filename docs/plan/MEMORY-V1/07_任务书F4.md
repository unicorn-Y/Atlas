## 1. F4-A 时区修复（产品 bug，最优先）

现象：用户说"明天上午 9 点提醒我"，观察者产出 `valid_from=2026-10-10T09:00:00+00:00`，提醒会在本地 17:00 才响，晚了 8 小时。
1. 观察者和意图桥解析相对时间、钟点时，按**用户本地时区**处理：优先读取 Atlas 配置中的时区（没有就新增 `user.timezone`，默认取系统时区，本机为 Asia/Shanghai），并把时区和当前本地时间传给观察者的提示词；存储时带正确的偏移（`+08:00`）。
2. 检查同类路径：反思者的日 / 周概括按本地日期切分；MemoryOS 的 as-of 和相对时间查询（"前几天"）也按本地时区计算。
3. 测试：对"明天上午 9 点""下周三下午三点""今晚八点"这类说法写单元测试，覆盖跨日边界（本地 23:30 说"明天"）；外加一次真实模型冒烟，确认 Automation 中任务的触发时间是本地 9:00。

## 2. F4-B 提醒只建一个，并且聊天能取消、能改时间（决定 ①）

E8 审计口径改为：**看用户最终是否拿到一个正确、可取消的提醒**，接受由流水线（观察者 → 意图桥）创建的提醒，不要求一定是模型主动调用工具。但必须同时满足：
1. **去重**：同一个意图只产生一个 Automation 任务。模型自己调了 `automation_manage`、流水线又识别出同一意图时，不得建出第二个（例如按来源消息 id 加意图关联键做幂等）。写测试覆盖"模型调工具 + 流水线同时触发"。
2. **取消和改时间**：聊天中说"取消那个提醒""改到下午三点"，对应的 Automation 任务被取消或更新，旧时间不再触发。写真实服务测试，并做一次真实模型冒烟。
3. 审计判词按新口径修改，修改前后的判词都写进报告；不得为此放宽其他断言。

## 3. F4-C 测试时钟驱动 Atlas 侧的"当前时间"（决定 ②）

目前测试时钟只通到记忆层，Atlas 侧（系统提示中的日期、时间工具、观察者的"今天"）仍然使用真实墙钟，导致时间类场景随运行日期漂移。
1. 在 TEST + 隔离根条件下，测试时钟同样驱动 Atlas 的当前时间来源：系统提示里的日期、时间相关工具、观察者和反思者的"现在"。建议做成一个统一的时钟接口，各处调用它，而不是在各处分别打补丁。
2. 生产路径一律使用真实时间。写测试证明：没有 TEST + 隔离根条件时，传入的测试时钟会被忽略。
3. 评测运行器中 `occurred_at_used_by_ws` 的硬编码 `False` 改为真实反映链路状态。
