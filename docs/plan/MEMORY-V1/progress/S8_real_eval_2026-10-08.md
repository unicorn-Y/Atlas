## 1. 原评测为什么无证明力

`scripts/memory_v1/eval_scenarios.py` 的"召回装配"是手搓假货：

- 观察者（真模型）抽取的观察**只 append 进进程内列表** `state["history_observations"]`，从不进 MemoryOS。
- 装配（约 1207–1256 行）遍历该列表、按 `scenario.id == 7/16/17/18/19/20` **硬编码冲突标记与状态标签**，
  `assembled_refs` 全是合成的 `ref_<场景>_<轮>` token。
- 从不调 `assemble_recall_context`，从不读真统一记忆库。

因此其 `11/30` 既不能证明也不能证伪真系统。

## 2. 返工内容

`scripts/memory_v1/real_memory.py`（新）：

- `RealMemoryService`：起/停一个**真 MemoryOS 服务**（隔离数据根、每场景独立库）。
- `push()`：观察经**真 `UnifiedMemoryFacade.observe_batch`** 落库。
- `recall()`：调**真 `assemble_recall_context`**。

`eval_scenarios.py`：

- 观察流进真记忆库；召回由真函数装配（离线时保留显式回退，dry-run 不受影响）。
- 每场景独立记忆库，避免场景间污染。

## 3. 顺带修掉的两个"真评测 bug"

1. **观察者日预算失真**：`_apply_model_config` 把预算设成 5,000,000，但传给 `MemoryObserver`
   的是最小配置（只有 `unified.enabled`），预算回落默认 **50,000** → 跑到第 ~11 个场景就
   `memory_observer.budget_deferred`，其后场景**没有观察** → 必然 FAIL。
2. **召回被本轮自身挤占**：原先把本轮观察在召回**之前**落库，导致召回返回"本轮提问自己"
   而非历史事实（生产里观察者是**回合末**触发，召回时本轮尚未入库）。改为回合末落库。

并接上**真反思者**（S4）以便构建画像块。

## 5. 剩余 9 个 FAIL 的根因（真实缺口，未掩盖）

**主因：画像块恒空。** 反思者把概括写成 `facet=SUMMARY` 的 `mem-profile-*` 记录，
而 `GET /v1/unified/profile`（`profile.current_profile`）**只投影 `PROFILE_FACETS`**
（PREFERENCE/STATE/HABIT/RELATION）；观察者亦只产 EPISODE/INTENT，不产 PROFILE facet。
两者未接 → `profile_tokens=0` → 元问题场景（"总结你对我的了解"、"女儿叫什么"、"用什么电脑"）
检索不到具体事实。

受影响 FAIL：#1 #2 #3 #16 #19 #21 #22（同一根因）；#8（跨会话方案检索）、
#18（迟到旧数据覆盖，temporal/supersession 断言）、#26（记忆修改即时生效）为其它路径问题。

**修法方向**：让反思者/概括产物投影进画像分节，或让观察者产出 PROFILE facet 观察，
使 `current_profile` 真正返回画像项。属 S3↔S4 集成缺口，建议单独立项。
