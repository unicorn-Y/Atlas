## 一、用户要什么（原话整理）

1. **全能 Agent，主要自己用**，每个细节都要比最强的那家好。
2. **整合各家最强**：「一家的某些功能不如别家的，要的都是各家最强的」。
3. **先做好一个能用的，以后看到哪家有新东西就抄过来，随便扩展，慢慢做强**（2026-10-01）。
4. **有现成代码就拿来改**，不从零写。
5. **先把主体做好**（2026-10-01）：每天实际在用的部分（对话里干活、读改代码、跑命令、上下文、会话、交互、子 Agent、扩展、模型）。外部功能先不做。
6. **实测放到最后**（2026-10-01）：每一波只做验收，不用真实模型逐波实测，太费配额。全部做完后统一实测，和各家横向对比。

## 二、路线：自有内核 = Hermes 骨架 + 各家最强零件

**为什么换内核**：外层框架决定实际体验，同一模型换个外层框架能差 13–18 分。Atlas 现在的内核（LangGraph 循环、自写工具、假压缩、15 行提示词）是最弱的一环，问题清单见 CORE-PARITY 第 0 节。

**骨架用 Hermes Agent**（`NousResearch/hermes-agent`，MIT 许可，Python）：
- 和 Atlas 后端同一种语言；
- 它本来就设计成一个内核同时供命令行、桌面端、聊天渠道使用，总入口 `AIAgent` 可以直接嵌入，回调齐全；
- 循环、出错恢复、文件和终端工具、上下文压缩、提示词组装、服务商，各家里它最全。

**怎么搬：fork 一份，作为 Atlas 的依赖**，不是零散拷文件：
- 在 GitHub 上 fork 成 `unicorn-Y/hermes-agent`，Atlas 的改动直接提交到这个 fork；
- Atlas 的 `core/pyproject.toml` 固定依赖到 fork 的某个提交号；
- 以后 Hermes 出新东西，在 fork 里 `git merge upstream/main` 就能合进来，只有改过的地方要处理冲突。用户说的「看到新东西就抄过来」就靠这个机制。

**零件各取最强**：CORE-PARITY 表里每一项都写了谁最强、从哪个文件拿。
- Hermes 不是最强的项，就从 OpenCode、Pi、Codex 的源码翻译过来（它们是 TypeScript 或 Rust）；
- Claude Code、ZCode 闭源，照它们的设计自己写。

**官方程序只当选项**：Claude Code、Codex 等原样运行的程序，继续作为输入框里「运行方式」的可切换选项（`runtime/backends.py`），不当主内核。原样运行的程序改不了它的循环、压缩、内置工具和上下文组装。

**Atlas 自己的部分全部保留**：界面（对标表里 170 项界面功能）、事件协议、检查点、撤回、插话、排队、配方、规格、看板、SSH、worktree、调度器、Telegram 等，C1 把它们接到新内核上。

## 六、执行流程（每一波）

C1 用的是旧流程：Luna 单独施工，Claude 每 20 分钟巡检，再开一个新的 Sol 对话验收。**从 C2 起改成 Sol 主控**（用户 2026-10-01 决定）：

```
Claude 写任务书 → 把「Sol 主控」提示词填进主机 Codex 新对话（模型选 GPT-6.1 Sol）→ 用户点发送
   ↓ Sol 主控：读任务书，拆成几块，开 GPT-6 Luna（高）子代理逐块施工（互不依赖的块可以并行）
   ↓ 每块完成后 Sol 先审：看 diff、跑相关测试、对照 CORE-PARITY；不合格就让 Luna 返工或插话纠偏；合格再开下一块
   ↓ 全部完成：Sol 跑全量测试和前端检查，写结果文件，推送，停止
Claude 读结果文件 → 把「独立验收」提示词填进另一个新对话（模型选 GPT-6.1 Sol）→ 用户点发送
   ↓ 独立验收：没参与施工的 Sol 按第五节清单验收、修问题、写验收记录（保留这一步是用户决定的）
Claude 读验收记录：
   - 通过 → 写下一波任务书
   - 没修完 → 写补做任务书
   ↓
C6 通过 → 实测阶段（Claude 参与）→ 收尾 → 最终审查 → 向用户汇报
```

- 提示词模板在 `tasks/HANDOFF.md` 第 6 节。
- Claude 不再巡检，只读结果、写任务书、填提示词。
- 发送按钮由用户点。

## 七、每一项的验收：「比最强的那家好」

1. **验收阶段**（每波）：CORE-PARITY 里标在本波的每一行，「最强做法」写到的细节都要做到，代码可证、测试覆盖。搬入的代码规模和来源对得上，不能自己写个缩水版。
2. **实测阶段**（最后）：同一批任务和各家横向比较，输了的项不算完成。
3. 每项再加至少一个别家没有的点（通常来自 Atlas 的界面、检查点、两台电脑、国内服务）。
