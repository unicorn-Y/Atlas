# 最终审查清单（Claude，在「实测」和「收尾」之后执行）

目的：在宣布「主体做完了」之前，由一个没参与施工的审查者，按用户的最终目标整体检查一遍。

## 一、对照用户目标
1. **主体全覆盖**：`docs/plan/CORE-PARITY.md` 每一行都是 ✔，并写了提交号；列出缺口。
2. **比最强的好**：实测阶段的横向对比报告里，每一项 Atlas 都不输给对标的那家；输了的项都有补做记录，并且已经关闭。
3. **拿来主义**：`docs/plan/VENDORED.md` 每一行核对来源、提交号、许可证；抽查 5 个搬入文件和来源对比，确认不是自写的缩水版。
4. **能持续抄新东西**：按 `EXECUTION-GUIDE.md` 第三点六节，实际把 Hermes 上游合并一次，确认流程走得通。

## 二、亲自实测（真实模型、隔离环境）
- 复跑实测阶段的任务集，确认补做之后的结果。
- 另外随机挑 10 个日常任务（改代码、读大仓库、长对话、子 Agent、撤回、插话……）在开发版界面里手动走一遍，记录体验问题。

## 三、代码
- 全量测试、前端四项检查自己跑一遍。
- 读每波的验收记录，确认记录里的问题都已修复并且有测试。
- 重点看本机接口的基础防护：OriginGuard、密钥存储、路径处理、子进程。安全审查功能由用户亲自做，这里只看本机会不会被外部网页或局域网随意访问。

## 四、产出
- 审查报告 `tasks/reviews/ATLAS-FINAL.review.md`：结论（能否交付）、按目标逐项打分、问题清单（严重 / 一般 / 建议）、下一步建议（解冻哪些外部功能）。
- 向用户汇报：做到了什么、和各家比怎么样、还差什么。
