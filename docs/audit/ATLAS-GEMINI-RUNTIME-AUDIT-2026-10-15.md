## 新增确认的问题

### A17 · P1 · local_exec 的 stdin 默认不关闭，正确的 stdin 脚本会等待 EOF 卡住

真实 S2 对 `python -` 提供 stdin，仍等待约 120 秒才超时。`core/atlas/kernel/exec.py:119` 对执行请求默认 `keep_stdin=True`；`core/atlas/tools/local_execution.py:182` 的 local_exec 模型工具参数提供 stdin，却没有公开 keep_stdin。模型按公开参数正确调用，也无法自然表达结束输入。

独立探针使用真实 ExecManager 与 LocalExecutionRuntime：默认输入策略的 `print('STDIN_EOF_OK')` 在 1 秒期限后 timed_out，耗时 1.308 s，输出为空；显式 keep_stdin=False 时 0.216 s 完成并打印该标记。没有改模型、增加重试或换语言来掩盖根因。

建议：一次性 local_exec 写完 stdin 后关闭输入；只有明确的交互进程才保持打开，并让工具参数、桥接层默认值及进程管理器保持一致。

### A18 · P2 · 验证识别遗漏 executable/args，已经通过 unittest 仍被催促验证

S1、S8 均真实执行 `python -m unittest` 并通过，随后仍出现 run.verify_nudge。`core/atlas/agent/verification_stop.py:19` 只检查 command/script/code 字符串，没有读取本次实际使用的 executable/args。`core/atlas/agent/tool_node.py:1358` 依赖该识别更新验证状态，停止门因而误以为未验证。

建议：基于标准化执行请求、退出码及结果识别验证，而不是只匹配某一种参数表示；保留失败验证不能放行的约束。

### A19 · P1 · local_git 的路径限制与工作区限制没有落实到 Git 实际根目录

S1 的工作区在本次 repair 合成子目录，allowed_paths 只包含该目录。local_file 访问父目录被拒绝；local_git 在同一子目录执行 diff，却让 Git 向上发现 `D:\Atlas` 仓库并返回已有用户 `engine/config.yaml` 的差异。随后显式传 paths=[orders.py]，仍返回同一份无关差异。

`core/atlas/tools/local_execution.py:944` 的 Git 分支仅在 add 处理 paths，diff 没有把 paths 传给 Git。这里同时有两个问题：接受参数但静默忽略，以及只校验 cwd 而未校验实际 Git 根目录。证据文件将无关用户配置差异全文替换为脱敏占位，未将其重新发布。

这次是工作区读取边界越过，没有证据证明发生凭据泄漏或越界写入。建议在执行前解析并校验实际仓库根目录；diff 使用 `--` 后的合法 pathspec；不支持的参数应拒绝，不能静默忽略。

### A20 · P2 · 同一个工具调用出现成功与错误两种状态

S1 的两个 Git diff 均 exit_code=0，底层 tool.completed 为 is_error=false、state=exited；上层重复完成事件却因 state 不是 completed/cancelled，标为 is_error=true。对应 `core/atlas/kernel/loop.py:1425`。S2 的 timed_out 结果在另一处又被标为 is_error=false，`core/atlas/kernel/exec.py:189` 没有把 timed_out 视为错误。

这会与第一轮 A03 叠加：同一次调用显示两张卡，甚至一张成功、一张失败。建议统一 exited/completed/timed_out/cancelled 的状态转换和错误语义，只发布一份权威完成结果。

### A21 · P2 · 桌面底部用量实际取最后一次标题请求，覆盖整轮工作用量

S7 的真实桌面底部显示“用量 396 tokens”。对应最后一次标题请求 input=383、output=13；整轮完成事件为 input=70,083、output=387。对话请求和标题请求用途不同，界面却取 activeEvents 中最后一个 run.usage 直接求和，见 `frontend/src/renderer/App.tsx:1114`、`frontend/src/renderer/App.tsx:1373`；`frontend/src/renderer/shell/Inspector.tsx:204` 也有类似取最后值的逻辑。

这里比较的是实际事件和界面显示，未把缓存、推理 token 或计费总额混为一谈。建议展示整轮权威累计值，明确是否包含辅助标题调用；同时修复 A04 缓存字段丢失。

### A22 · P2 · 执行中的普通子进程没有实时输出事件

S10 使用无缓冲 Python，连续 60 秒每秒输出一行。磁盘工具输出日志有 60 行、553 字节，整个 run 的 tool.output 数为 0，只有完成结果包含输出。依赖首条输出才能触发的取消因此未发生，之后改用进程状态 API 独立验证取消成功。

`core/atlas/kernel/loop.py:464` 创建内部事件队列，但只在启动后排空一次；`core/atlas/kernel/exec.py:146` 的输出捕获写日志与缓存，没有完成到运行事件的持续转发；`core/atlas/agent/tool_node.py:1207` 的 ExecManager 路径也绕过普通工具的 output callback。

建议为受管进程保留至退出/取消的输出转发器，使用序号去重、有限缓冲及断线补发；避免 UI 显示“执行中”却无法知道进展。
