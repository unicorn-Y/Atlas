## 补充来源的纳入边界

- Hermes/OpenClaw 仅补“消息平台 Gateway 的策略/toolset/定时投递”和“执行节点配对后单独审批节点能力”。Atlas 已有 channels/devices 基础 API，本次补 UI/状态，不绕过原有权限审批。
- Goose 仅补参数化 Recipe 启动器；Pi 仅补一个 package manifest 对 extensions/skills/prompts/themes 分类筛选；Cline 仅补跨类型 marketplace 条目目录。Cline 的一般 MCP、插件和技能安装已被主对标组覆盖，不重复计项。
- Codex/Claude 的付费账号登录、企业额度、组织托管策略和 telemetry 后端依赖各自云服务。Atlas 是本地/自托管产品；不伪造第三方账户或云账单。本次仅实现 Atlas 本地能支持的 Profile、用量和诊断视图，并在对应无服务行保留原因。
- 对矩阵 A、B、D 章节及附录 VI–IX 的修正也逐条检查了本区交叉项；新增的会话内搜索/会话成本轮次展示归 A，停止/编辑重发/提示词增强/`/goal` 等对话能力归 B，无头/SDK 与 PR 工具归 D，本分支不改这些区域。VIII-C2/H/C3 参数名修正也属于 D，本分支只记录来源边界，不改 D 的工具 schema。
- 矩阵主表空白按“未核实”处理；以附录及固定提交源码/官方文档为证据。主表与附录矛盾时采用附录修正，并在对应行明确 Atlas runtime 当前支持范围。

## 实现与文件边界

- 本区新增 renderer 文件放在 `frontend/src/renderer/components/settings/` 或 `pages/`，源自开源项目的移植文件顶部注明上游仓库、固定 SHA、相对路径和许可证。
- 后端只使用 C 区列出的路由文件或新增独立 router；`application.py`/`App.tsx` 等共享入口由总控追加注册，不重排其他区域代码。复用 MCP API 时不修改 D 区 `tools_router.py`。
- 不改 `D:\Atlas` 或其他 F1 工作树；不添加/运行测试套件。验收仅按任务书执行后端启动、前端 build、本区界面打开检查。
