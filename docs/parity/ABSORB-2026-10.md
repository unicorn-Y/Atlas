## 三、本轮施工（分支 `absorb-all`）

### 1. 独立会话派活（第一项，对标 Claude Desktop `start_session`，代码从 OpenClaw 翻译）

| 能力 | 实现 | 比原版好在哪 |
|---|---|---|
| 提议卡片 | `session_start` 的 `offer` / `own_initiative` 只建提议，主会话时间线出卡片（开新会话 / 就在这里做 / 忽略），对话框上方的会话条也能开始；7 天不点自动失效 | 卡片和会话条两处都能操作；刷新后会话条仍在（不依赖当轮事件） |
| 独立会话 | 子会话是普通 Atlas 对话，走和桌面一样的 `run.start`，侧栏缩进挂在主会话下；打开时界面按 run_id 接上直播，审批、暂停、停止都能用 | 顺带修了「后台开跑的运行（自动化、渠道、回报唤醒）界面接不上」的老问题：打开任何对话都会自动接上它正在跑的运行 |
| 自动回报 | 子会话停下时把最后一条回复 + 用时/tokens 送回主会话：主会话在跑就插进去，空闲就唤醒它跑一轮；兄弟会话都停下再统一唤醒；30 分钟内最多唤醒 8 次 | 回报插进去但主会话没读就结束了，会自动改成下一轮的开头，不丢；用户手动停掉的子会话不回报 |
| 互发消息 | `session_send`（按 id / 句柄 / `parent`），对方在跑就插入，空闲就开新一轮 | 子会话卡住时可以问 parent 一个问题 |
| 独立 worktree | `use_worktree=true` 时子会话在自己的 git worktree 和分支上改（基于主会话的工作树分支） | 子会话继承主会话的工作区和权限，永远不会比主会话权限大 |
| 规则 | 由别的会话或回报触发的那一轮只能提议、不能直接开；只读/计划模式下也只能提议 | — |
