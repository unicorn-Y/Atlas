### 2.3 大消息分片协议

`preload.js` 里定义了校验函数，协议标记为 `codex-host-chunked-message-v1`：

```
{ marker:'codex-host-chunked-message-v1', transferId, sequence, kind:'start'|'chunk'|'end',
  tokens: [ {type:'array-start'|'object-start'|'container-end'|'string-end'|'string-start'|'key'|'string-chunk'|'value', ...} ] }
```

→ 这说明主进程与渲染进程之间会传输**超大结构化对象**（如整个会话历史），用"token 流"分片以避免结构化克隆的内存峰值与 IPC 体积上限。

### 2.4 MCP App 沙箱隔离（`sandbox-preload.js`）

- 允许的源：`https://*.web-sandbox.oaiusercontent.com`、`codex-sandbox://*.web-sandbox.oaiusercontent.com`
- 必须带 `?app=skybridge` 且 hash 中有 128 字符内的 `initId`
- 通过 `MessageChannel` 端口白名单移交能力：
  - 通用：`navigate`、`notifyMcpAppsHostContext`、`notifyMcpAppsToolCancelled`、`notifyMcpAppsToolInput`、`notifyMcpAppsToolResult`、`requestMcpAppsResourceTeardown`、`runWidgetCode`、`setAdditionalGlobals`、`setSafeArea`、`setTheme`、`setWidgetData`、`setWidgetView`
  - 仅在部分场景：`applyAutofillCandidate`、`getCurrentPath`、`notifyMcpAppsMcpNotification`、`prepareEnvironment`、`runUserCode`、`screenshot`、`stop`

→ MCP App（即"应用内小部件"）运行在**独立源 + 独立 preload** 的沙箱里，只能通过显式端口通信，无法直接访问主 preload 的 `electronBridge`。

### 2.5 浏览器页 preload（`browser-page-preload.js`）

注入到应用内浏览器标签页，暴露 `codex_desktop:browser-page-event`、`browser-sidebar-runtime-message`、`get-browser-annotation-api-policy`、`get-browser-webmcp-policy`。
→ 说明 Codex 内置浏览器支持 **MCP/WebMCP 工具发现** 与 **页面标注（annotation）API**，且策略由主进程下发。

## 5. 进程编排

主进程内有 `resolveCodexPath` / `resolveNodePath` / `resolveNodeReplPath` / `resolvePrimaryRuntimeNodePath` 四个二进制解析器（`bootstrap-cdWF4rWM.js`），并区分：
- `isPackaged`（打包态 vs 开发态）
- `platform`（win32 走不同分支，含 WSL 路径处理 `shouldUseWslPaths`）
- `resourcesPath`

主进程通过 `app-server` 连接管理 Runtime：
- 连接键：`codex-app-server`
- 凭据前缀：`openai-bearer.`
- 有 **SQLite 恢复确认**机制：`onRecovery({databasePath, backupFolder})`，恢复前排队通知
- app-server 有 `daemon`（本地守护进程）、`proxy`（stdio 转发到控制套接字）、支持 `ws://` / `wss://` / `unix://`
