|---|---|

**结论**：这是典型的 **strip 过的 Rust 二进制**——Rust 符号表被剥离，只剩 CRT（`__acrt_*`、`_malloc_base` 等）和少量 C++ 模板实例化名字。所以"函数边界"有了，但"函数语义"必须靠字符串交叉引用恢复。

## 4. 从 API 导入反推的实现结构

| Windows API | 用途推断 | 对应安全层 |
|---|---|---|
| `CreateJobObjectW` / `SetInformationJobObject` / `TerminateJobObject` | 进程树约束与统一杀灭 | 生命周期 |
| `SetTokenInformation(TokenDefaultDacl)` + `SetEntriesInAclW` + `S-1-3-4` | 构造受限令牌 + capability SID | 权限 |
| `NtCreateNamedPipeFile` / `CreateFileW` / `GetNamedPipeInfo` | 命名管道通信 | IPC |
| ConPTY 相关（`spawned ConPTY is missing its process job`） | TTY 模式 | 终端 |
| `CreatePipe` ×3（stdin/stdout/stderr） | 非 TTY 模式的管道 | IO |
| 私有桌面（`private_desktop_name`） | 隔离窗口站/桌面 | UI 隔离 |

## 5. 局限（重要）

- 具备函数边界，**不等于具备函数语义**。要给出"某函数做什么"，需要：
  1. 对 52 个大函数逐一做 Ghidra 反编译 → 伪代码；
  2. 把字符串偏移（第 3 节）反查交叉引用，找到引用它们的函数；
  3. 结合 Rust 源码 `windows-sandbox-rs` 对齐。
- 本轮**未做**第 1、2 步的完整展开（时间成本高），因此报告里对 runner 的描述以**协议 + API 导入 + 字符串**为准，不编造函数名。
