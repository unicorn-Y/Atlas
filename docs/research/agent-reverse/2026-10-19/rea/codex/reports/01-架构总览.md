## 一、四层进程架构（实测）

启动桌面端后实际观察到三类进程（`Get-Process` 实测）：

```
ChatGPT.exe  (Electron 主进程 + 渲染进程 + GPU/Utility 共 10+ 子进程)
   └─ codex.exe            ← 341 MB Rust Agent Runtime，由 Desktop spawn
        └─ codex-code-mode-host.exe   ← 74 MB，Code Mode 执行宿主
   └─ codex-command-runner.exe        ← 8.2 MB，沙箱命令执行代理
   └─ codex-windows-sandbox-service.exe (55.8 MB，Windows 沙箱服务)
```

关键点：**Desktop 本体不含 Agent 逻辑**，真正的 agent loop 在 `app/resources/codex.exe` 里（一个 341 MB 的 Rust 单体二进制），且该二进制与 CLI 发行包中的 `codex-x86_64-pc-windows-msvc.exe` 是同一程序的不同构建（两者版本均为 0.163.0，PE 时间戳分别 `0x6AD11095` / CLI 包内为 2026-10-15 构建）。

桌面端 `app.asar` 内甚至还**内嵌了一份完整 CLI 源码树**（1278 个 .js、499 个 .ts、331 个 .cc、326 个 .h、320 个 .md），说明 Electron 应用与 Rust CLI 共享同一仓库构建。

## 二、Desktop 与 Runtime 的通信方式

| 层 | 机制 | 证据 |
|---|---|---|
| 渲染进程 ↔ 主进程 | Electron IPC，`contextBridge.exposeInMainWorld('electronBridge', …)` | `.vite/build/preload.js`（全文可读） |
| 渲染进程 ↔ 主进程（大消息） | 分片传输协议 `codex-host-chunked-message-v1` + `codex_desktop:chunked-message-ack` | `preload.js` 的 `i(t)` 校验函数 |
| 渲染进程 ↔ MCP App 沙箱 | `MessageChannel` 端口 + `codex_desktop:mcp-app-sandbox-host-message`，沙箱域白名单 `web-sandbox.oaiusercontent.com` | `sandbox-preload.js` |
| 主进程 ↔ Runtime | CLI 的 `app-server` 子命令（JSON-RPC over stdio / UDS / WebSocket） | `codex app-server --help`：`daemon` / `proxy`，`--remote ws://host:port` |
| Runtime 对外协议 | **172 个 RPC 方法 + 85 类服务端通知**（见 `PROTOCOL-METHODS.md`） | `codex app-server generate-json-schema --experimental` 生成 |
| 命令执行 | 私有命名管道 `\\.\pipe\...`，首帧必须是 `spawn_request` | `codex-command-runner.exe` 字符串：`runner: expected spawn_request, go`、`runner: no pipe-in provided` |

## 三、Codex 的四套"外壳"

逆向发现同一套 Rust 内核被四种前端复用：

1. **TUI**（`tui` crate，456,055 行）— 终端交互界面
2. **Desktop**（Electron + React，webview 574 MB）— 图形界面
3. **app-server**（`app-server` crate 195,443 行）— 给任意客户端做后端
4. **exec-server / code-mode-host** — 无头执行服务

这也是为什么 `codex app-server` 帮助里写着 `[experimental]` 但实际已是 Desktop 的正式后端。

## 五、最值得注意的"非公开能力"

这些能力在官方文档里没有，但二进制/协议里是硬证据（**S 级**）：

| 能力 | 证据 |

## 六、证据等级说明

- **S**：二进制/源码/官方生成物直接可读（本报告绝大多数）
- **R**：本机实际运行观察（CLI 命令输出、进程列表、CDP 截图）
- **D**：官方文档声明
- **I**：推断
- **U**：无法验证

本报告中标注"实测"的内容均属 **R**。
