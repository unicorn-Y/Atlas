## 2. Hook 机制（插件级）

`browser` / `chrome` / `computer-use` / `unified-computer-use` 四个插件都声明了**完全相同的三个 hook**：

```json
"hooks": {
  "hooks": {
    "Interrupt":     [ { "hooks": [ { "type":"mcp_tool", "server":"node_repl", "tool":"turn_ended",
                                      "input": { "hook_event_name":"${hook_event_name}",
                                                 "session_id":"${session_id}",
                                                 "turn_id":"${turn_id}" } } ] } ],
    "SubagentStop":  [ { "hooks": [ { "type":"mcp_tool", "server":"node_repl", "tool":"turn_ended",
                                      "input": { "hook_event_name":"${hook_event_name}",
                                                 "session_id":"${agent_id}",
                                                 "turn_id":"${turn_id}" } } ] } ],
    "Stop":          [ ... ]
  }
}
```

关键点：
- Hook 执行类型是 **`mcp_tool`**，即 hook 本身可以调用 MCP 工具
- 目标固定为 `node_repl` 服务器的 `turn_ended` 工具
- `SubagentStop` 传的是 `session_id = ${agent_id}`，说明**子代理结束时也会触发**，且能拿到 agent_id
- 变量插值 `${hook_event_name}` / `${session_id}` / `${turn_id}` / `${agent_id}`


`api.json` 定义了 TypeScript 风格的 API 表面：
```
Agent.browsers: Browsers
Agent.documentation: Documentation
Browsers.get(id): Promise<Browser>
...
```

`documents.json` 定义了文档的注入模式：
- `"mode": "model"` — 由模型主动读取
- `"mode": "included"` — 直接注入
- `when` 条件：`requiredBrowserCapabilities` / `browserTypes` / `requiredApiMembers`

→ 这是**按能力条件注入文档**的机制，不是把所有文档塞进上下文。

## 7. 判断

Codex 的插件系统不是"配置文件 + 脚本"的松散结构，而是：
1. **有市场（marketplace）、有签名、有安装策略**
2. **插件可同时携带 skill + MCP server + hook + 前端 interface**
3. **hook 可以调用 MCP 工具**（`type: mcp_tool`），意味着 hook 不是只能跑 shell
4. **文档按能力条件注入**，控制上下文开销

这套设计比多数竞品的"扩展点"要完整一个量级。
