# Unresolved research boundaries

All eight lanes are report-complete for this continuation, but none establishes exhaustive product behavior. These residuals are intentionally left for GPT-6 review and, where useful, a later authorized runtime study.

## By lane

- **Claude Desktop:** the package is the enterprise MSIX; consumer package equivalence is unknown. Local Hyper-V VM named-pipe methods and framing are statically visible, but service installation/launch parent and full Go execution call graph are not established. The new cloud Cowork backend and cloud protocol are outside the visible client. No R-level app operation.
- **Claude Code:** only bounded native CLI help/version operations ran. No login, Agent turn, model/tool cycle, or live daemon was executed. Mailbox writer transaction details and reader/ack/replay semantics, event ordering, cross-device/cloud behavior, and full PE function graph remain open.
- **Codex Desktop:** only selected Electron bundles and 41 targeted webview chunks were mapped; the full ASAR and remaining 20,362 webview assets were not analyzed. No desktop action was followed live to JSON-RPC; app-server/runner/host process tree and dynamic session/recovery behavior remain unknown.
- **Codex CLI:** help/version probes establish package launch only. Authenticated app-server RPC, a real Agent turn, Code Mode request/cell lifecycle, daemon restart recovery, and live voice/WebRTC were not observed. Binary overview timed out; only bounded PE header/import/string evidence is reported. Remote service internals remain unknown.
- **OpenCode:** CLI help/version ran, but desktop UI and an authenticated server operation did not. Full ASAR analysis timed out after integrity mismatch; OpenConsole mismatch cause is unknown. Browser/CDP request and failure semantics are static source evidence, not live execution evidence.
- **ZCode:** v3.15.3 runtime/Desktop artifacts and v3.15.1 source are separate versions. Full ASAR analysis timed out; individual entry integrity and renderer attach/consent/model-context result flow remain open. No package/runtime operation; the unpacked node-pty integrity mismatch is unexplained.
- **DeepSeek Harness Core:** CLI `--version`/`--help` were observed after installing the exact published tarball with scripts disabled. No profile, Agent, model, web server, or authenticated request ran. Default profile loading, live event/session recovery, Web TGZ-to-runtime UI build identity, and external server behavior remain unknown. CLI, source and Web package versions differ.
- **DeepSeek Harness Desktop:** two community packages were analyzed; original zips and full source trees were not committed. No desktop was run. For anywhere-labs, exact UI control-to-`session/updateQueue` mapping remains unknown; official DSH runtime mechanisms are kept separate from both community shells.

## Cross-lane limits

1. Static bundle/source evidence does not establish menu visibility under account rollout, successful service connection, model response, tool side effects, cancellation behavior, or cold recovery at runtime.
2. Several products call remote or cloud services. Client artifacts reveal protocol surfaces, not the server-side implementation; those areas remain U.
3. A package hash validates the archived bytes against the pinned manifest. It does not prove source-to-binary reproducibility or that different release channels/build flavors are equivalent.
4. The common Atlas comparison is `main@aa6196f550098cc46081dc6db2c376cb87ddffa5`. Each lane gives scoped path-level comparisons; do not broaden an observed gap into a claim that Atlas has no related capability elsewhere.
5. The analysis found declared-vs-observed integrity mismatches for unpacked native companions in Claude Desktop, OpenCode and ZCode; Codex Desktop's outer extraction passed while its ASAR native-addon integrity check differed. These are recorded as bounded discrepancies; causes are unknown.
