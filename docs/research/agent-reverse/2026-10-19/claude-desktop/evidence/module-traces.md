## Cowork artifact handler chain (same main bundle)

The preload's generated API method `runScheduledTask(taskId, preloadContext)` registers under the `CoworkArtifactBridge` method schema in `index.chunk-lzaSYO3Q.js` around character 5,836,915. The handler at ~5,863,754 checks rollout enablement (`qnr()`), run permissions, and that the artifact is still shown; it resolves the scheduled task, checks imported tasks are enabled, then calls `runNow(..., {personStarted:true})`. Its main bundle records outcomes including disabled/rejected gesture/error/success. Around ~5,864,600 the handler checks a gesture and rejects unless user gesture is recent; actual check uses Electron event tracking. This closes a genuine UI→preload→IPC→handler→scheduler call path for the artifact surface.

`callMcpTool` at ~5,860,203 checks artifact visibility and validates args; task artifacts take a separate `Rla` branch. For normal artifact calls it resolves the MCP tool/server, applies managed tool policy and disabled-state checks, prompts for destructive calls unless remembered approval exists, then dispatches through a server/tool path. Only read-only remote calls may qualify for a cache path under policy; destructive tools are not blindly cached. This is a narrow, concrete tool bridge; exact service backend and server RPC remain outside this trace.

The app side of the Cowork artifact protocol sets a top-level frame origin guard (`cowork-artifact:` and no parent frame) before registering six methods: five bridge operations plus `setEditableFocused`.
