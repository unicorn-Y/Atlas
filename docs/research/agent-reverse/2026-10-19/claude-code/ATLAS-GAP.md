## Direct engineering findings (Atlas S)
1. **ACP resumed-session ID mismatch**, line-specific (GAP-01), is the highest-value concrete investigation. It is a code-path inconsistency, not a measured exception.
2. **Workers are transient**, both conversation stores explicitly deleted in agent/__init__.py:640-650. An Atlas owner needing long-lived/background child retrieval cannot rely on that code path.
3. **External event projection is lossy by design**, because normalize_external_event only handles a small recognized family and ignores unknown updates. This is source-observable; whether a particular real ACP peer emits more cannot be decided without a trace.
4. **External session mapping is process-local**, run_drive.py:1965-1976. Runtime durability must be evaluated separately from the persisted main conversation.
5. **Do not classify all background work as absent**: Hub, scheduling, subprocess process registry and worker callbacks exist; compare exact semantics.

## Recommended narrow verification sequence
1. Synthetic ACP peer tests: start → prompt → close host → resume(old ID) → second prompt → inspect exact peer sessionId; assert event identity matches requested ID.
2. ACP integration fixture emitting additional event types, two nested agent streams and tool status changes. Record pass-through coverage, parent/child IDs, final error propagation.
3. Run three Atlas worker tasks; finish one, cancel one and restart host during one. Inspect durable transcript state, ability to retrieve progress and parent notification.
4. Compare official Claude Code 2.1.302 native daemon/session trace after extraction before designing a replacement background supervisor.
5. Create a one-page state transition and UI-projection reconciliation from real event corpus; avoid duplicated test scaffolds until events are grounded.
