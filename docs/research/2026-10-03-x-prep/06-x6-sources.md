## Architecture finding

Required design is continuous chunk transport plus a duplex pipeline and a turn controller. Streaming recognition yields **partial** hypotheses for live UI, while a turn boundary yields one final transcript for the Atlas session. Barge-in cancels the currently speaking TTS/output queue immediately; event replay must not re-enqueue audio already cancelled. Agent text and tool calls still pass through Atlas's current run, policies and tool registry. A provider can own acoustic turn detection or Atlas can run VAD/turn detection, but each voice session selects exactly one authority and reports that choice.

Pipecat's current release notes describe per-frame interruptibility and coordinated task/processor interruption behavior; the library repository is the source for extensible pipeline building blocks. Gemini Live confirms native duplex over WebSocket and requires client playback queue clearing on interruption. LiveKit documents adaptive interruption as hosted Cloud capability. These are distinct deployment features; do not promise interchangeable functionality until the selected providers pass the same acceptance suite.

## Contracts and acceptance

Voice binding record: `voice_session_id`, existing `atlas_session_id`, `run_id|null`, `device_id`, `transport`, `provider_route`, `input_format`, `output_format`, `turn_authority`, `state`, `last_sequence`, `created_at`, `closed_at`. No transcript is duplicated into a new session database; partial transcript is ephemeral, final transcript enters the current Atlas run once with source metadata. Event sequence and audio playback cursor are separate from agent run sequence.

Fake acceptance: deterministic PCM stream fixture; partials merge to exact final transcript once; provider dropout/resume does not duplicate final input; barge-in cancels every queued future TTS frame within measured transport budget and leaves current session/history consistent; overlapping device sessions are rejected or explicitly joined; provider swap retains session identity; event reconnect resumes sequence; fake image/audio generation emits correct task artifact and audit event, while a video request is rejected/unsupported.

Real acceptance: browser first, with consented local mic and speaker on isolated test origin. Verify 20-40 ms input chunks end-to-end, partial transcript timing, user speech while agent is speaking, immediate audio stop, response to interruption, noise/backchannel behavior, output queue drain, network drop/reconnect, and one chat-visible session transcript. Record measured p50/p95 input-to-partial, final-turn and interruption-stop latency and selected provider/region. Then verify one local audio generation/output and one image-generation artifact; no video path. Only after browser acceptance should Atlas desktop and X3 remote device transports be enabled.

Known limit: exact Pipecat provider set and tested Windows browser transport remain to be selected at implementation time. Live microphone acceptance, provider latency, VAD language quality, and cost are **not verified by this research**. Current Atlas image provider/readiness and whether generated image already persists through `task_artifacts` need code-level acceptance check before replacing any route. No current source justifies silently exposing microphone audio outside an active user-started voice session.
