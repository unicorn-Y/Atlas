## Product and protocol comparison

- [A2A current specification](https://a2aproject.github.io/A2A/latest/) models a task as a long-running unit, with `submitted`, `working`, `input-required`, `auth-required` and terminal states. Artifact content can be URL, bytes or structured data. It provides interoperability semantics, not a trusted device registry or Atlas's durable storage.
- [Hermes DM pairing source](https://github.com/NousResearch/hermes-agent/blob/main/gateway/pairing.py) is concrete code for short code approval/revocation and permission-safe local persistence, but the subject is a messaging user. Its [relay transport](https://github.com/NousResearch/hermes-agent/tree/main/gateway/relay) is an outbound WebSocket connector link, not QR pairing or remote dashboard authorization.
- [Tailscale device onboarding](https://tailscale.com/docs/features/access-control/device-management/how-to/set-up) shows device approval as a separate pending approval decision. [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) applies tailnet ACLs to private service exposure; [Funnel](https://tailscale.com/docs/features/tailscale-funnel) makes a service internet reachable and must remain a separate, opt-in feature. Tailscale is a deployment transport option, not a vendored library requirement.
- A2A's latest public protocol source and the Hermes checked-out branch are cited at exact SHAs in the evidence JSON. No open-source, platform-neutral “phone QR pair + Atlas artifact sync + Windows device handoff” implementation was verified; the glue and durable task lease remain Atlas work.
- Product claims are platform-scoped: Perplexity's [Windows product page](https://www.perplexity.ai/en-GB/hub/products/computer-for-windows) supports local Windows file/app work and phone-started remote completion; the [Mac setup page](https://www.perplexity.ai/personal-computer-setup) separately describes pairing the phone for 2FA, approvals and remote start. These examples establish demand and UX patterns, not reusable source code or Atlas parity.

## Contract and acceptance target

Device record: `device_id`, `owner_id`, `label`, `platform`, `public_key_id`, `state=pending|trusted|revoked|offline`, `capabilities[]`, `last_seen_at`, `created_at`, `revoked_at`. Never store the pairing secret after challenge exchange. Pairing challenge has random high entropy, one use, short expiry (5 minutes), server-side hash, and explicit owner approval unless an already trusted owner-authenticated flow is present. Events: `device.pairing_requested`, `device.trusted`, `device.revoked`, `device.presence_changed`, `task.handoff_requested`, `task.lease_transferred`, `task.event_cursor`, `artifact.created`, `artifact.shared`, `artifact.expired`.

Fake acceptance: two simulated devices enroll through expiry/replay/rate-limit/revoke cases; reject invalid owner, replayed QR, revoked device, missing capability, stale lease epoch and cross-owner artifact ID; reconnect and replay events without duplicate mutation; verify share-token scope, expiry, checksum and no filesystem path disclosure. Exercise `submitted -> working -> input-required/auth-required -> working -> completed/failed/canceled` and preserve one Atlas task/session identity.

Real acceptance: separate Atlas test account and clean phone browser, two Windows/LAN clients, TLS/overlay test environment. Pair through QR and approve/revoke; start a task on phone and resume it on the Atlas laptop with history cursor; transfer lease without duplicate execution; create/edit a spreadsheet or document artifact, sync content/hash, expire a private share link, verify anonymous access is denied, and demonstrate explicitly read-only public artifact sharing. Disconnect network/laptop, return online, and prove state recovery. Keep the service localhost-only until the opt-in trusted-LAN acceptance passes. Record exact devices/network mode and evidence paths.

Unverified: no suitable open-source QR/device registry was found; no Atlas mobile app, general task lease, LAN exposure contract, or blob sync service was found in the X-prep baseline. Hermes DM pairing is not a substitute. Windows hibernate/wake and Internet reachability need a real host/network trial. Do not claim “always on” based only on a successful online test.
