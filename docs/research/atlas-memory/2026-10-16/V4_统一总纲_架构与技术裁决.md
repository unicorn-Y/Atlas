> V4 将原 V3 的 **55 份源码/产品/学术/架构研究文件** 与 `CONTINUATION_2026-10-16.md` 统一收纳。本总纲是跨版本的**当前结论**；原始文件继续保留完整内容和版本，用于追查证据而非让不同版本互相覆盖。原 V3 压缩包不修改；V4 是独立新包。这里所有“已验证”如未额外说明，指**已通过 GitHub 直接读取静态源代码/官方文档**，不是已在 Windows Atlas 跑通。

## 0. 一页结论

**目标**：Atlas 自己持有可持续积累、可追溯、可纠错、能主动用于工作并从经历中学 Skill 的长期记忆系统。Codex、Claude、其他外部 Agent 作为可替换执行工具；模型/软件升级不应夺走 Atlas 的连续经历。

**建议演进次序**：先解决 W2 已暴露的证据精确定位、队列可靠性、Dream 增量性以及 worker 断开记忆的问题；接上 ContextBroker 的“任务前准备 + 执行中按需追问 + 执行后回收”；再做有证据的 Episode/Claim 与主动召回；最后把真实行动结果送入已有 SkillOpt。不是再装多个记忆服务器，也不是把全部记忆一次塞给外部模型。

**当前底座暂定**：保持 Atlas/Hermes 原始会话与工具日志的证据来源；派生 Fact/Claim/Episode/FTS/关系可先用 SQLite；Markdown/Git 保留人为可编辑展示价值；媒体用文件/blob 引用；数据迁移方案需同任务回放比较后才能最终冻结。Postgres/pgvector、重型图服务是实测后可选项，而非已被否决或已选定。

**不做**：现在不实施视觉、语音、Android 感知；不做新 RBAC/人工审批/token grant/外部 Agent 记忆孤岛；不为了漂亮数字扩大无关测试。

## 1. 用户已确认的最高优先级架构决策

1. **Atlas 是唯一长期记忆主体**。跨设备、跨模型、跨执行器仍属于同一 Atlas 的经历、事实、关联、技能和承诺。其他 Agent 不作为平级的常驻长期认知真源。
2. **外部 Agent 默认充分执行权限**，可读写文件、修改 Atlas 及记忆系统代码、调试、执行命令；ContextBroker 选择提供相关记忆，意图是节省上下文和减少噪声，不是权限控制。
3. **双向任务上下文**：Atlas 委派前装配用户当前要求、项目身份、最新状态、历史失败与有用经验；外部 Agent 运行中可以反复 request_more，Atlas 选择摘要或原文及其证据；实际 diff、提交、运行日志与失败/成功结果回流 Atlas。
4. **长期统一感知协议**：未来聊天、任务、电脑、浏览器、手机、视觉、语音、生活/工作活动共享事件身份、时间和证据指针。视觉/语音/手机目前只研究与定义 schema，不启动相关采集/部署。
5. **采用成熟开源内核机制，不复制多套产品宿主**。可以改现有 W0/W1/W2 和 Markdown/SQLite 设计，但绝不先假定复杂系统自然更强；复用前锁上游 SHA 和许可证。
6. **执行权限与记忆真实性分离**：外部执行器有权改代码/数据，仍需分清“它说完成”与“有工具输出/目标验收证明”；用户已明确说过的事情不能被模型二手推断悄悄覆盖。

以上覆盖任何旧 A/B/C 报告里关于多 Agent 平权共同人格、外部 Agent 不得修改 Atlas、强制记忆授权租约、人工逐项确认等过时建议。权威旧源：`source/03_主权与委派/00_正式决议与旧资料纠偏.md`。

## 4. 统一原生架构：一个真源、不同数据寿命、按需索取证据

```text
 User / Atlas automation / future PC, browser, Android, voice, vision events
                             |
                  Atlas Planner & Runtime    ← 当前任务、计划、恢复点
                     |             |
          原始事件/证据层      TaskState/RunState
          event_id + ref             |
                     |               |
                Episode/Claim/Entity/Link/Temporal
                 （可更正、可追溯、可重建）
                     |              |
      Memory RecallRouter         Skill / Policy / Commitment
       lexical→dense→temporal      经验、适用条件、实际验证
          →有需要才扩展邻域                 |
                     └──────┬─────────┘
                            |
               ContextBroker (薄原生模块)
                            |
       prepare_context → worker.run ← request_more
             Codex / Claude / other external tools
                （完整开发/执行权限）
                            |
             Tool logs, diff, tests, evidence
                            |
                      Atlas 归档/巩固
```

**五个互相关联但不可混成一张文本表的对象**：

1. `SourceEvent`：原始证据/来源，稳定 `event_id`、`source_id`、`task_id`、`run_id`、`session_id`、`tool_call_id`、`actor`、`project_id`、`occurred_at/received_at`、`payload_ref`、`hash`。别因重新摘要再创造“第二份独立事实证据”。
2. `TaskState/RunState`：执行的当前进度与恢复点；不等于长期事实，由任务系统稳定管理，不能指望向量检索找回正在执行的状态。
3. `Episode / MemoryClaim / MemoryEntity / MemoryLink`：目标-步骤-失败-实际结果-证据串联，Claim 双时间（何时成立 vs 何时得知），跨项目采用稳定 ID、边分清证据支持/反驳/步骤顺序/因果候选。
4. `WorkingContext / ContextBundle`：生成给 Atlas 或执行器的即时上下文，可丢弃，不能被反复回写当新来源。ContextBroker 支持 `prepare_context`、`request_more`、`collect_result`、`record_episode` 四种最少动作。
5. `MemoryPolicy / Skill / Commitment`：检索策略、已经可执行的 Skill、定时或条件未来承诺分别独立语义；重用现有 SkillOpt 和运行调度，避免 Skill 或提醒只存一个向量标签。

### 操作流程

- **入库**：原始日志证据不可因摘要更新而丢失；按唯一来源 ID 消费，记录 extractor_version/checkpoint。长期事实支持 user correction/supersede/dispute/forget，且派生索引不能复活删除的内容。
- **召回**：对话/任务开始做轻召回；工具重复报错、重大决策、切换子任务、调用 Skill 前动态触发。精准 ID/path/error 优先词法；模糊意图引入 embedding；证据不足再回到原始轨迹邻域；提取答案时明确已验证、来源转述、仍未知。
- **委派**：Atlas 首次给 ContextBundle；执行器可以继续 request_more（`task_id/query/seen_ids`），原文由 Atlas 查询；外部工具有 FULL_ACCESS，不额外审批；完成后 Atlas 接收可见的 diff/commit/log/test evidence。
- **巩固**：借 ReMe per-source/per-job 状态和 Graphiti 双时间；纠错、崩溃恢复、增量同步；模型做归纳而不整页无差别重写。
- **技能**：ReasoningBank/MemOS 等提供正负例和条件的提炼思路；最终由 Atlas 既有 SkillOpt 真正调用/验证/反馈/回滚，不另建竞争的晋升器。

## 6. V4 新增/遗留风险统一排队（去重）

| 级别 | 缺陷或不确定性 | 证据属性 | 最小验证动作 |
|---|---|---|---|
| P0 | W2 Dream 全局 checkpoint 跳过不足 3 天 group | 旧静态代码风险 | 3 天渐进产生项目，日更 dream，应含 3 天全部证据 |
| P0 | Dream 页面写入/Git commit 与 checkpoint 不原子；失败后重算 ID | 新静态代码风险 | 失败注入 + 重启，核对相同 source ID 恰好出现一次 |
| P0 | TurnQueue 只受单进程 asyncio.Lock 控制，跨实例无原子 claim | 新静态代码风险 | 双实例抢同一记录的并发消费 |
| P0 | TurnQueue `attempts >=3` 行永久离开 pending 查询 | 新静态代码事实 | 暂时模型故障三次后恢复，确认补提炼路径 |
| P0 | 模型管理器或 model_router 缺失时，处理后仍删 pending | 新静态代码风险 | 无模型运行一轮，恢复模型后仍可提炼 |
| P0 | 日记追加成功但 stage 未更新的中断可重复 append | 新静态代码风险 | 在 append / stage 之间故障注入和重试 |
| P0 | 来源 session@timestamp 近邻定位错位；工具步骤摘要有 30 条上限 | 静态确认的精度不足 | 同秒消息、超长工具任务精确打开第一步 |
| P1 | embedding 被索引 sync 线程调度但无 running loop；失效初始化不自动重试 | 静态调用链风险 | 正常对话自动构建真实 embedding 并可恢复 |
| P1 | trigger 文本代替稳定项目 ID | 静态设计缺陷 | 两个不同 repo 同名错误不得合并 |
| P1 | worker 不自动读 Atlas 记忆、执行中无完整追加上下文循环 | 静态确认 | 两执行器接续任务、途中再要旧决策/反例 |
| P1 | tool `ok` 和 `verified` 不等于用户目标成功 | 旧明确缺口 | 命令 exit=0 但功能不对不得自动晋升 Skill |
| P1 | W2 CJK 双字 gram 与 trigram 已有，不应重复开发；效果未量测 | 已读源码事实 | 中文短词/错误码/路径/概念同义查询实比 |
| P2 | 双时间、纠错再巩固、防来源自我强化、删除传播 | 设计要求未实测 | A→B→C 历史问答、修改后不复活旧说法 |
| P2 | SkillOpt 调度/采纳/实际复用率、负例 | 代码入口可见，链路待测 | 留出任务证明 Skill 改善，并能降级无效技能 |

**证据等级**：A=源码/官方仓库内容直读；B=官方说明/论文方法；C=第三方/待查；`Atlas_E2E_PASS` 仅在用户真实运行环境或可重复模拟上执行之后才能标注。不要用“源码存在”填 E2E PASS。

## 7. 真正值得优先比较的方案与最少测试

### 选型实验

- E01 队列/巩固幂等、失败恢复和三天 Dream；输出事件 ID 处理状态。
- E02 W2 weighted+MMR 与 Hindsight RRF，同一组中文语义词、代码路径、错误码、不同时间版本。
- E03 AMA-Agent 分级证据扩展 vs 只用 W2 摘要，要求解释一次真实 multi-tool 修复的因果与证据。
- E04 初始委派 + 执行中 request_more + worker 结果回流，换 Codex/Claude 后记忆仍归 Atlas。
- E05 事实纠错与双时间、多来源同一事实去重，模型自报成功 vs 工具客观验收。
- E06 memory→候选经验→既有 SkillOpt→执行效果，不因为产生更多 Skill 就认为成功。

每实验用相同真实轨迹、固定模型和预算、任务成功标准；指标包括 evidence recall@k、错误召回率、真实任务成功率、误用技能率、p50/p95、额外 token 和处理恢复率。原有 `source/02_本轮深挖/tests/atlas_memory_research_cases.jsonl`、`source/00_新增研究/03_实验与验收协议.md` 不用重造。V4 没有声称以上测试已执行。

### 什么时候才考虑大更换

- SQLite/原先本地存储在 1万/10万事件和实际多设备/并发负载上明显不合要求，再比较 Postgres/pgvector。
- 轻量两跳 Entity/Link 无法处理跨任务推理，再证明 Graphiti/专用图优于复杂度。
- 采用其他项目的长期记忆服务宿主，必须确实省去更多 Atlas 原生开发、也不能拥有第二份相互矛盾的用户/项目真源。
- 避免仅凭 GitHub Star、单一论文数字、记忆库总条数或“像海马体”名称作裁决。
