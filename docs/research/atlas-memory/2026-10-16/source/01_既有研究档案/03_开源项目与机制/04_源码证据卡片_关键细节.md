## E01｜ReMe：后台巩固状态机（**首选借鉴**）

**仓库版本** `agentscope-ai/ReMe@404aa6bf3b0cbe5047c504b347271fbb7d268aeb`，Apache-2.0。

1. `reme/steps/evolve/auto_memory.py`：`AutoMemoryStep` 从对话生成 daily note；`_sanitize_msg_for_save()` 主动过滤工具返回里可能包含的**已检索记忆**，防止“搜索结果回流到日志，下次被误认为用户的新表述”的自证循环。还包括消息图片保存时的路径与 ID 校验。这一安全措施 Atlas 很值得移植。
2. `reme/steps/evolve/dream/extract.py`：`DreamExtractStep` 扫描给定日期范围，区分 `changed/unchanged/deleted` 源文件；无改动就跳过；LLM 不可用记录失败，不把失败当已处理；模型从**本轮改动的文件**抽取少量 memory units。
3. `reme/steps/evolve/dream/integrate.py`：`DreamIntegrateStep` 对提炼单元逐项合入长久知识，使用应用级写锁，并对尝试前后的 digest 文件做快照比较；失败分支保留状态。
4. `reme/steps/evolve/dream/finish.py`：`DreamFinishStep` 只 checkpoint 未失败路径，输出扫描、变更、失败数量。不要使用一个无差别的“全成功”布尔位。
5. `reme/config/default.yaml`：可看到 `dream_cron` 的 `dream_extract_step → dream_integrate_step → dream_finish_step` 和手工 `auto_dream` 流程；同时存在自动记忆、文件索引作业。

**复制目标而非复制宿主**：Atlas 内设计 `consolidation_jobs(event_or_file_hash,status,attempts,last_error,last_processed_at)`；扫描增量事件→用 Atlas `model_router` 提炼→给 Markdown 写**候选**摘要/事实→独立检查证据→仅成功时 checkpoint。明确 `processing` 超时恢复、幂等去重。不要安装 AgentScope 整套框架、额外启动 ReMe HTTP 服务，不默认复制 ReMe 的私有 API 配置。

**危险点**：后台整理绝不能把工具/Web 检索到的旧记忆再次视为新事实；梦想/反思输出不可自行“核实”用户个人事实；隐私删除后不能从 backlog 回灌。

## E02｜MemOS 本地插件：真正的 L1→L2→L3→技能（**首选借鉴**）

**仓库版本** `MemTensor/MemOS@a7367d07e55db61099f7b4e2c1108bc5831a24f3`。注意顶层 Apache-2.0，而 `apps/memos-local-plugin/package.json` 声明子包 MIT；每个移植源文件逐一核权利链。该本地插件使用 TypeScript，Node >=20，并非可直接 `pip install` 的 Python 核心。

| 源码位置 | 实际做的事 | Atlas 目标 |
|---|---|---|
| `apps/memos-local-plugin/core/memory/l2/induce.ts` | `induceDraft` 把不同 episode 的证据轨迹交给 LLM，要求给出 `title, trigger, procedure, verification, rationale, caveats, confidence, support_trace_ids`，验证后生成候选策略 | 定义 `PolicyCandidate`；先保留证据而非自动执行 |
| `core/memory/l2/signature.ts`、`candidate-pool.ts`、`gain.ts` | 将同类轨迹聚类、构造候选并用独立证据/收益更新候选策略 | 不允许一条自生成结论多次转述凑“支持数” |
| `core/memory/l3/abstract.ts` | `abstractDraft` 聚合互相兼容的 L2 策略与来源轨迹，构造 `environment/inference/constraints` 和证据 ID，准备世界模型候选 | 世界模型仅限可验证环境规律，不能做“人格真理” |
| `core/skill/eligibility.ts` | `evaluateEligibility` 只允许 active、gain 足够、独立 episode 支持足够且成功锚点满足的策略结晶为技能；还处理重复/重建 | 直接借资格判断的思想/纯逻辑，挂 Atlas 已有技能库 |
| `core/skill/lifecycle.ts` | `applyFeedback` 维护 candidate/active/retired 生命周期、成功/失败次数与评价 | 失败自动降权/退役，有实测证据才升级 |
| `core/retrieval/retrieve.ts` | 区分 `turn_start`、`tool_driven`、`skill_invoke`、`sub_agent`、`decision_repair` 等召回触发，并给不同召回预算 | 重点借执行中 JIT 召回，防止只在用户发话时回忆一次 |
| `core/retrieval/ranker.ts` | 多检索通道合并、去重、候选排序、与奖励因素结合 | 可在现有 FTS/SQLite 上增加轻量多通道排序 |

**实施建议**：先 `L1 episode`（不单建多维库），再 `L2 policy candidate`，再 `L3 world observation`；每层都标清 `evidence_episode_ids`、`verified_by`、`scope` 和反例。技能提拔前至少一次**独立工具或用户反馈**；模型生成的 confidence 不算实测验证。每层可以独立 feature flag 逐步启用。

**切勿误判**：源码里有 L3/Skill ≠ Atlas 当前已有技能自动进化；MemOS 官方自报加速或准确率 ≠ Atlas Windows 上已经实现。

## E03｜OpenClaw：遗忘、来源、巩固、防回灌（**W0 对照基准**）

**仓库版本** `openclaw/openclaw@66207936af93c0ad90885633ea44e973872fa3ff`，MIT。

- `extensions/memory-core/src/memory-forget-kernel.ts`：`markMemoryForgotten()` 与 `purgeForgottenMemory()` 两阶段；结合 lineage、session tombstone、索引 chunks 与 embedding cache 清理。**不等于**完整 git 历史擦除，不能因此误称“OpenClaw 保证所有备份都忘”。
- `extensions/memory-core/src/memory-entry-origins.ts`：记录、查询、删除记忆来源；异步 Worker 有明确 mutation authority 概念；便于把事实映射回原会话/来源。
- `extensions/memory-core/src/dreaming-consolidation.ts`：模型给出添加、合并或替代计划，并明确旧内容 `priorEntries` 及来源标记；代码会解析和校验更新操作，原则是**把记忆文本当数据而非指令**。
- `extensions/memory-core/src/memory-budget.ts`、`memory-forget-*`、`short-term-promotion-*`：分层预算、提炼、忘记会话与晋升的真实代码。

**Atlas 直接修的点**：人工修改后旧结构化值一致性；遗忘先有 tombstone 以阻断读取，再清派生索引/日记/图链接，再处理版本历史与用户声明范围，撤销接口不得恢复已永久遗忘的正文；忘记后未消费队列也必须过滤。**注意**：清理原始 engine 日志和备份属于不同范围，需要做出明确用户可理解的约定，避免数据删除和运行审计的矛盾。

## E04｜A-MEM：低负担记忆卡片联结（**W2 可采用**）

`WujiangXu/A-mem-sys@f303dfc71e07bdc787f4bc135d4cea328ae30e99`，MIT。`agentic_memory/memory_system.py`：

- `MemoryNote` 数据包含 `context/keywords/tags/links/retrieval_count/evolution_history` 等，`analyze_content` 先用 LLM 标注，`add_note` 更新并写检索库，`find_related_memories_raw` 可沿 `links` 多取邻居。

`google-research/reasoning-bank@ed80611788292ea739f1effd31f16c53823b8a0d`，Apache-2.0：

## E09｜为什么不直接融合所有仓库

1. **许可**：仓库顶层和独立插件子包许可可能不同；第三方 README 引用的算法可能引用论文而没有可拷贝代码；实际复制时对每个文件保留版权/NOTICE/许可证，且检查非代码资产与模型权重的独立条款。
2. **Windows**：某仓库支持 Win ≠ Atlas Win11/Electron/自研 Kernel 同一进程可以正常装；Rust、C++、LanceDB、Graphiti/FalkorDB、GPU embedding 需要隔离或可选。
3. **运行模型**：Python/TS 的模型调用和回调方式不同，不应直接接第三方密钥池或复用自己的聊天模型设定。
4. **持续改动成本**：上游频繁更新，直接 fork 整套在 Atlas 内维护代价高；优先移植纯逻辑+附源码依据，后续按目的重新对照上游。
5. **评估门槛**：任何 P0/P1 可上线能力都必须能提供针对性回归（含 Windows 实测）；A 级“静态核对”绝不等于真实 E2E 可用。

## E10｜人工核实状态/不确定性提示

- 这份包在 Github 上直接核查到了上述**实际文件目录和具体函数名**；全部候选仍未经过 Atlas 运行环境导入测试。
- A-MEM、ReMe、MemOS 和 ReasoningBank 对迁移实现路径支撑最强；微软 Memora/MIRIX/Synapse 仅明确存在模块，不具备与 Atlas 对比的真实效果数据。
- OpenClaw 复杂遗忘系统里也未能证实“所有 Git、远端及备份彻底擦除”，不能做绝对安全保证。
- 上游版本固定在 `06`，再访问最新 README 不必重查全部仓库；只需目标函数级别有冲突时核验那个文件。
