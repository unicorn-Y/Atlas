# Atlas 长期记忆研究｜全域二次查漏与统一总账

> 日期：2026-10-14。依据用户原始 A/B/C 三份任务书、原交付 A/B/C 研究报告与 01-遗漏审计，再通过联网阅读官方说明、源码、Issues、用户评论与原始论文进行**独立增量核实**。定位是「研究证据和剩余工作总账」，不是宣称已完成每库实测、每位用户调查、每个仓库逐行审计。
>
> 证据层级：**P**=项目/产品官方文档；**S**=直接源码文件；**I**=原仓库 Issue/Discussion、开发者实证；**U**=原始用户评论；**R**=论文原文/学术出版；**T**=第三方整理/源码审计索引。**T 属于二手线索，所列缺陷仍需锁版本复核。**

## 0. 结论：原版为什么会一再漏

1. 最初目录范围由 A/B/C 三份任务书中的**例举名单**主导，没有用「Agent 记忆技术分类树 × 产商与开源生态 × 评测能力」作交叉扫描。
2. A 把「产品有一个章节」错误当成「功能、用户评价、逆向都有证据」，特别是将多个中国产品、陪伴产品合并；一些所谓 Top 20 抱怨不是用户第一手评论，频率也缺抽样分母。
3. B 用 13 维同一套文字模板覆盖了很多项目，但没有源码定位、固定 commit、当前许可证、写入 Prompt、纠错函数、删除级联、Windows/中文指标。
4. C 以长期问答指标为中心，**行动后的收益、程序/策略记忆、长期动态画像、多模态源的时间对齐**等方向不成体系。
5. 「找到新项目」和「完成深度研究」之前混成了一个计数；本次分开登记，不再以仓库数量宣布完成。

## 1. 新发现的可利用资源：不是继续从 0 搜 20 个仓库

**[Agent Memory Atlas](https://neoneye.github.io/agent-memory-atlas/)【T】** 和 [完整横向比较](https://neoneye.github.io/agent-memory-atlas/compare/)【T】为当前最重要的新索引：页面在检查时显示**732 套**记忆系统条目（网站自己的统计，未独立逐条核验）、按七种机制标记，公开记忆单元、存储、写入、召回、更正、权限范围、背景任务、信任与缺陷，并声称每个分析绑定具体 commit。[源仓库及评审方法](https://github.com/neoneye/agent-memory-atlas)【S/T】。它还有 [模式库](https://neoneye.github.io/agent-memory-atlas/patterns/)【T】与 [Benchmark 索引](https://neoneye.github.io/agent-memory-atlas/benchmarks/)【T】。

**最重要的使用方式**：先把 Atlas 当前已实现能力和这个索引的「纠错、scope、tombstone、双时间戳、审计、人工审批、负例」过滤器对照，再回到**被引用仓库的那个 commit**复核；不能把作者的结论直接写成自己已验收。

这个索引也给出了有价值的反例：它对 [SimpleMem 的代码审计](https://github.com/neoneye/agent-memory-atlas/blob/main/content/systems/simplemem.md)【T】指出文本记忆层只有整库清空、缺逐条删除/纠错，而同仓库 EvolveMem 部分另有 status、scope 和审计。这是**对不同子模块切开看**的必要性；当前仍按第三方代码评审线索处理，尚未由本次自行 clone 重跑。

## 5. A/B/C 三线交叉才看见的失败模式（增量，不用来凑论文数量）

| 现象 | 为什么真实重要 | 最快验证方法 / 研究线索 |
|---|---|---|
| ① **二次提炼复活旧错误** | 人工修改事实，但旧原文仍在归纳来源，下一次「睡眠整理」又把错误写回来 | 修正后连续跑两次后台整理，再搜旧错误；使用 rejected-value tombstone。参考 [Agent Memory Atlas 模式](https://neoneye.github.io/agent-memory-atlas/patterns/)【T】 |
| ② **用户不知道能审改** | “具有管理功能”在 UX 上等于不可发现 | 新用户零引导找入口；[LibreChat Issue](https://github.com/danny-avila/LibreChat/issues/11266)【I】 |
| ③ **记忆合并后遗漏哪条被修改** | 多份摘要不能解释来源、推论与用户确认的差别 | 每一事实保留原始事件指针和归纳版本链；[SimpleMem 源码审计](https://github.com/neoneye/agent-memory-atlas/blob/main/content/systems/simplemem.md)【T】 |
| ④ **自动后台记忆拖垮前台速度** | 用户想要的自然对话不应等待整理模型重试 | 故障注入 observer 超时，测聊天是否降级继续；[Mastra Issue #21849](https://github.com/mastra-ai/mastra/issues/21849)【I】 |
| ⑤ **工具操作的结果被过滤掉** | Agent 记住“调用过工具”却不知成功/失败，会学到错误技能 | 原始 trace: call → result → observation 强关联；[Mastra Issue #15244](https://github.com/mastra-ai/mastra/issues/15244)【I】 |
| ⑥ **多模态结果被转成无意义 token 流** | 图片、屏幕、语音不能靠一股脑塞文本模型而形成可靠记忆 | 多模态 MIME/时间/来源类型一致性；[Mastra Issue #15883](https://github.com/mastra-ai/mastra/issues/15883)【I】 |
| ⑦ **记忆没有触发真实行动** | 问用户生日答对，但主动提醒生日失败；高 QA 分数不能证明 Agent 能做好事 | MemoryArena / DolphinBench 任务执行成功率；[论文](https://arxiv.org/abs/2602.16313)【R】 |
| ⑧ **隐含偏好学错** | 用户行为和明确口头偏好不同；模型把偶然一次选择升级成长期原则 | 人物显式/隐式偏好分测；[PersonaMem-v2](https://arxiv.org/abs/2512.06688)【R】 |
| ⑨ **多源删除延迟/再发现** | 删除模型摘要，但连接到 Gmail/照片/原始聊天的事实还在 | 删除聊天/断开来源/上游源删除分别测；[Google 官方说明](https://support.google.com/gemini/answer/16598406?hl=en)【P】 |
| ⑩ **只有有效时间，没有认知时间** | 知道“事实发生在周一”，无法回答“我们周三才得知变化” | 两条时间轴分别保存 valid_time/observed_time；[第三方源码审计](https://github.com/neoneye/agent-memory-atlas/blob/main/content/systems/simplemem.md)【T】 |
| ⑪ **用户、Agent、项目隔离被后排序取代** | 检索到了不该看的内容，之后才过滤会泄漏到 reranker | 每层 SQL/search 的 owner 过滤先于召回；[Atlas capability index](https://neoneye.github.io/agent-memory-atlas/compare/)【T】 |
| ⑫ **“知道”和“能用”分数混算** | 记忆命中，却错误应用到当前情境，影响行动 | 将「找对、采用、适用、做对、停用」分开计分；[DolphinBench](https://arxiv.org/abs/2609.24971)【R】 |
| ⑬ **软件升级损坏原有记忆路径** | 记忆存到包缓存目录而不是固定数据目录 | 升级、回滚、搬家、双设备恢复测试；[MCP Memory 老 Issue](https://github.com/modelcontextprotocol/servers/issues/220)【I】 |
| ⑭ **系统把自动清理当真删除** | 正文删了不代表向量碎片/备份不保留 | 分逻辑删除、索引不可检索、物理删除、备份留存期限；[Agent Memory Atlas 的删除注释](https://neoneye.github.io/agent-memory-atlas/compare/)【T】 |
| ⑮ **敏感事项的“恰当沉默”** | 个性化准确不等于总应提及；陪伴 AI 不应无关时主动重提某伤痛 | 不触发负例、时间和情境阈值，要求有用户可见的主动提醒偏好；[过度个性化研究 OP-Bench](https://arxiv.org/abs/2601.13722)【R】 |
| ⑯ **用户纠正不能马上生效** | 后台索引异步完成前，下一轮仍给旧值 | “读己之写”一致性检查，及时失效原条目；[Google 同步延迟说明](https://support.google.com/gemini/answer/16598406?hl=en)【P】 |
| ⑰ **人格只靠模型模仿，不维护自己历史承诺** | AI 说「我会提醒你」但没有可执行待办，到时遗忘 | 自己的承诺独立于用户事实，交给可观察的计划/提醒调度；原始任务书已涉及，此处升级为可验收例 |
| ⑱ **评测指标误导复制方向** | 作者成绩常基于不同模型/抽取预算/评委，重现后可能排序反转 | 固定回答模型、评委、候选数和成本；[Redis 2026 复测](https://redis.io/resources/agent-memory-benchmark-report/)【P/实测】 |

## 6. 余项完成判定：以后不能再用“已收录”冒充“已研究”

| 状态 | 满足条件 | 不满足时必须怎么写 |
|---|---|---|
| **DISCOVERED** | 有真实可打开的产品/仓库/论文原始地址 | 只能说「发现了」，不能说「研究完成」 |
| **VERIFIED-FEATURE** | 官方文档或用户界面可复查具体写入、召回、控制行为及版本 | 缺项目版本、账户/地区差异写「版本未证实」 |
| **CODE-PATH** | 锁定 commit，标明写入 Prompt、数据结构、实体/时间/更新/删除/召回主要路径并核对关键函数 | 「支持xxx」但找不到代码只能列待核 |
| **REAL-USER** | 原帖 URL、日期、平台、产品、独立用户样本与可能重复源 | 不得从 1 条评论写「常见」；不许把研究风险当投诉 |
| **BENCH-REPRODUCED** | 相同测试集、固定模型/评委/成本、保存输入输出与 Windows/中文耗时 | 作者自报数字标「作者报告」；不能冒称本地实测 |
| **FIELD-COVERED** | 原任务书每一条要求有相应证据/明确失败记录（登录、robots、无原文等） | 不得宣布三份任务已彻底完成 |
