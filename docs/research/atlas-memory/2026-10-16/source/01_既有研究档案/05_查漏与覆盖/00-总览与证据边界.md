# Atlas 长期记忆三线调研｜总览、证据等级与未完成项

**研究日期：2026-10-14**。用途：为用户个人 Windows + 中文优先的 Atlas 长期记忆技术选型提供可追溯研究材料；**现阶段不代表已经修改 Atlas 仓库或跑过实机性能测试**。

## 一、交付范围

| 报告 | 已整理内容 | 本轮主要依据 | 尚不能据此得出的结论 |
|---|---|---|---|
| A 产品与用户抱怨 | 39 个产品/合并条目；定性 Top20 抱怨与失败模式；Top10 借鉴机制；闭源拆解难度排序 | 官方文档、真实 Reddit / App Store / Product Hunt 评论、GitHub Issues、部分论文 | 不等于样本具统计代表性；没有完整还原全部闭源服务端实现；部分中国市场 App 未核实 |
| B 开源项目机制 | 18 个开源项目/项目体系；每项 13 维问答与总表；若干代码级路径和问题 Issues | GitHub 实际文件、公开架构文档、论文、Issues/Discussions | 不等于 18 项全部源码逐函数审计；无本地 P95/内存/成本测量；许可证多数需锁版本 |

## 二、四条经得起原始资料核对的主要结论

1. **过期事实不只是“检索时间权重”问题。** [Memora/FAMA](https://arxiv.org/abs/2604.20006)（论文）专门惩罚引用已经失效的记忆。用于 Atlas 的高价值点是将“事实何时有效”和“系统何时记录/失效”分开。
2. **自动判断冲突会误伤不相关记忆。** Graphiti 提供 [`valid_at`、`invalid_at`](https://github.com/getzep/graphiti/blob/main/graphiti_core/edges.py) 等字段（源码），但 [#1728](https://github.com/getzep/graphiti/issues/1728) 是无关事实被错误失效的用户报告（单个 issue）。有时间图不等于冲突判断可靠。
3. **记忆要有“原始证据真源”，并将摘要和索引视作可重建衍生物。** [EverOS 的 Markdown + SQLite + LanceDB 设计](https://github.com/EverMind-AI/EverOS/blob/main/docs/how-memory-works.md) 是实在公开的方案；[claude-mem 的非阻塞 Hook→worker](https://github.com/thedotmack/claude-mem/blob/main/docs/public/architecture/hooks.mdx) 有在线速度参考价值。
4. **“知道过去”不等于“每次都提醒你过去”。** [OP-Bench](https://arxiv.org/abs/2601.13722) 直接研究过度个性化；[ProactAgent](https://arxiv.org/abs/2604.20572) 研究触发时机。Atlas 必须区分写入、找到、使用、主动打扰。

## 三、可信度和数据边界

- **级别 1**：可直接打开的源码字段、接口定义、官方公开行为。确认的是“此源码版本或页面如此描述”，不是现场跑通。
- **级别 2**：论文提出的方法、论文作者报告的成绩。确认的是“作者这么测/这么声称”，不是异构硬件/模型间公平横评。
- **级别 3**：Issue、Reddit、Product Hunt、App Store 的第一手用户或开发者报告。确认的是“有人经历或报告过”，无法推出全平台发生率。
- **级别 4**：技术风险分析和类推。必须保留“推断、待验证”；不可以冒充独立事故或事实。

## 四、检索平台尝试与访问不足

本轮已经检索尝试：知乎、V2EX、贴吧、小红书、B 站、即刻、掘金、CSDN、博客园、少数派、NGA、微信公众号、魔搭、语雀、公开飞书、Reddit、Hacker News、X、Lobsters、dev.to、Medium、Substack、YouTube、Product Hunt、Qiita、Zenn、note、Naver、App Store、Google Play、Hugging Face 讨论、GitHub Issues、OpenReview、arXiv 等。

**实际可追踪并有信息量的样本**：Reddit、App Store、Product Hunt、GitHub 文件与 issues、部分中文博客园和掘金、官方平台文档、arXiv 和 OpenReview 索引。比如 [中文 Graphiti 机制介绍](https://www.cnblogs.com/JavaPub/p/23180396) 仅作线索，机制结论回到 GitHub 核验；[Replika App Store 用户差评](https://apps.apple.com/us/app/replika-ai-companion-chat/id1158555867?see-all=reviews) 标明评论日期而非“2026 现状”。

**检索并不等于完整采样**：Naver 检索受 `robots.txt` 限制；小红书、贴吧、即刻、NGA、X、YouTube/Google Play 部分评论需要登录、反爬、地区环境或评论 API，未取得可独立复查的细致样本。国内产品官方长期记忆机制与可信投诉还缺资料。未完成这些区域时，不应声称“全球渠道已经找全”。

## 五、还差什么才能升级成任务书要求的最终全面版

- 国内豆包、Kimi、元宝、通义、文心、智谱、DeepSeek，以及国内陪伴 AI，每家需产品版本、屏幕行为、用户评论截图或永久链接、必要时用户自行提供应用包进行本地客户端拆解。
- 开源 18 项逐库固定 commit：读核心提炼 prompt、完整删除路径、当前 LICENSE、最近 Issues、CLI 可复现的中文小样本，并记录 Windows 实测 P50/P95、RAM、CPU、模型/token 成本。
- 论文原文评测细节（数据泄露与同条件比较）及 OpenReview 的实际审稿意见需逐篇检查并引用；现报告没有虚构审稿人观点。
- 收集一定规模且去重的论坛样本，才能把 Top20 从定性分析升级为有可信分母的“发生频率统计”。
- 这些材料最终应与 **Atlas 当前仓库** 对照，只筛选真正缺失、能最小代价复用的具体实现；当前未读取最新代码或修改仓库。

## 六、当前更有价值的研究顺序（非开发施工书）

Graphiti（时序和错误失效）→ EverOS（可编辑原文真源）→ Hindsight（分层召回与反思）→ claude-mem（非阻塞自动采集）→ Letta（代理自管理记忆）→ Kindroid / Nomi（陪伴和主动触发）→ Memora / OP-Bench / MemSecBench（验证何时**不应该**召回、保留、行动）。
