# 03｜Atlas 长期记忆统一架构与分阶段 Codex 施工蓝图（Opus 5.5 审核稿）

> **立场**：这是供 Opus 5.5 审查、修订的实施草案，不是既成代码。用户允许将不适配的机制逐步移植，不要求“一次性全装”；优先保证长期方向正确和数据不打架。除非明确需要，否则先别开第二套常驻记忆服务，不重写现有桌面/Kernel。

## A. 最终目标：不是让模型永久装载全部记忆

记忆应实现：**捕获 → 编码 → 标准化/归因 → 长期存储 → 召回 → 行动 → 结果反馈 → 巩固/再巩固 → 策略/技能晋升 → 可信度更新与遗忘**。Atlas 主人是唯一事实授权方，Agent 可以学习操作经验但不能通过自我总结伪造用户事实。记忆库可用不同模型/不同工具调用/不同设备访问。

### 1. 推荐的六层结构

```text
输入：用户文本、视觉/语音、电脑/手机工具轨迹、子Agent结果、系统状态
   │
[事件观察层 L0]
   ├─ 真实事件和引用: engine/state.db, run log, media refs; 不重复保存原始大文件
   ├─ source_kind/user|agent|tool|web|subagent, privacy_scope, evidence_refs
   └─ durable pending queue + idempotent event IDs
   │
[情景层 L1 — 类海马体]
   ├─ episode: goal/participants/time/steps/environment/outcome/evidence
   ├─ pattern separation: 相似但不同事件不合并
   ├─ salience/novelty: 决定优先巩固什么，不决定原始资料是否被抛弃
   └─ cue indexes: 多线索/实体/场景/时间
   │
[事实/人物/项目层 L1.5]
   ├─ 人、事、用户事实、项目状态、Atlas自己的重要行为
   ├─ 来源等级+有效时间+人工覆写+历史/矛盾
   └─ Markdown 人可读真源, SQLite 派生倒排/关系/可选向量
   │
[巩固层 L2 — 背景/睡眠]
   ├─ ReMe: only changed episodes → extract units → integrate → checkpoint
   ├─ 事实跨事件链接/合并重复/提出冲突/保留引用
   └─ ReasoningBank/MemOS: 失败与成功轨迹归纳「候选策略」
   │
[模型/技能层 L3]
   ├─ world observations: 设备/项目/工具版本、环境规律, 来源+时效
   ├─ policy: 触发/步骤/适用/禁用/验证/反例+support cases
   ├─ skill candidate → trial result → active | retired
   └─ 实际执行交给 Atlas 已有工具/技能库，不发明第二安装器
   │
[召回/行动/反馈]
   ├─ turn_start: 常驻少量+按需相关事实
   ├─ tool_error, stage_change, subagent_result, decision_repair: JIT 动态回忆
   ├─ prospective_intent: 条件/时间触发而不是都塞进 prompt
   ├─ evidence-aware response: 找不到说不确定，不把模型猜测当来源
   └─ action outcome: pass/fail/partial, verifier, negative_examples → 反馈到 L2/L3
```

### 2. 数据主权，避免“多个真源”的含混

1. **原始事件权威**：现有 `engine` 会话、工具执行日志、媒体库、工作区变更；有稳定 ID 和权限。
2. **提炼记忆权威**：`data/memory/*.md` 及结构化片段，是用户可查看编辑的长期知识源；记录证据指针而非复制原始日志全文。
3. **索引是派生品**：SQLite FTS、实体/关系图、可选向量索引与运行状态队列可重建或恢复；不能变成第二套“未经审查可自写用户事实”的真源。
4. **作业状态不是知识真源**：队列/检查点在 SQLite；可以从已处理事件重建，未处理项必须持久。
5. **Git 提交不是不可删除的保险箱**：用户要彻底忘记时，要与密钥/隐私需求兼容，不能被 `revert` 复活。

**注**：不要机械照搬“Markdown 是唯一真源”到原始工具日志；真正的原始运行证据已经有独立权威来源。应该保证**同一种信息只有一个权威写入路径**，而不是所有字节只允许一种数据库。

## C. 运行流程中插槽建议（逐步加，不重做 Kernel）

```python
class MemoryPort:  # 伪接口，不是项目现有可调用类
    async def recall_for_turn(self, message, task_context, budget): ...
    async def recall_for_event(self, trigger, event, budget): ...
    async def observe_event(self, event): ...             # durable enqueue
    async def observe_turn(self, user_msg, response): ... # 保留老入口向下兼容
    async def read_evidence(self, refs, principal): ...
    async def run_consolidation(self, checkpoint): ...
    async def record_outcome(self, episode_id, verification): ...
    async def forget(self, request, scope): ...
```

- **保留** `agent/run_phases.py` 的前置+后置插槽；把实际策略藏在库模块内部，由 `memory.library.enabled` 总开关控制。
- 在 `kernel/loop.py` 关键时机（工具异常、阶段切换、子 agent 结果、停止前验证）加低预算事件召回；**不允许每个 token/每张截图都触发模型调用**。
- `memory_search` 增加 `kind, filters, as_of`，再按需增加 `memory_get` / `memory_trace` 返回来源证据；保障旧调用兼容。
- 捕获原始工具轨迹：**不要求保存密码、私钥、浏览器 session/cookie、全部屏幕视频**；对高敏输出先做脱敏/摘要与路径指针。
- 所有后台 LLM 走 Atlas 现有 `model_mgr.model_router`，不要复制各项目的独立 API Key 配置。配置固定写入模型、低思考成本、失败退化为原始证据可检索。

## E. 分阶段施工任务书（Opus 核查后给 Codex）

### W0：记忆可靠性补缺【必须先做，别扩散成全 Atlas 重构】

**范围**：`memory/library/{__init__,extract,index,store}.py`、`agent/run_phases.py`、`api/memory_library_router.py`、记忆 UI。

1. 人工修改语义完整，手改优先；候选冲突不自动覆盖。
2. 遗忘定义与覆盖范围清楚：停止提起/彻底删除分开；处理 Git、日记、索引、diff、revert、派生事实以及会话原文范围；备份/外部同步要注明限制；不可逆操作只在有明确用户授权和经过迁移时执行。
3. 原始观察先持久队列，后台消费提炼，幂等重试和失败记录。
4. 读前时效过滤、配额公平、先排除再排名、worker 可按 scope 读记忆。
5. 最少 9 个专门场景见 `01`。

**退出条件**：跨会话记忆可靠、更正立即生效、重启不丢、删除不复活、无旧服务依赖。无明确 host 验证不能写 PASS。

### W1：情景记忆 + 巩固任务【ReMe 方法】

- 在现有运行日志之上做 `EventRef`/`Episode`，具体怎么分段：当前 goal 与 agent run 作为首选自然边界，长任务分阶段事件；session 仅作容器不必等于一次经历。
- `episode` 需包含：时间/参与者/目标/关键步骤/工具输出引用/结论/验证状态/失败原因及其确定性。
- 后台阶段：`scan_changed -> extract -> integrate -> verify -> checkpoint`；必须只标记成功文件；再次运行幂等；对误判/无模型任务可追溯。
- 不修改既有聊天 engine 数据；只链接，减少重复存储。
- 初期巩固仅形成“情景摘要 + 可验证事实候选”，不要立即形成高优先级指令。

**退出条件**：隔天新会话追问一项 5 步操作任务，能还原前后经过及证据、明确哪一步真正验证通过。

### W2：关联 + 执行中召回【A-MEM + MemOS 检索】

- 新增 `MemoryRelation` 或用文件元数据表达双向可追溯链接。
- 召回优先：`exact/FTS -> alias/entities -> relation -> optional semantic`；对不同时间/不同故障采用 pattern separation，先确保不误认再强调“联想”。
- 在 `turn_start/tool_error/stage_change/subagent_result/verification` 启用不同预算；限制相同事件一轮重复注入；敏感情景默认不主动冒出。
- 实验可选 embedding 时，优先支持轻量多语 provider；开关关掉仍能用。

**退出条件**：碰到历史出现过的特定故障，执行中有依据地召回相似经历；面对不同原因的相似故障不会胡乱照搬。

### W3：从经历学到候选策略【ReasoningBank + MemOS L2】

- 证据至少来自不同的 episode，不能从同一个失败事件反复总结当成多次独立证据。
- `policy`: `trigger, preconditions, procedure, verification, rationale, caveats, negative_cases, evidence_refs`。
- LLM 产物初始 `candidate`，未经工具验证不自动升级；允许 user override/删除；冲突策略并存并标边界。
- 新策略只影响“检索建议”，默认不被当作永久系统提示或立即可执行技能。

**退出条件**：能回答“为什么以前这办法有用、什么时候失效”，实际类似任务有改善，无证据不装懂。

### W4：世界模型、技能生命周期、未来记忆【MemOS L3/Skill + Atlas 自有系统】

- 环境/世界模型不是“关于世界的所有知识”；仅保留对具体设备、操作环境、依赖版本、系统状态已观察的规律。
- 技能晋升只在多个独立 episode 实际证据+最低成功反馈、边界检查后进行，挂现有技能库；保留降级/回退路径。
- 未来条件意图：pending/armed/fired/done/cancelled/expired，有触发条件、截止时间、冷却、去重与用户可见操作；复用已有提醒/任务框架。

**退出条件**：在新任务上重复用成功经验；已失效的技能不再自动推荐；“条件满足再行动”不漏且不循环。

### W5：桌面/手机多模态情景与空间认知（用户后续目标，必须预留接口）

- 事件可以绑定 `media_ref`（截图/video/ASR）与 `UIState`（应用、窗口、页面层级、控件证据、时间）；原媒体仍由各自的存储/保留策略管理。
- 高分辨率图像不直接在每次召回时塞进上下文，先用轻量场景摘要，确有必要再回读媒体原件。
- 将“曾经看到这个界面”与“现在界面仍是如此”严格区分；UI 交互需现时确认，不能信旧截图做高风险动作。

**退出条件**：Atlas 在常用软件看到错误能调出曾解决的相关经历，同时用当前截图确认界面状态，不会复制已过时点击坐标。

### W6：慢慢扩充的可选研究轨（不丢弃）

- Graphiti / HippoRAG 图检索：只当 FTS+links 的效果无法达到场景需求，再评估安装图数据库。
- Soar / CORTEX / Mnemos：小规模独立算法 A/B，不整体改写 Atlas Kernel。
- RLM：超长历史回溯按需调用，严格成本上限和沙箱控制。
- 本地模型 Titans/HOPE/Engram：研究性质，不能通过外部 API 直接更新权重。

## F. 依赖隔离与性能规则（允许逐渐适配，但别污染主仓）

- Python/WIN11/Electron 前端原则上保持现有依赖集；ReMe/MemOS/ReasoningBank 只移植纯计算与数据结构，不带 AgentScope/Node/WebArena 运行时。
- 可选依赖清单按照 `feature=on` 单独安装，版本锁死、在 Windows 小范围试用。公开仓库声称支持 Windows ≠ Atlas E2E 支持。
- 读路径尽可能没有 LLM：轻量索引、候选排序、时效/权限过滤；写/巩固/经验总结用专用 writer 模型，低优先级运行。
- 配额每个触发点可配置且有全轮 ceiling；避免工具调用 100 次触发 100 次昂贵回忆。
- “质量提升”必须评估：来源支持率、纠错一致性、实际执行结果、适用边界误判、遗忘覆盖、回忆 p50/p95、每 100 轮额外 token 成本。

## G. 对 Opus 的关键审查问题（必须回答，不要只说方向合理）

1. W0 有没有遗漏可实测的误记、恶意文本投毒、并发/崩溃/索引不同步问题？
2. Schema 是否存在不必要字段或自我循环；人工编辑的 `key/value` 应如何合一？
3. 保留完整原始证据是否与用户完全遗忘冲突？如何定义清晰的删除语义/备份策略？
4. 多 agent 的可见范围与共享身份怎样设计，既统一又不让外部内容升格为主人命令？
5. MemOS 策略 `gain`/`support` 是否真能在 Atlas 工具反馈中得到非虚假的结果？
6. 哪些算法技术/许可门槛实质更低，适合先抄？哪些本包高估了可移植性？
7. 为保证“逐步接入”，W1/W2 的可选适配器、rollback 与初始数据转换应如何做？
8. 是否有更优替代，但必须提供代码证据才能推翻当前选型？

**Opus 若认同方向，输出经过压缩的 Codex 分波任务书；不要在一个任务书里塞近百种算法，也不要仅因为名字仿脑就给高优先级。**
