# Atlas 记忆系统：源码级筛选、移植路线与施工任务书

**调查日期：** 2026-10-15  
**Atlas 基线：** `unicorn-Y/Atlas` 的 `memory-v1`，提交 `7826e91c6c71dfc180f6fad6136b5eb53a9dab52`  
**目标：** 保留 Atlas 现有单一记忆真源，选用成熟开源算法补全事件记忆、关联召回、巩固、自我经验和技能形成；速度优先，不重复叠加多个数据库或常驻服务。  
**证据分级：** A=直接查看源码/依赖/目录；B=官方源码仓库文档；C=作者报告/项目宣传，尚未独立复现。  
**验收边界：** 本报告属于远程静态源码和资料审查；未在用户 Windows 主机运行性能、准确率或集成测试；未修改 GitHub 仓库。

## 0. 核心结论

1. **保留 `Markdown + Git + SQLite` 真源及 `get_library()` 生命周期插槽。** 不要安装另一套完整记忆后台替换它，更不要同时启用 2~4 个独立真源。
2. **第一优先级：ReMe 的分层记忆与增量巩固。** 学其 `session -> daily -> digest`、变更扫描/检查点、来源引用与文件图；不整套引入 AgentScope 服务。
3. **第二优先级：MemOS 本地插件的 `Trace -> Policy -> World Model -> Skill`。** 这是最直接能改善 Atlas 做事能力的部分。按源代码的纯算法/数据结构在 Python 中移植；不为此安装 Node 常驻核心。
4. **第三优先级：A-MEM 的记忆关联、ReasoningBank 的成功/失败经验提炼，必要时参考 HippoRAG 的关联排序。** 尽可能复用现有索引；向量化可选且后置。
5. **先修既有 P0 再加高级记忆**：编辑文本与 `value` 不同步；遗忘后 Git 历史/变动页面/日记可能泄露；后台提炼无持久队列；过期事实在检索前未过滤；召回配额被第一类占满。
6. **项目变更纠正：** 原 `EverMind-AI/EverMemOS` 已更名/迁移为 `EverMind-AI/EverOS`，不是两个独立系统。另有 `EverMind-AI/EverAlgo` 算法拆分库。

## 3. 可以直接借鉴的代码细节（不是泛泛推荐）

### 3.1 ReMe：增量梦境巩固（最合当前 Atlas）

- `reme/steps/evolve/auto_memory.py`: 对会话消息做来源过滤，刻意不保留可能包含重复召回文本的工具结果，防止搜索结果被再次当成用户亲口事实；对图片引用有路径与格式校验。
- `reme/steps/evolve/dream/extract.py`: 默认按日期扫描，按文件修改时间比对先前检查点，**未变化就跳过**；模型不可用时标记失败路径，不把本次变化假装已处理。
- `reme/steps/evolve/dream/integrate.py`: 将抽取单元逐项整合进 digest；以写入锁序列化；有文件变更侦测和结构化结果校验。
- `reme/steps/evolve/dream/finish.py`: 区分成功路径和失败路径，持久化已处理检查点，让下一次只重跑必要部分。
- `reme/config/default.yaml`: 有 `dream_cron`、`auto_dream`、`auto_memory` 等配置入口。

**移植办法**：不把 Atlas 的 `我.md/现状.md/人/事` 换成 ReMe 格式；在 `data/memory` 下增加 `情景/` 与 `巩固/` 或明确的 `daily/digest` 视图和一张 `consolidation_jobs` SQLite 状态表。复用 Markdown 真源和索引，复用 Atlas 当前模型路由。关键对象：`source_session_id`、`source_message_ids`、`source_event_ids`、`checkpoint`、`attempts`、`status`。只处理新增加或被编辑的输入，保留来源引用。

**不要直接复制** `AutoMemoryStep`/`DreamExtractStep` 全类当作独立函数，因为它们调用 AgentScope `BaseStep`、上下文、`file_catalog` 等大量服务。先把算法状态机抽出来重写 Python 最快。

### 3.2 MemOS：不是记更多，而是从工具轨迹学习

- `core/memory/l2/induce.ts`: 至少多个不同 episode 的证据聚合为候选策略；提炼 `title / trigger / procedure / verification / rationale / caveats / confidence / support_trace_ids`。含结构校验、失败降级与文本安全处理。
- `core/memory/l3/abstract.ts`: 多条相关策略聚簇后，生成环境、推断与约束等世界模型字段，保留底层 trace 引用；与存储解耦。
- `core/skill/eligibility.ts`: 只有 `active` 策略、达到 gain/support 门槛、存在成功证据、没有过期重复技能，才晋升技能。
- `core/skill/lifecycle.ts`: 技能随实际任务反馈更新成功率与状态，包含概率平滑；可降级或退役。
- `core/retrieval/retrieve.ts`：按 `turn_start / tool_driven / skill_invoke / sub_agent / decision_repair` 使用不同取回预算。这比 Atlas 目前只在用户发消息时自动召回更值得学。
- `core/retrieval/ranker.ts`：多通道召回与去重排序，不必每轮全部知识加载。

**移植办法**：从 Atlas 已有的 engine session、工具结果、任务日志采集 `trace`（任务、目标、工具、输入、输出摘要、错误、最终是否通过验收、证据路径）；把 `policy / world / skill` 放为单一真源的结构化 Markdown/JSON 记录，SQLite 仅为派生索引；从现有技能库加载已验证技能。初期关闭自动执行新技能，允许主动推荐；只有实际验收成功才能激活，不要让 LLM 一句“完成”就算成功。

**不要直接安装 MemOS 本地插件作为 Atlas 的记忆核心**：子包需要 Node >=20 和自身 SQLite 管道，还会形成第二套真源；其 Hermes adapter 面向特定宿主，Atlas 已经换为自研 kernel。

### 3.3 A-MEM：自动联结而不是另建数据库

- `agentic_memory/memory_system.py` 的 `analyze_content` 由模型生成关键词、摘要、上下文和类别，`add_note/process_memory` 连接新记忆与历史邻居；`find_related_memories_raw` 进一步展开关联节点。
- 当前工程版直接使用 Chroma、sentence-transformers、transformers 等，不适合为几条关系额外装常驻嵌入体系。

**移植办法**：新增低成本 `memory_edges` 表，边格式 `from_id, relation, to_id, evidence, confidence, valid_from, valid_to`；先用人物/项目 ID 和规则连边，模型联想作为低可信候选，复用 Atlas SQLite 索引；别让模型“觉得有关”就等同于事实关联。

### 3.4 ReasoningBank：提炼正面和负面操作经验

- `WebArena/induce_memory.py` 实际从 `think + action + success/failure` 轨迹整理记忆项；`WebArena/memory_management.py` 使用多种嵌入提供者，包含非常重的模型加载逻辑。
- `README` 明确说明该实现用于研究与演示，**不是官方生产支持产品**。

**移植办法**：只借 prompt/输出 schema 和经验质量过滤，**不安装** `WebArena`、Vertex 和大型嵌入依赖。统一交给 Atlas 现有专用模型路由。

### 3.5 EverOS / EverAlgo：值得关注，但整包有硬依赖风险

- 最新 EverOS `pyproject.toml` 直接写出了 Lancedb 版本兼容与某些 EverAlgo 版本搭配导致默认 `POST /add` 报错的问题；须锁版本复测，不能假定 `pip install everos` 一装就稳定。
- EverAlgo 把 user-memory、agent-memory、rank、knowledge、boundary 算法分包，**更适合抽算法参考**。
- Atlas 已有 SQLite + 可编辑 Markdown，完全替换为 LanceDB/SQLModel 会增加工程迁移及错误风险。

### 3.6 MemPalace：保原文方向对，但不要被排行榜带走

- 官方提供分层存储和 `mempalace/searcher/`、可插拔后端；默认 Chroma，需要嵌入模型（官方多语言选项约 300MB）。
- 作者给出了 Python/NumPy/Rust 检索后端在 168k/334k 行规模上的性能对比，同时明确历史数字并未在后续修复后重新跑；不可直接宣称 Atlas 获得同样性能。
- 适合借用 transcript 的逐条定位、结果证据引用和分层召回；Atlas 本就有 engine/state.db，不应拷贝一次独立聊天存储。

## 4. Atlas 最小施工分波（供 Codex 直接派工）

### W0 — 修现有记忆的硬性正确性（先做）

1. `edit_entry` 保持 `text/value/key/src` 一致；对用户手动修改的事实设明确覆盖优先级，自动提炼不得静默覆盖。
2. 遗忘定义分两档：**停止主动召回** 与 **用户要求彻底删除**。彻底删除必须覆盖 Markdown、派生索引、日记、diff 展示、可恢复版本、原始会话及备份的处理策略；不能承诺删除未检查的远端副本。Git 历史改写属于不可逆操作，先做安全迁移/备份计划、明确范围，别直接全库重写。
3. 先持久化待写任务，再异步调用提炼模型；重启后续跑/幂等处理，避免同一会话写入重复。来源记录不可混入外部网页/工具输出。
4. 召回前执行有效期过滤；三类常驻页独立分配最低预算；候选排除与排名先后顺序修正。
5. 留下 6 个简短真实验收案例：跨会话、用户更正、彻底遗忘、重启待写、过期事实、未发生过事件不能编造。

### W1 — 情景记忆与增量巩固（核心升级）

**参考 ReMe，不启动另一套服务。**

- 新增 `episode_id`，由事件边界决定一个操作任务的开始/结束；包含 user goal、session、事件时间、关键工具调用、环境变化、结果、证据指针。
- 原始事件留在已存在的 engine/run logs，只保存索引指针和可读的事件卡片。
- 基于变更检查点巩固 `episode -> digest`：一次只整理改动事件，保存失败待重试，不阻塞当前对话。
- 新增 `memory_search` 的 `kind=episode` 与 `memory_get` 来源回读，召回事件时能恢复时间、原因和结果。

**验收：** 新会话问“一次 Atlas API 修复为什么失败、后来怎么成功”，回答提供正确事件路径和来源；编造不存在的修复必须拒绝。

### W2 — 动态召回与联结（体验提升）

**参考 MemOS 检索与 A-MEM 卡片关系。**

- 在 `turn_start`、关键工具报错、工作阶段改变、sub-agent 汇报、最终验收前五类事件上设置小预算召回；限制重复注入和总 token。
- 使用混合关键词+来源+人/事关系；不添加强制常驻 embedding。向量检索只作为可选插件，并提供无向量退化路线。
- 原始事实、用户更正、外部证据、模型猜测必须在结构化记录中保留不同可信来源。

**验收：** 同一目标两次不同故障不会混为一谈；工具异常发生后会检索对应历史经验，而不是只依赖开场记忆。

### W3 — 成功失败经验、世界模型、技能晋升（自主能力升级）

**参考 MemOS L2/L3/Skill、ReasoningBank。**

- 至少两条不同任务的证据才允许形成共享策略候选；明确 `trigger/procedure/verification/caveats/negative_cases/evidence_ids`。
- 世界模型只保存验证过的环境规律/系统版本/约束，不直接把模型的预测变成规则。
- 候选策略必须通过实际操作反馈才能激活为技能，支持降级和退休。让现有 Atlas 技能库承接执行，不造第二套技能安装器。
- 用户能查看“某条策略来自哪几次任务、成功/失败如何改变其可信度”。

**验收：** 过去成功经验能缩短类似任务操作；遇到已记录的反例不会盲目照搬；失败的技能可自动停止推荐。

### W4 — 以后再考虑，暂缓

- HippoRAG/Graphiti/FalkorDB 全套图数据库；MIRIX 的全天候视频录制；Soar 认知运行时；Titans/HOPE/Engram 神经网络内部状态修改；RLM 递归运行时。除非有明确质量问题无法用当前轻量系统解决，否则不装。

## 5. 性能和工程约束

1. Atlas 主机属于 **Windows + Python 后端 + Electron/React**，核心改造优先 Python 标准库/现有 SQLite；新依赖要可选。
2. **读快写慢**：前置召回只用派生索引；模型提炼、记忆巩固、技能演化全在后台，不阻塞响应。
3. **保留一个可解释真源**：人工编辑后立即生效；搜索索引从真源重建。避免 ReMe/MemOS/MemPalace 各自写一份冲突的长期事实。
4. **模型成本可控**：分类只在新事件、状态变化或有价值的工具结果上触发，不要每条工具输出都调用 LLM。
5. **质量目标**：报告“证据支持率、召回正确率、幻觉与误失效率、遗忘成功率、实际任务收益、p50/p95 召回延迟”，而非用更多模块衡量效果。
6. **隐私/权限**：账号/令牌不入事实；网页和外部工具输出不可升格为用户事实或高优先级指令；子 Agent 标记作者、任务和来源；忘记必须有覆盖范围。

## 6. 给 Codex 的任务书（可复制）

> 工作分支基于 `memory-v1` 最新 HEAD。只改 Atlas 记忆系统；不再安装新的独立记忆服务。保持 Markdown 真源 + SQLite 派生索引 + 现有模型路由 + 前端框架。第一波先修 W0 的数据正确性和持久化，完成后按 W1→W2→W3 推进。
>
> 可参考源代码：ReMe `reme/steps/evolve/dream/*` 和 `auto_memory.py`；MemOS local plugin `core/memory/l2/induce.ts`、`l3/abstract.ts`、`core/skill/{eligibility,lifecycle}.ts`、`core/retrieval/*`；A-MEM `agentic_memory/memory_system.py`；ReasoningBank `WebArena/induce_memory.py`。把算法和状态机移植进 Python，不照搬其宿主运行时和数据库。
>
> 每波只做足以证明行为有效的少量回归和真实对话案例，禁止为了测试而引入大量新框架。每波提交并推送仓库，附关键代码落点、效果对比、未达成项。不要把未运行的 Windows 实测写成 PASS；不要默认重写用户的 Git 记忆历史或删除既有数据。
