## A. Atlas 真正运行的记忆链路（基线：`unicorn-Y/Atlas@7826e91`）

| 动作 | 代码和调用 | 直接可核对的事实 | 施工原则 |
|---|---|---|---|
| 每轮召回 | `core/atlas/agent/run_phases.py` `_phase_context → _merge_library_recall`；`memory/library/__init__.py` `recall` | 非 worker 自动读取常驻和相关记忆；`_build_messages` 生成 SystemMessage；`_hermes_turn` 合并并传入 `KernelRequest.system_message` | 保留宿主级插槽；不要只在 Hermes 插件层挂钩 |
| 主动搜索 | `core/atlas/kernel/loop.py` 的 `memory_search`；`kernel/tools.py` 工具 schema | 可以请求 `.search(query, limit, include_history)` | 增强同一搜索接口，保留返回 evidence refs |
| 后台写入 | `run_phases.py` `_phase_finalize → _schedule_library_write`；`memory/library/__init__.py` `schedule_turn/observe_turn` | `asyncio.create_task`，内存 `_tasks`；先写日记，再 LLM 提炼，再 `extract.apply` 和 git commit | 必须引入持久待办与幂等；不能因推理失败让原始事件丢失 |
| 当前永久记忆 | `memory/library/store.py` | Markdown + 独立 git；SQLite index 由文件重建 | 保留单一数据主权与可回溯来源 |
| 当前忘记 | `memory/library/__init__.py` `forget_entry`；`store.py` `redact_diary, commit, show, revert` | 只消除当前文本和部分日记，Git 旧历史仍保留；变动 UI 可显示删除差异；`git revert` 可恢复 | 忘记必须跨文件、索引、历史、UI、备份与派生知识一致 |
| 编辑矛盾 | `memory/library/__init__.py` `edit_entry`；`extract.py` `known_facts, apply` | 编辑 `text/src/at`，未同步 `value`；LLM 提炼读取 `entry.value or text`；`apply` 无 owner override 保护 | 用户改过的值为高优先；值/文/来源一处更新 |
| 常驻挤占 | `memory/library/__init__.py` `_resident_block` | 总预算 1500 chars，固定按 `我.md → 现状.md → 它自己.md` 顺序截断 | 每类最低配额和冲突/失效筛选 |
| 时效 | `extract.py` `expire`; `library/__init__.py` `recall` | 过期整理在后置写入，前置读取不主动过滤 `until` | recall 必须先执行只读有效性过滤 |
| 召回截断 | `library/__init__.py` `_relevant_block` | FTS Top12→排除已覆盖页→Top3，过滤发生在 Top-K 之后 | 候选过滤应先于 Top-K，允许候选补全 |
| 子 Agent | `run_phases.py` `_phase_context` / `_phase_finalize` | `worker` 不自动加载长期记忆也不参与普通后置记忆写入 | 共享索引、作用域和归因，别让 worker 任意写成 owner 事实 |
| 自身经验 | `library/__init__.py` `_write_diary` | 用户最多 2000 字；助手回复最多 300 字；没有将整轮工具 trace 结构化为 episode | 引用原始 run-log 和工具结果，避免存重复大文本 |
| 承诺与部署 | `docs/memory/PLAN-V1.md`, `PURGE-RESULT.md` | 计划比现有代码实现丰富；2026-10-14 报告称 Windows host 清理和真人模型验收未完成 | 不能把计划书 COMPLETE 等同于主机 E2E PASS |

## B. ReMe：可以移植的“睡眠巩固”状态机（A）

仓库：`agentscope-ai/ReMe@404aa6bf3b0cbe5047c504b347271fbb7d268aeb`（Apache-2.0）。

具体文件：
1. `reme/steps/evolve/auto_memory.py`：会话上下文转日记；`_sanitize_msg_for_save` 特别过滤工具检索返回的旧记忆，防止“从自己刚搜出的记忆再提炼成用户事实”的证据回流。
2. `reme/steps/evolve/dream/extract.py`：扫描最近天数的 Markdown 输入，比对文件修改时间/目录索引，仅对发生变化的内容执行提炼，LLM 不可用时记录失败路径，防止无限重试同一输入。
3. `reme/steps/evolve/dream/integrate.py`：把候选记忆单元逐项合并到摘要/长期文件；集成时使用应用级异步锁、记录具体改动文件、处理部分执行成功。
4. `reme/steps/evolve/dream/finish.py`：只把成功处理的文件推进 checkpoint，保留失败路径供后续处理。
5. `reme/config/default.yaml`：存在 `dream_cron`（extract/integrate/finish）以及 `auto_dream` 任务定义。

**可直接按原理重写的算法步骤**：增量源检测 → 待处理候选 → 强制带 evidence refs 的 LLM 抽取 → 版本冲突检查 → 逐单元合并 → 成功 checkpoint / 失败保留 → 定时再跑。Atlas 现有 Markdown + SQLite 足够承载这些状态；不必全装 AgentScope。

**必须自行补的保护**：ReMe 流程不等于天然拥有可靠忘记；忘记名单必须优先参与未来巩固，旧日记不能重新晋升已删记忆。过期、用户覆写、来源类不同，需明确优先级。

## C. MemOS 本地插件：Trace → Policy → World model → Skill（A）

仓库：`MemTensor/MemOS@a7367d07e55db61099f7b4e2c1108bc5831a24f3`。注意 **项目顶层许可证 Apache-2.0，`apps/memos-local-plugin/package.json` 另标 MIT**；复制具体文件前必须按该子树 LICENSE/NOTICE 复核。包要求 Node >= 20。

**已读源码和可提取的纯逻辑**：
- `apps/memos-local-plugin/core/retrieval/retrieve.ts`：把召回场景显式分为 `turn_start`、`tool_driven`、`skill_invoke`、`sub_agent`、`decision_repair` 等；各自的 TopK 和 L1/L2/L3 注入规模不同。**相较 Atlas 只在轮开始召回，这是最直接的升级点。**
- `core/retrieval/ranker.ts`：多通道召回融合、相似性排名、去重和奖励优先；纯排序逻辑可复写 Python，底层无需保留 TS 宿主。
- `core/memory/l2/induce.ts`：从多段独立 episode 证据归纳候选策略；JSON 包括 `title / trigger / procedure / verification / rationale / caveats / confidence / support_trace_ids`；草案先为 `candidate`，不直接升格。
- `core/memory/l3/abstract.ts`：从兼容的 L2 策略簇与原始 traces 提出世界模型，保留环境/推断/约束及 evidence IDs，不直接代替事实。
- `core/skill/eligibility.ts`：晋升条件检查状态、收益、独立证据数、成功锚点、是否已被现有技能覆盖；纯逻辑适合直接移植。
- `core/skill/lifecycle.ts`：技能候选→活动→后续修正，按成功/失败反馈更新试用计数和置信/效用；不允许只因 LLM 生成漂亮描述就自动视为成功技能。

**推荐移植顺序**：先 `retrieval` 场景接口 → 再 L1 episode schema → 再 L2 候选策略 → 回馈的验证/禁用条件 → L3/Skill 最后接。不要把 L3 “世界模型”当成有事实保证的真实环境状态。

## I. 库与运行的工程级禁令（来自实际证据，避免空泛）

1. 任何项目的 README benchmark、星数、卖点都不等于 Atlas 真实结果；不会把“AGI/仿脑/最强”写成验收标准。
2. 不并排运行 ReMe + MemOS + EverOS 三套完整真源。允许可插拔**算法服务**或被动影子试验，但每条记录只能有明确 owner、revision、source、confidence、evidence_refs。
3. 高危删除不要默认 `git reset --hard` 或暴力清理工作目录；遗忘可能涉及 raw session、索引、历史、导出、备份，要求范围表和可重复、可验证的处理策略。
4. 不要将 “A：源码阅读” 描述成“功能已实测”，也不要因为某个研究仓库依赖多就永久抛弃——列入慢速适配/隔离试验轨。
5. 许可：对具体复制代码/文件保留 SPDX、版权所有者及 NOTICE；同仓子包可能有不同许可，不要凭 README 直接确定。
