# Atlas 记忆系统全域调研交接包｜Opus 5.5 先读

**基线日期：2026-10-15。仓库：`unicorn-Y/Atlas`，应基于 `memory-v1`（**不是 `main`**），已核对 HEAD `7826e91c6c71dfc180f6fad6136b5eb53a9dab52`。**
**目的：让 Opus 5.5 在不重新全网检索、不把二十多套系统逐个下载试装的情况下，审查 Atlas 记忆体系的缺口、判断算法移植取舍、给 Codex 可施工方案。** 本包是公开仓库和用户仓库的静态源码/依赖审查；不是 Windows 主机端到端实测，不是性能实测，也未改变 Atlas 代码。

## 【先读即得到的结论】

1. Atlas 已具备：每轮开始读取 `我.md/现状.md/它自己.md` + 线索匹配，系统提示词注入，`memory_search` 工具，回复后异步 LLM 提炼，Markdown 文件+独立 Git，派生 SQLite/FTS5、网页管理 UI。接线位于 `core/atlas/agent/run_phases.py` → `core/atlas/memory/library/` → `core/atlas/kernel/loop.py`。
2. 基线存在真正阻断可靠性的风险：**人工修改只更改 `text` 却没同步 `value`；遗忘只提交 Git 而不清旧历史/变动 diff，旧事实可被恢复；异步写入无持久队列；过期时效在写后而非读前清理；常驻配额按“我→现状→它自己”固定挤占；检索先取 top12 再排除常驻导致遗漏候选；worker 自动注入缺失**。细节见 `01`。
3. 当前缺少真正的长程情景记忆、操作轨迹事件化、跨事件联系、执行中动态回忆、定期巩固、策略证据积累、技能晋升反馈、来源可信度隔离、未来条件触发、自我经历、视觉/手机感知事件。**这些不是要同时建成十套数据库。**
4. **最佳组合**：保留 Atlas 基线与数据主权；ReMe 提供 `daily → extract → integrate → checkpoint`；MemOS 本地插件提供 `L1 trace → L2 policy → L3 world model → skill` + 按运行阶段检索；A-MEM 提供关联更新；ReasoningBank 提供成功/失败经验提炼；StructMem 提供事件级绑定；可选 Graphiti/HippoRAG/语义向量以后再接。其余候选按 `02` 建立后续路线，不抹掉潜力。
5. **优先参考 OpenClaw 当前 `extensions/memory-core/src/memory-forget-*` 和 `dreaming-*`**，因为 Atlas 以前参照的记忆架构，其上游已处理遗忘/巩固更细。不能假定直接移植不用适配。
6. **两个重大防踩坑纠正**：`EverMemOS` 已迁至 `EverMind-AI/EverOS`，并有 `EverAlgo` 拆分算法库；**Letta** 最新研发代码在 `letta-ai/letta-code`，旧 `letta-ai/letta` 仓库属于归档旧服务。Mem0 2026 年公开的新成绩包含云端非开源优化，不能直接作为开源 SDK 性能对照。
7. **渐进接入**：不适配的不丢弃，放“备选模块+禁用开关+依赖隔离”轨道。避免一股脑把 Node、LanceDB、Graphiti、FalkorDB、GPU embedding、C++ Soar 塞入 Atlas Python 进程。以后有明确收益再逐步上。
