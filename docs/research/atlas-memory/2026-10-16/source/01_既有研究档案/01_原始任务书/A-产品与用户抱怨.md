我在给自己做一个个人 AI agent 的长期记忆系统（只服务我一个人，跑在我自己的电脑上）。目标是像人一样自然地记住和想起，但比人可靠：每条记忆能追到出处，用户能看到、能修改、能删除。

请你联网做一次调研，范围是**现有产品的记忆功能，以及用户对它们的真实反馈**。

## 要调研的产品

**闭源产品是这次的重点之一**，开源的另有任务。越全越好，下面只是起点：

1. 大公司助手：ChatGPT（保存的记忆 + 参考历史对话）、Claude（记忆、项目、聊天搜索）、Gemini（个人上下文）、Microsoft Copilot、Perplexity、Grok，以及国内的豆包、Kimi、元宝、通义、文心、智谱清言、DeepSeek 等的记忆功能
2. 陪伴类 AI：Replika、Character.AI、Kindroid、Nomi、Pi、Dot（New Computer）、Talkie，以及国内的星野、猫箱、筑梦岛等
3. 做"记住一切"的产品和硬件：Rewind / Limitless、Microsoft Recall、Personal AI、Plaud、Bee、Rabbit 等
4. 编程和办公 agent 的记忆：Cursor、Windsurf、GitHub Copilot、Devin、Augment、Claude Code、Codex 的记忆或知识库功能，以及 Monica 这类浏览器助手
5. 闭源的记忆服务和平台：Zep Cloud、mem0 托管版、Letta Cloud 等，以及你知道的其它商用记忆 API

## 每个产品请回答

- **怎么记**：自动记还是用户叫它记？记的是原话、摘要，还是提炼出的事实？
- **怎么想起**：每轮自动带入，按需检索，还是靠关键词触发？会不会主动提起过去的事（比如主动问"你昨天说的面试怎么样了"）？
- **用户能控制什么**：能不能看到全部记忆、修改、删除、暂停？删除是真删吗？
- **"有自己的想法 / 不只是顺着用户"**：陪伴类产品是靠什么做到的（人设、记住自己说过的话、主动发起对话……）？
- **用户最常抱怨什么**：这一项最重要。请去 Reddit、贴吧、小红书、知乎、应用商店评论、官方论坛等地方，找真实的抱怨，比如忘事、记错、记忆混乱、人设崩、记了不该记的、隐私担忧、越用越慢。每条抱怨请附上来源链接，并标注大概的频率（常见 / 偶尔）。
- 有没有公开的技术说明、工程博客或泄露出来的系统提示词，能说明它实际是怎么实现的

## 闭源产品额外要查：实现线索（我之后要自己拆开研究原理）

对每个闭源产品，尽量找到：

- **本地客户端**：有没有桌面端、浏览器扩展、手机 App？用什么技术写的（Electron、Tauri、原生、Flutter、React Native……）？客户端里能不能看到记忆相关的逻辑，还是全在服务端？
- **别人已经做过的拆解**：逆向分析文章、抓包分析、客户端代码分析、泄露的系统提示词或内部文档（GitHub 上有专门收集系统提示词的仓库，也请查）
- **官方透露的实现**：工程博客、技术演讲、论文、专利、开发者文档、API 文档
- **间接线索**：招聘岗位描述里透露的技术栈、员工的公开分享、更新日志里关于记忆功能的变化

## 输出格式

1. 每个产品一节，按上面几项写，**每个事实附来源链接**；拿不准的请标"未证实"
2. 最后汇总一张表：**用户抱怨 Top 20**。列：抱怨内容、出现在哪些产品、频率、你认为的技术原因
3. 再列一份：**这些产品里值得借鉴的具体做法 Top 10**，每条说明它解决了什么问题
4. 一张**闭源产品拆解线索表**。列：产品、客户端形态和技术栈、记忆逻辑在客户端还是服务端、已有的拆解 / 泄露资料链接、你估计的拆解难度（低 / 中 / 高）、最值得先拆的原因。按"值得先拆"排序

请用中文回答。宁可少而准，不要编造；找不到就写"没找到"。

## 搜索要求（必须遵守）

不要只看官网、GitHub README 和大媒体。真实情况和用户抱怨大多散在各种论坛、社区和小平台上，这些地方是本次调研的重点。

**1. 必须覆盖的来源类型，每类至少尝试搜一次：**

- 中文社区：知乎、V2EX、贴吧、小红书、B 站（视频简介和评论区）、即刻、掘金、CSDN、博客园、少数派、NGA、微信公众号（可以用搜狗微信搜索）、魔搭社区、语雀和飞书的公开文档
- 英文社区：Reddit（r/LocalLLaMA、r/ClaudeAI、r/ChatGPT、r/OpenAI、r/singularity、r/replika、r/CharacterAI、r/SillyTavernAI、r/AI_Agents、r/ChatGPTPro 等）、Hacker News（包括评论区）、X/Twitter、Lobsters、dev.to、Medium、Substack、YouTube（视频和评论）、Product Hunt 评论
- 日韩：Qiita、Zenn、note.com、Naver
- 应用商店评论：App Store、Google Play，以及国内各大应用商店
- 开发者内部讨论：GitHub 的 **issues 和 discussions**（不是 README）、Hugging Face 的讨论区、各项目的 Discord 或论坛公开存档
- 学术：arXiv、OpenReview（包括审稿意见）、Semantic Scholar、Papers with Code

**2. 搜法：**

- **按问题搜，不只按名字搜**。例如"AI 记忆 混乱""AI 忘记 我说过""陪伴 AI 人设崩""ChatGPT memory wrong""companion app forgets""agent memory hallucinated memories"
- **多种语言都搜**：中文、英文，必要时日文
- **顺着链接再走两步**：看到一篇好帖子，就去翻它引用的链接和评论里提到的项目
- **不要只看大项目**：star 很少的小仓库、个人博客、一次性的实验报告都要看，经常能找到别人没注意的好办法
- **时间优先最近 12 个月**，更早的经典内容也可以收

**3. 进不去的地方如实说：**

需要登录、被屏蔽、打不开的平台，请在结尾单独列一份"没能访问的来源"清单，写明你本来想在那里找什么。我会自己去查。

**4. 每条信息都要附来源链接，并标注来源类型**（官方 / 社区 / 用户评论 / 论文 / 源码）。拿不准的标"未证实"。
