# 选型基准：不要靠 README 宣传决定重构

## 1. 统一回放材料（从 Atlas 自己的真实任务中构造）

第一批建议不高于 20 个可复查情景：

- 4 个跨会话回忆用户明确事实/偏好的问题；至少一例后来被纠正。
- 4 个多工具修复任务：目标→失败→改法→真实验证；要求能够说清某一步“未验证”。
- 3 个相似症状不同根因的问题：不能照抄上次的解法。
- 3 个项目状态演变：过期的分支/版本/决定要被新状态覆盖，但保留历史时间查询。
- 2 个子 Agent/设备切换：来源隔离、继承正确的任务上下文。
- 2 个负例：“数据库根本不存在的个人事实”不得编造。
- 2 个失效/遗忘/恢复例：忘记后在当前检索、摘要巩固、旧缓存中不可被自动复活。

原始日志应匿名化做成不可变评测副本，固定模型、温度、输入上下文预算与评分器，记录来源链接；不同候选不允许偷看目标答案。**不需要重构大型测试框架，直接复用常见 JSONL 回放脚本即可。**

## 2. 核心指标（每次方案比较都记录）

| 类别 | 要报告 | 除了分数还要看什么 |
|---|---|---|
| 召回 | recall@k、precision@k、错误召回率、拒答正确率 | 命中哪个证据、遗漏哪些、错误发生于提炼/索引/检索/融合哪一步 |
| 动态事实 | 更新命中率、时间正确率、被撤销事实再现率 | 世界有效期与系统获知期是否能区分 |
| 情景动作 | 任务成功率、有效步骤召回率、同错复发尝试次数 | 是否区分真正验收与工具返回 `ok` |
| 多 Agent | 跨任务延续率、越权读/写率 | worker 的猜测是否污染确认事实 |
| 成本 | p50/p95 检索延迟、首次索引秒数、每条写入 token、每轮注入 token、磁盘占用 | 同一次实验的硬件/模型版本 |
| 维持质量 | 原始内容遗失率、纠错后再污染、重复记忆率、无效巩固率 | 异常重启是否从检查点恢复且无重复消费 |
| Skill | 学到的 Skill 在留出任务中的效果、回归率和退役率 | 不能用生成的 SKILL 数量冒充收益 |

## 3. 结构化小对照：3 种架构 × 3 种检索

架构：A 文件+SQLite、B Postgres+pgvector、C 深改成熟库。如果某个体系无法在用户机器上装好，标安装代价，不硬凑分数。

检索 R0 关键词/FTS；R1 关键词 + 向量 + 元数据；R2 R1 + RRF + 按需图邻域/时间索引 + 有证据的 rerank。

对照原则：相同的写入证据和问题，不能只让高配方案拿多几倍提示词。记录前后端延迟与真实 API 消耗。先在几十个真实任务里筛最可能的，再跑公开数据集。**不应仅凭 LoCoMo 高分就宣称 Atlas 任务记忆好了。**

## 4. 外部数据集用途

- LoCoMo / LongMemEval：跨长对话事实与时间问答；工具行为覆盖有限。
- LongMemEval-V2（451 问）：web 环境状态、工作流、踩坑和前提意识，强烈推荐。
- AMA-Bench（ICML 2026）：state/action/observation/tool 的长期轨迹，推荐。
- MemoryAgentBench：事实合并、长程认知、更新、冲突。
- ForgetEval / AOEP：监督删除/纠错/作用域；分别核对代码和复现条件。

## 5. “反复造轮子”禁止事项

- 禁止在没有比较 benchmark/源码依赖前先创建新数据库和 N 个抽象管理器。
- 禁止重复部署独立的 memory 真源后宣称已经“融合”。
- 禁止把转译每个算法当成必要目标，许可允许时可直接复用稳定函数与包。
- 禁止把纸面方法名当作真实能力：必须可指出源码路径、输入输出、调用契约和至少一个对照样例。
- 禁止为了简单而无条件保持旧 Atlas 架构，也禁止因为先进就无条件引入重型图数据库。
