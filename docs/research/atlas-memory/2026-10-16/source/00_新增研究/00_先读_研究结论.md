# Atlas 原生记忆系统：研究纠偏与初步技术裁决（2026-10-16）

## 用户真实目标（不得误读）

研究所有值得研究的记忆系统的**构造方法与源码实现**，借用成熟代码/算法/模型/数据结构，把它们融合、改造成一套 **Atlas 自己的记忆系统**。不是给 Atlas 插几套独立的插件，也不是必须逐字将别人代码重写一遍。Atlas 还在开发期，旧版 Markdown、Git、SQLite、Python 模块划分、现有界面和运行时都不是预设不可改的硬约束。可以改存储、检索、写入、生命周期乃至 Agent 调度边界；但是必须比较好处和切换成本。

**本轮交付：** 公开材料与部分原仓源码复核、候选模块定位、三种底座架构对照、原生目标架构草图、基准评测和未决问题。**尚未在用户 Windows 环境下载/编译/运行候选系统，尚未复现实验指标，尚未修改 Atlas 仓库；不能说选型已经定案。**

## 纠正前几轮的偏移

- 原来反复强调“不碰 Markdown+Git+SQLite”缺乏比较依据；**停止把旧架构当作真理**。
- 原来建议仅 Python 重写大量代码，可能变成二次造轮子；**优先原代码复用、薄层封装，其次兼容性移植，最后才从算法重做**。
- 反过来，装一个完整 Hindsight/Graphiti/MemOS 服务后仍保留 Atlas 另一套主记忆后台，也是在叠加轮子。**原生化首先是统一语义、操作和生命周期，不是统一编程语言**。Electron 主进程承载 TS 算法、Python 后端承载 Python 算法并不丢人，但两者不能维护两份互相矛盾的事实。
- “记忆越多越好”“图谱一定比 Markdown 强”“SOTA 一定适合 Atlas”“每条对话都用 LLM 提取”等都是未经证实的假设。
- “长期记忆”不是“人的意识或 AGI”的充分条件；先以可度量的连续性、纠错和任务收益评估。

## 本轮最高价值的五项发现

1. **Hindsight 可直接借其检索融合模块**：`hindsight-api-slim/hindsight_api/engine/search/fusion.py` 有独立 `reciprocal_rank_fusion` 及 `cap_per_source`。MIT；这段比重写四路排序省时，推荐做检索试验的现成候选。源：https://github.com/vectorize-io/hindsight/blob/main/hindsight-api-slim/hindsight_api/engine/search/fusion.py
2. **Graphiti 适合研究双时间轴与矛盾更新**：`graphiti_core/edges.py` 记录 `valid_at/invalid_at/created_at/expired_at`；`utils/maintenance/edge_operations.py` 关闭旧边的有效期。不要预设必须引入 Neo4j 才能表达这四个字段。Apache-2.0。源：https://github.com/getzep/graphiti/blob/main/graphiti_core/edges.py
3. **ReMe 的巩固管线是现成的工程设计**：`dream/extract.py`→`integrate.py`→`finish.py`，保存处理状态，失败不冒充成功。源代码调用 AgentScope 的 `BaseStep`/file catalog，直接复制大类会拖进宿主依赖；可以使用现成实现作为参考，移植其稳定状态机与提示词。Apache-2.0。源：https://github.com/agentscope-ai/ReMe/tree/main/reme/steps/evolve/dream
4. **MemOS local-plugin 与主 MemOS 是不同层级对象**：local-plugin `core/retrieval/retrieve.ts` 有五个触发入口；`memory/l2/induce.ts` 和 `skill/eligibility.ts` 负责跨经历经验归纳与 Skill 晋升规则。插件 package.json 标 MIT、Node >=20，独立作为 Atlas Python 记忆核心可能拉入 Node/better-sqlite3/运行时组件。先利用其检索触发和策略算法，不要同时再起 MemOS 主记忆后端。源：https://github.com/MemTensor/MemOS/tree/main/apps/memos-local-plugin/core
5. **Atlas 现成 SkillOpt 不能忽略**：`core/atlas/evolution/skill_sleep.py` 已从 Hermes `state.db` 收会话并让 SkillOpt 候选技能通过 held-out gate，目标 `skills/learned/atlas-learned/SKILL.md`。需要核实脚本真的被调度、数据足够、负反馈是否准确、技能是否真的生效。**不应重新设计一套与它打架的 Skill 晋升器。**源：https://github.com/unicorn-Y/Atlas/blob/memory-v1/core/atlas/evolution/skill_sleep.py

## 实质性新纳入研究（较 10 月 14～15 日归档）

- **独立的广覆盖代码地图**：https://github.com/neoneye/agent-memory-atlas ，有锁 Git 版本的系统审计、21 种复用架构模式和验收案例；它是研究索引，不是裁决来源。仓库说明承认许多旧库的安全检查尚未完成。重点读 `content/patterns/index.md`、`content/benchmarks.md`。
- **EvolveMem**：不是仅更新记忆内容，而是诊断错误后调整召回配置，并在变差时回滚；`aiming-lab/SimpleMem/EvolveMem`。代码与论文： https://github.com/aiming-lab/SimpleMem/tree/main/EvolveMem 、https://arxiv.org/abs/2605.13941 。用途是后期离线检索参数优化，不应在线每轮自动改算法。
- **LongMemEval-V2**：451 道人工题，覆盖静态状态、动态状态、工作流、环境踩坑、前提意识，来源有多模态 web agent 轨迹；比只测闲聊更契合 Atlas。https://github.com/xiaowu0162/LongMemEval-V2
- **AMA-Bench**：真实和合成的状态-动作-观测-工具轨迹，针对长期行动记忆。ICML 2026：https://proceedings.mlr.press/v306/zhao26bs.html
- **Mastra Observational Memory**：Observer/Reflector 维护对话观察流；值得借用缓冲、压缩和避免自身状态回流。`packages/memory/src/processors/observational-memory/observational-memory.ts` 中明确规避“工作记忆状态回流导致自覆写”的已知问题；核心 Apache-2.0，`ee/` 则为非自由企业许可证。https://github.com/mastra-ai/mastra/blob/main/packages/memory/src/processors/observational-memory/observational-memory.ts
- **Claude-Mem**：从工具 hooks→持久入库→异步压缩→搜索、时间线→按需详情，有真实 coding agent 数据模型参考，不必复制它的独立服务。https://github.com/thedotmack/claude-mem/blob/main/docs/public/architecture/overview.mdx
- **MIRIX 版本分岔**：官方文档称 0.1.6 起主线不再是桌面个人助手，旧桌面 agent 在 `desktop-agent` 分支。研究摄屏流程时要锁对应版本，不能把旧宣传当当前主线实现。https://docs.mirix.io/getting-started/overview/
- **OpenViking**：L0 摘要、L1 概览、L2 详情特别适合大记忆逐级展开；官方 docs 说明 L0/L1 为目录级 sidecar，不是每个文件 3 副本。仓库 AGPLv3，**借思想不直接复制源码**，除非专门确认授权和许可证义务。https://docs.openviking.ai/zh/concepts/03-context-layers

## 初步设计立场（待用户决定重视点）

- 采用“**事实/状态/经历/知识/技能/承诺**是不同的记忆语义”而非一切都叫 fact；底层物理实现仍保持开放。
- 原始对话/工具/屏幕事件保存来源证据并有索引；提炼的信念是可更新、有溯源的**派生视图**；热点摘要/工作记忆是可丢弃缓存；Skill 是经过实际使用反馈的执行资产。
- 优先混合检索（关键词、语义、时间/元数据；关系扩展按需）＋场景触发，而不是全量送入上下文。
- 绝对不能让提炼后的摘要通过二次读入，冒充新的独立来源反复强化自己。
- 具体 DB 选型不在研究前锁死：SQLite/FTS5/vec、PostgreSQL/pgvector、文件+派生索引都应该拿同一批任务跑出结果才定。
