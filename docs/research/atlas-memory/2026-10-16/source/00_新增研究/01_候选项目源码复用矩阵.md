# 候选项目与可复用构件矩阵

证据等级：A = 此轮直接通过 GitHub 连接器读取文件内容；B = 官方仓库 / 文档核实机制但未深入单元调用链；C = 论文或第三方、尚未源码级审计。**“有代码可移植”≠已经完成适配或效果复现。** 许可只标当前核实的项目或子目录声明，复制任何文件时仍需固定 SHA 与许可证/NOTICE。

| 项目 / 入口 | 研究对象与源码落点 | 当前证据 | 复用模式 | 需要注意 | 初步优先级 |
|---|---|---|---|---|---|
| Hindsight (MIT) | `hindsight-api-slim/hindsight_api/engine/search/fusion.py`：RRF 和按检索路限额；retention / observations / mental models | A+B | **借用纯 Python 排序模块**，评估全文/BM25、dense、时间、关系通道 | 完整 Hindsight API/服务、模型依赖和独立 Memory Bank 并非必需 | P0 |
| ReMe (Apache-2.0) | `reme/steps/evolve/dream/{extract,integrate,finish}.py`；`auto_memory.py` | A+B | **借用增量检查点和处理状态机**，可复用提示词/规则 | 原类绑 AgentScope `BaseStep`，全量复制需大量依赖 | P0 |
| MemOS local-plugin (package MIT, 顶层 Apache-2.0) | `core/retrieval/{retrieve,ranker}.ts`、`memory/l2/induce.ts`、`skill/eligibility.ts` | A | **移植场景召回参数和策略证据门槛**，依赖无关的判断函数可以等价移植 | Node/better-sqlite3、TS 运行时，与整个 MemOS 不能混为一谈 | P0/P1 |
| Graphiti (Apache-2.0) | `graphiti_core/edges.py`、`utils/maintenance/edge_operations.py` | A | **复用双时间戳字段/矛盾关闭规则**，图存储可替换 | 如果直接上 Graphiti 核心会带图数据库驱动和抽取链路 | P1 |
| Mastra OM (核心 Apache-2.0, `ee/` 其他授权) | `packages/memory/src/processors/observational-memory/observational-memory.ts` | A+B | 借 **Observer/Reflector 压缩隔离、观察流与状态回流防护** | 大型 TypeScript 宿主，且部分 enterprise 目录不能直接复制 | P1 |
| Claude-Mem (Apache-2.0) | 官方 `docs/public/architecture/overview.mdx`，hook→DB→worker→search，三级 search/timeline/detail | B | 借 **编码 Agent 轨迹结构、渐进式细节展开、后台观测** | 它的完整 worker 服务未必比 Atlas 原生运行时简单 | P1 |
| A-MEM (MIT) | `agentic_memory/memory_system.py` `MemoryNote` 的 keywords、context、links、evolution_history | A | **移植记忆图链接/重组**，避免照搬 Chroma+各种 embedding 依赖 | 与双时间轴和证据边可能重叠，需要对比 | P1 |
| ReasoningBank (Apache-2.0) | `WebArena/induce_memory.py`、`prompts/memory_instruction.py` | A+B | 借 **成败经验提炼模板**、验证后再生成 playbook | 原工程部分是研究实验脚本，不能直接作为生产模块 | P1 |
| SimpleMem / EvolveMem | `simplemem/core/{memory_builder,hybrid_retriever}.py`、`EvolveMem/run_evolution.py` | B+C | **多视图编码、召回意图路由、离线自调优** | “lossless”“30x”来自作者/论文，需要针对中文实测 | P1/P2 |
| MemSkill (Apache-2.0) | 论文与开源实现；Controller/Executor/Designer | B+C | 学习 **怎么提炼记忆的元技能**，而不是工具操作 Skill | 作者明确说不是 procedural/experiential Skill，切勿重复造操作技能系统 | P2 |
| Hindsight 上层 Observations | 证据锚定的归纳观察、保留支持引用、可再更新 | B | **跨事实推理 / 反思视图** | reflect 模式多步 LLM，时延和成本不适合每轮 | P1 |
| Mem0 (Apache-2.0) | `mem0/memory/main.py` additive extraction、多信号检索与用户隔离 | A | 借 **候选事实批量抽取、身份作用域与过滤** | 旧版教程里的 graph/update 策略与新版 OSS 不一定相同；按当期 commit 分析 | P1 |
| MIRIX (Apache-2.0) | `mirix/services/episodic_memory_manager.py`、六类记忆、`desktop-agent` 分支 | A+B | **屏幕 / 语音活动归档、情景/过程/资源分流** | 高开销、多个 writer agent；主线与旧桌面版已分离 | P2 |
| OpenViking (AGPLv3) | `.abstract.md` L0、`.overview.md` L1、原始 L2，按需下钻 | B | **参考层级检索设计，不直接复制代码** | 高 copyleft / AGPL 合规；核心定位更偏“上下文数据库” | P2 |
| memU (Apache-2.0，见仓库声明) | `src/memu/app/service.py` `MemoryService`；wiki + 跨 agent | A+B | 研究 **跨设备目录 / scope / Wiki 导航** | 当前 `MemoryService` docstring 是 embedding-only；不要按旧介绍推断所有内核皆 LLM 提取 | P2 |
| Letta / Letta Code | `src/agent/prompts/letta.md`、工作记忆块与文件式自编辑 | B | 借 **自我编辑可见记忆块与变更记录** | 记忆自我编辑需要和用户修正权、确认策略对齐 | P2 |
| HippoRAG | PageRank/图多跳传播，实体与事实绑定 | B | 当相同实体的跨事件多跳明显输给向量检索再引入 | PageRank 图不是“类脑海马体”就一定高分；额外索引复杂度 | P2 |
| MemPalace | verbatim 原始保留与带作用域的结构化导航 | B | **保留原始证据、按人物/项目/事件索引** | 作者自己纠正“30x 无损”夸大；原文模式评分不代表算法普遍领先 | P2 |
| Honcho | `src/dialectic/` 用户推理、peer 差异化画像 | B | 研究多角度用户建模与回答前深度检索 | 推断不等于用户亲口确认的事实；自我画像不应抬高为用户事实 | P2 |
| LangMem | `create_memory_store_manager` 后台归纳、ReflectionExecutor | B | 参考 LLM 提炼的生命周期与异步调度 | 更偏 LangChain/LangGraph 整合，移植时可能依赖过重 | P2 |
| Cognee | `add/cognify/memify/recall` 的 ETL 与知识图加工 | B | 借图式知识整理与分批处理 | 多存储后端与复杂管线重于单机默认需求 | P2 |
| Supermemory | 用户/组织作用域、语义检索 | C | 对比跨设备用户画像与延迟 | 项目许可证/商业可用部分需重新锁版本核对 | P3 |
| Voyager/SkillOpt | 行动轨迹 + 测试后技能保存；Atlas 已有 SkillOpt 入口 | A(Atlas)+B | **优先把现有 SkillOpt 与真实任务证据对上** | 只看用户说“好了”不算可执行工具验证 | P1 |
| Memory-R1 (ACL 2026) | ADD / UPDATE / DELETE / NOOP Memory Manager，RL 优化 | C | 长期研究记忆策略学习 | 要训模型，和当前工程目标规模不符；非即插即用 | R&D |

## 核对中容易误导的数字

- OpenViking 自报 LoCoMo 80%+ 并不意味着在 Atlas 的中文/工具任务中达到该数字：https://www.openviking.ai/ 。
- MemPalace 的 96.6% 是某配置的 R@5（召回）而非跨任务成功率；其作者公开指出 AAAK 压缩为有损且指标更低：https://github.com/deco31416/mempalace 。
- Hindsight AMB https://agentmemorybenchmark.ai/ 包含不同模型/范围配置，数值不宜无控制横比。
- 第三方 OAMB 从准确率、上下文 token、索引 token、检索延迟、索引时间五维比较：https://github.com/rocke2020/open-agent-memory-benchmark ；这些结果也不能充当 Atlas 本机复现。
- Reddit 第三方自建对照“纯 Markdown Wiki 赢了 8 套”属于待复核的单一测试声明，显示**不要预设复杂性优势**，并不是全面性能定论：https://www.reddit.com/r/AI_Agents/comments/1veeix3/i_ran_8_ai_agent_memory_systems_through_2176/
