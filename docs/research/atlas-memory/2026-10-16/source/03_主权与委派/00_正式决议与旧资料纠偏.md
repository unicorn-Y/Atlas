# Atlas 记忆架构最终决议：唯一长期记忆主体，外部 Agent 默认充分执行权限

**决定日期：2026-10-16；决策来源：用户本轮明确确认；状态：已确定的产品要求，尚非已实施功能。** 这是当前研究总包的**最高优先级架构决议**。旧资料涉及与之矛盾的权限设计，以本文件为准。

## 1. 一句话定义

**Atlas 是唯一持续积累长期经历、事实、认知、技能的主体。Codex、Claude 等外部 Agent 是可更新、可替换的强力执行工具，通常具有完整开发与文件修改权限。** Atlas 会为任务自动准备相关记忆；外部 Agent 在执行途中可向 Atlas 追加查询，由 Atlas 找到资料并回复。任务执行证据回到 Atlas 后由其组织和提炼记忆。

**特别纠偏：长期记忆所有权 ≠ 进程文件权限 ≠ 任务工具权限。** 之前把「唯一记忆主体」解释成「外部 Agent 必须禁止读写记忆文件」是错误理解。用户不仅允许外部 Agent 开发、修改 Atlas，也允许其修改记忆系统相关代码、库结构、测试或数据迁移。不要新增为了防止这些操作而设置的隔离层和审批门。

## 2. 用户已确认的要求（决议优先级高于旧研究）

1. **唯一长期记忆主体：Atlas。** 外部 Agent 不需要共享长期人格画像或共同管理一套“多主脑”。其当前任务对话是临时执行状态。
2. **外部 Agent 是拥有充分权限的开发者/执行器。** 默认无需新增角色 ACL、项目读写白名单、token grant、短期凭证、过期/撤销/租约/审批等复杂权限基础设施；复用 Atlas 现有工具执行机制。
3. **初始记忆包 + 执行中主动补充。** Atlas 委派时提供任务当前状态、有关历史、关键约束、类似解决方案和已知失败；外部 Agent 缺资料时以普通工具请求通知 Atlas，Atlas 搜索并返回。
4. **信息供给的精选不是权限限制。** 不应无端把庞大历史一次塞入执行器上下文；节省 token、避免噪声才是主要理由。需要详细证据时允许展开原对话或本地直接查看。
5. **自动吸收经验，但不把自报成功等同于验证结果。** 保存原始事件/工具日志可自动进行；上升为长期事实或 Skill 时应记录出处、结果证据、是否验证。无需让用户逐项审批，也不需要对每个低风险事件做昂贵的验证。
6. **可重构 Atlas 现有存储与框架。** 用成熟项目的核心算法、数据结构和代码实现构建 Atlas 自己的记忆系统，不以 W0/W1/W2 的 Markdown/SQLite/现有 Python 层次为最佳架构预设。
7. **未来完整多模态统一设计，当前不实施视觉/语音/手机采集。** 聊天、任务、浏览器、电脑、手机、语音对应同一个事件本体；3060 6GB 笔记本作为未来感知端候选，能力待测。

## 3. 分清楚四种不同权利

| 事项 | 实际设计 |
|---|---|
| 修改 Atlas 代码和数据文件 | Codex/Claude 等执行器通常**可直接进行**；任务本身就是开发 Atlas |
| 使用上下文与查询历史 | Atlas 默认预装相关记忆，执行器还可向 Atlas 请求追加；不人为设安全禁区 |
| 记录外部执行过程 | Atlas 统一保存工具调用、执行日志、提交、文件差异、用户反馈等，并注明来源 |
| 谁拥有长期记忆与认知结构 | Atlas；外部模型不负责长期记忆的独立管理，取证和经验晋升采用 Atlas 的统一流程 |

换言之，外部执行器可以修改 `core/atlas/memory/`、数据库迁移或架构代码；这与 Atlas 在运行时保持**唯一统一的长期记忆体系**完全不冲突。

## 4. 对历史文档的逐项覆盖

- **作废**：之前 V3 草案的 `DelegationGrant`、短期 token、`allowed_project_ids`、`denied_sensitivity`、`expires_at`、`revoke_delegation`、`authenticate -> scope_filter -> redact` 必要路径及「外部 Agent 禁止查看全局事实/原文/编辑库文件」规定。
- **作废**：`02_本轮深挖/07_待用户确认事项.md` 里关于多 Agent 共同长记忆写权限的 A/B/C 选项；答案已明确，不要再重复询问。
- **保留**：`context bundle`、追加资料请求、任务结果回收、出处记录、变更历史、去重、冲突纠正、Skill 学习和多模态契约。
- **修订**：旧材料「外部 Agent 不得写记忆」应理解为**不让外部 Agent 直接输出的无证据推断无条件成为已验证事实**，不表示代码或数据文件不能改，也不表示必须设置强制写入隔离。
- **不新增**：安全堡垒、权限微服务、审批工作流、单独的外部 Agent 记忆数据库。

## 5. 实施纪律

**默认：速度优先，做功能而不是权限工程。** 最小闭环是 `prepare_context()` → 外部执行器 → 可选 `request_more()` → `collect_result()` → `record_episode()` → 增量提炼。保持工具适配器薄；只对会导致记忆重复、永久丢失或错误晋升的逻辑做小型定向回归。真正有分歧时再向用户询问，不为了常规可逆技术细节频繁中断。
