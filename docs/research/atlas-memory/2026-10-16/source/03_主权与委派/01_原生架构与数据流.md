# Atlas 原生单主体记忆系统：开放执行权限版架构与数据流

> **这是设计蓝图，不表示所有组件已实现。** 上层只有一个 Atlas 认知记忆系统；被调用的其他 Agent 是执行工具。模型供应商替换或版本升级不应改变 Atlas 已积累的长期记忆。

```text
用户 / 自动任务 / 未来视觉与语音事件
                  │
                  ▼
          Atlas Planner & Runtime
                  │
   ┌──────────────┼──────────────────────┐
   │              │                      │
   ▼              ▼                      ▼
 记忆引擎       执行调度                Atlas Skill 系统

 episodes       工作上下文               召回与反馈
 facts/edges    工具调用

   │                       ▼
   └─────────────▶ ContextBroker（薄逻辑组件）
                         │
             初始相关记忆与必要证据
```

## 1. 上下文供给而不是权限网关

ContextBroker 是 **Atlas 内部任务上下文编排函数**，不要把它做成外部插件、独立数据库、权限中心或复杂网络服务。

外部任务正常采用：

1. `prepare_context(task, worker)`：Atlas 检索当前项目状态、用户最新指令、相关决策、已验证失败经验及出处，提供精简而足够的信息。将整库一次塞入模型通常造成成本和干扰；这是上下文质量问题，不是拒绝访问。
2. `worker.run(task, context)`：Codex/Claude 正常在 Atlas 工作区全权限开发、读文件、执行命令、改项目代码。可以修改记忆系统源码和迁移数据。
3. `request_more(query, why)`：工作过程中外部执行器通过消息、工具调用或已有会话通道向 Atlas 提问；Atlas 选取信息并返回。根据执行器需要可返回摘要、原文定位、代码路径、已有测试结论或多条证据，不再人为设置读取禁区。
4. `collect_result()`：Atlas 收集执行摘要、实际 diff/commit、运行日志、测试和后续待办；不需要因为所有工具都成功就先等一次“记忆审批”。
5. `record_episode()`：保存过程、来源和实际结果；可在后台抽取事实及经验；证据不足的结论标为「暂未核实」而不是强行当作事实。

## 2. 干活和记忆主体分开

- **任务执行层**：可由不同提供商的 Agent 进行，权限按用户原有 FULL_ACCESS 工作方式配置，**不新增限制**。
- **认知层**：事实、经历、项目状态、偏好、技能及使用反馈统一存于 Atlas 管理的记忆体系。Codex/Claude 不需要另外维护永续长记忆副本。
- **证据层**：记下 `task_id`、`source_agent`、`model_version`（如果可得）、`session_ref`、`artifact_ref`、`time`、`result_observed`。这些字段只是用于追溯和去重，不是授权凭证。
- **未来感知层**：截图、手机 UI 事件、音频片段使用同一事件结构，但此阶段只保留结构约定，不启用持续采集。

## 3. 外部 Agent 请求更多记忆时

最少输入：当前任务 ID、问题、缺少什么。最少返回：相关记忆/证据、必要原文指针、当前是否可靠。无需 `DelegationGrant`、令牌续租、单项授权、作用域 ACL。

Atlas 对追加请求可选择：`found / not_found / need_original`；检索时优先关联同一项目，但外部 Agent 明确需要其他项目案例或原始历史时可以继续查，不按人工白名单阻挡。

为了避免重复浪费 token，附上已给过的 `memory_ids` 或 `context_revision` 即可。这是缓存与去重信息，不是权限控制。

## 4. 经验归档的低成本真实性规则

- 原始操作、执行日志、工具失败、文件 diff：可直接保存为**观察事件**。
- 外部模型说“测试通过”：记为**执行器陈述**；有退出码/测试日志再加上 `verified_by=tool_output`。Atlas 不必人工逐条审查。
- 外部模型推断的用户偏好或长期事实：保留证据关联、冲突标识，避免让二手总结盖过用户明确指令。
- “失败的方案”可写入反例记忆，不自动归纳为永久性禁忌；环境更新后允许复测。
- Skill 优先复用现有 `skill_sleep.py`/SkillOpt；候选流程需要经过可观察的实际执行和评价，而不是只凭大模型自述。

## 5. 可变的技术底座

本版**不冻结**数据库选择。Markdown/SQLite 可以先用，但要对比结构化事件库、时间关系检索、向量/FTS 融合、检索阶段推理、增量巩固等方案的真实收益，必要时替换旧框架。避免「为了迁移方便」放弃明显更优的机制；也避免没有真实收益就引入多个数据库和服务。

## 6. 未来多模态（研究保留、实施暂缓）

未来 `ObservationEvent` 有稳定的 `event_id, observed_at, device_id, modality, task/session linkage, evidence_ref` 等字段，可以把图像/语音/手机经历与任务历史关联。笔记本 3060 6GB 只作为未来计算节点候选，不强行规定它必须做 ASR/VLM 或数据库。当前不实施视觉音频采集、不启动后台录屏。
