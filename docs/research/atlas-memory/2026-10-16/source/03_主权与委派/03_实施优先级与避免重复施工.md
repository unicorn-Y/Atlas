## 优先的四件事

1. **委派信息包**：在 Atlas 现有调用外部 Agent 的位置增加 `prepare_context()`，前置拼接任务 + 历史 + 已验证经验；外部 Agent 保持现有 FULL_ACCESS。不需分拆新的记忆服务。
2. **追加补充**：现有工具/消息通道加 `request_more(query)` 语义；先支持全文检索、最近任务原文定位；不做权限网关。
3. **统一回收事件**：从外部执行器原有工具日志、进程结果、commit 和文件 diff 生成任务 Episode；即便 worker 本身不运行 Atlas `_schedule_library_write()`，也可以在委派结束由主 Atlas 统一接收。别给每个执行器单独记忆库。
4. **逐步提升召回与总结质量**：针对错误历史检索、全局 checkpoint 漏处理、检索结果混杂、错误 Skill 晋升，用 ReMe/MIRIX/Hindsight/AMA-Agent/Graphiti/MemOS 成熟代码与思路补足；只做必要的实测对照。

## 后续不立刻施工

- 图像/音频/手机采集与实时 VLM/ASR 服务。现在只维护事件 schema 与时间线关联能力。
- 「第三方插件化长记忆总线」、多 agent 权限系统、分布式记忆主从同步和每工具审批 UI。
- 过量工程：为一个简单函数铺几层 service/repository/facade/permission class、先写大而全治理规则再干活。

## 最小质量底线 ≠ 权限限制

必须有：原始证据可回溯、去重幂等、时间和状态真实、补写失败可恢复、避免一次模型瞎猜污染用户事实。这些是任何成熟长期记忆的正确性要求，不需要额外限制 Codex 对 `D:/Atlas` 的代码访问。

## 研究证据状态

已核对源码路径与独立分支提交；**尚未**在用户运行主机上实施、跑跨模型连续委派真实测评，W2-A 性能数据包括合成向量而非真实 embedding 模型延迟。建议后续使用少量真实任务验证后，再决定替换/移植哪一部分代码。
