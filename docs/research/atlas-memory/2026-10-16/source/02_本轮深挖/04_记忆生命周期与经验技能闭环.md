# Atlas Memory Lifecycle：一套记忆系统，不是三个助手和十套库

## 1. 采集与写入：先保存事件，再决定什么值得记

**正确顺序（建议）：**

```text
Atlas / Codex / Claude / tool / device
  → EventEnvelope.normalize + scope check
  → 事件 ledger 持久保存（或引用现有原始 session，避免双写）
  → 异步 processing queue（可重试、可追踪、按 event_id 幂等）
  → Episode segmenter（目标/窗口/工具/时间/状态切换）
  → Extract：事实候选 + 任务经历 + 错误教训 + 未完成项
  → ClaimGateway：合法作用域、来源独立性、矛盾/更正/时效处理
  → materialized memory views + search indexes
```

用户消息与工具事件首先有稳定身份，提炼失败应留下待办而不是导致原始证据消失。现有 Atlas 有日志/session 和 W0 durable queue，要优先复用并扩展事件类型，不新建第二个聊天存储库。对于主机以外设备，采用同步时传稳定事件 ID、幂等 upsert；延迟到达的事件不得因为“昨天已经 dream 过”而漏处理。

### 防止自回流/虚假多源佐证

- User said、tool observed、page extracted、LLM inferred、memory retrieved 五个 origin type 不得混写。
- 同一个原文被 3 个摘要 Agent 重复提炼，只算 1 个独立源，必须留 `derived_from` 关系。
- 用 `epistemic_status` 记录“候选/支持/反驳/撤销/过期”，不只 `confidence=0.93`。
- 记忆检索返回一条旧建议，不能被随后的总结识别为用户新决定。
- 面向项目配置/软件版本：区分环境 snapshot 与长期稳定偏好，状态变化要主动使旧结论过期或 supersede。

## 2. 情景记忆（Episode）：重点是“行动为何发生、后果怎样”

Episode 不应被固定为“每个会话每天一条”。合适的边界：目标改变、工作空间切换、明显空闲后恢复、新的长子任务、一次问题尝试的开始/成功/失败。支持 episode 之间 `CONTINUES`、`BLOCKED_BY`、`SUPERSEDES` 等关系，日/周总结只是对此的**派生视图**。

示例：某配置报错：

- `goal`: 让 Atlas 启动；`environment`: Windows + 具体仓库和 commit。
- `attempts`: 先改 A，失败→回滚→改 B，测试通过。
- `observations`: 错误日志、工具退出状态、文件差异、测试报告位置。
- `outcome`: 测试通过 vs 用户确认使用正常（两个独立结果）。
- `lesson`: 仅在版本和环境条件匹配时推荐 B，不能永久宣称“A 没用”。
- `verification`: `test_id`、命令、期望、实际、时间、来源，不仅 `verified=true`。

## 3. 检索：把推理中的“什么时候想起”纳入运行时

**检索触发器**（来自 MemOS 五入口设计、结合 Atlas 实际任务）：

| 场景 | 优先拿什么 | 延迟/预算策略 |
|---|---|---|
| 对话/任务开始 | 近期项目状态、显式用户偏好、关键决定 | 小块注入，不要全部常驻 |
| 启动子任务/worker | workspace 相关目标、版本、近似解决方案 | 精确 scope，返回依据而非整库 |
| 工具连续出错 | 错误签名、过去同类失败和有效解法、反例 | 触发式，数量限制，不要无限循环检索 |
| 调用已学 Skill 前 | Skill 版本、前置条件、过去验证和已知不适用例 | 只拿相关几条 |
| 执行高风险决策前 | 最近决定、未完成约束、当前状态 | 要求来源/时效足够清楚；必要时问用户 |
| 回忆“为什么/哪一步” | 事件链、相邻工具日志和有争议的原因 | AMA-Agent 式证据充分性评估，按需向原始轨迹下钻 |
| 任务完成后 | 本次用过的记忆和真正验证结果 | 写 MemoryUseTrace，不把“模型说完成”当成功 |

**算法候选**：Atlas W2 native normalized weighted scoring+MMR vs Hindsight `reciprocal_rank_fusion`；初始候选包含词法精确、语义、时间/状态/项目 metadata，关系展开只对多跳问题激活。安全/过期/权限过滤必须在候选返回模型前强制执行。对符号、文件路径、错误码、版本号优先 lexical/exact ；对概念和同义表达才激活 embedding。若候选证据不足，返回“未知”或继续查证，不要自动编故事。

## 4. 巩固：增量、重算、纠错、冷却，而不是覆盖旧页面

建议从 ReMe 的 `DreamState` 与 MIRIX 的 auto_dream 边界控制吸收：

- **Observation → Episode**：按 task/run 聚合，仅处理有新事件 ID 的片段；发生时间和入库时间同时参与增量。
- **Episode → Claim**：每条 candidate 均有 `CREATE / CORROBORATE / REFINE / CORRECT / DISCARD`，来源明细；“CORRECT”不能丢掉之前错误曾存在的事实。
- **Claim → Project Snapshot**：面向项目的当前状态由 claims 查询生成；旧 Markdown 可作编辑视图，但不依赖 LLM 完整重写保存真相。
- **多经历 → Policy**：至少跨独立成功/失败场景支持，并保存反例与适用条件；不能一场失败就归纳“永远别这样做”。
- **Policy → Skill Candidate**：交给现有 SkillOpt 的 replay + held-out gate。最终是否能在 Atlas runtime 触发还要单独验证。

持久状态粒度最少要支持 `(source_id, processing_kind, extractor_version, state, retry_count, last_error, processed_at)`；任务崩溃后按同一事件 ID 重试；旧版本提炼可重算，而不重播已经删除/已撤回的用户数据。检查点按来源和工作项推进，不因为“本次没有满足 3 天条件的分组”就永久放弃来源事件。

## 5. 跨设备/多 Agent：读与写不对称

建议当前默认：**项目经历与参考知识可被共享给已授权 Agent；事实更新必须有来源署名、scope、写入冲突解决；模型推断不能覆盖用户确认事实**。至于 Codex/Claude 是否可直接写入全局用户画像，需要用户拍板，不能偷换为“所有 Agent 自动拥有同一全局事实写权限”。

- `workspace/project` 与 `user-private` 不同作用域；一个应用窗口看到的密码不能因“用户在电脑上操作”自动广播给所有 worker。
- 延迟同步时 `received_at` 不等于 `occurred_at`；按因果/来源决定冲突，不靠最后写入者自动胜出所有事实。
- 删除/更正一条事实后，其他设备的派生缓存/embedding/Skill 索引必须收到 tombstone 或失效消息，避免断线重连复活旧记忆。
- 类脑比喻：海马体式事件→新皮层式抽象可以借鉴，但不能把医学术语冒充已验证的算法设计。

## 6. Skill 学习：必须有强证据门槛

Atlas 已有 `evolution/skill_sleep.py`，它从 Hermes 会话 harvest、重放候选技能，在 held-out 评估比旧版好的情况下 adopt。现在缺的是证据的质量、可执行性、Skill 使用 trace。形成完整闭环：

```text
Episode success/failure
→ Policy candidate (ReasoningBank, MemOS L2)
→ 独立 episode 支持数 / 适用条件 / 反例
→ Eligibility (MemOS)
→ SkillOpt replay+held-out gate
→ 可执行 SKILL.md 版本注册 + 召回/技能触发
→ 真实任务结果、失败和回退
→ 更新候选/降级/退役
```

**三个反例必须过**：同一会话重复说三次不算三个支持；工具输出 0 不代表功能验收通过；两个版本的相似故障可能原因完全不同，旧 Skill 不可自动强行执行。

## 7. “未来感知端”架构只设计不施工

```text
主机 Atlas core ─── authoritative events/claims/episodes/skills
   ↑ ↓
   可选异机感知 Worker（3060 6GB 仅为未来候选）
   屏幕/UIA/视觉、Android、VAD/ASR/音频、视频片段
   → 按范围过滤/脱敏/压缩→ signed ObservationEnvelope
```

无论未来使用哪种 VLM/ASR，**新的认知 claim 必须从新的观察事件产生**，不得直接让远端模型未经作用域校验修改用户长期事实。这是统一系统的关键：不限制未来模型，限制的是记忆的真实性和来源。
