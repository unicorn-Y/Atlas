# 视觉、语音、手机：完整规划，但暂停实施

用户明确要求：这部分必须写进 Atlas 长期记忆目标架构；不准从研究资料里删掉，也**不准现在去做音视频采集/模型部署**。已有一台 RTX 3060 6GB 笔记本作为未来感知资源候选，尚未确认长期运行角色。

## 1. 哪些决定现在必须确定

- `ObservationEvent` 必须能容纳文本/结构化交互/媒体引用/空间或时间范围，不将一切硬塞入 `user_text`。
- 跨设备唯一来源身份、设备时间与入库时间、原始证据可追溯、来源权限/删除传播在 v0.1 定义。
- 抽象划分“感知事件”和“从感知推断的用户事实”：屏幕上出现网页 ≠ 用户认可页面观点；识别到说话者 ≠ 说话者的每句话是用户指令。
- Agent 之间共享项目时间线，但来源权限不应默认等同为可写用户画像。
- 模型版本/提示词版本需随派生标记，未来换更强 VLM/ASR 可以重算观察，不覆盖不可逆的原始证据 ID。

## 2. 未来屏幕/浏览器感知研究矩阵（不施工）

| 研究 | 现有可参考思路 | 约束 |
|---|---|---|
| 屏幕可读结构 | Windows UIA accessibility tree、CDP/DOM、OCR、截图 | UIA/DOM 是结构信号，不可冒充像素级全视觉理解 |
| 截图键帧 | Screenpipe paired_capture 的 tree+frame，同步时间戳 | 现行源码非标准开源许可；只分析设计 |
| 活动切段 | focus、tab navigation、用户动作、时间变化去重 | 不应“每秒一截图 = 每秒一长期记忆” |
| 视觉理解 | Qwen3-VL-Embedding/Reranker；各种 VLM 事件识别 | 未来在 6GB 笔记本上部署哪一型号需单独实测 |
| 浏览器学习 | URL/页面版本/DOM/工具动作，网站 workflow 及坑点 | 浏览过的广告不能升级成用户偏好 |
| 隐私控制 | App/窗口 exclusion、暂停/透明指示、凭据和消息屏蔽 | 不能做成默认泄露账号凭据的历史记录器 |

## 3. 未来音频/语音研究矩阵（不施工）

| 环节 | 需要记录的结构 | 关键失真点 |
|---|---|---|
| 音频事件 | `audio.segment`、device/source、起止时码、媒体指针 | 环境回声、麦克风泄露、第三方声音 |
| 转写 | ASR partial/final、置信线索、音频 offset、语言 | partial 反复更正，不能将每个 partial 当新独立事实 |
| 说话者分离 | speaker_id(可能未知)、转写 span 与说话者的关系 | 不能凭声音似乎熟悉就确认是用户 |
| 对话意图 | 谁要求什么、是否是引用、是否达成决策 | 提问/假设/讽刺不算确认事实 |
| 情绪/习惯 | 模型推断仅作为低权候选 | 不可将感知推断直接写成稳定人格画像 |
| 事件融合 | 与当前 PC/手机/聊天任务 ID 对应 | 跨设备时钟误差、不同会话源合并 |

用户过去已经研究过实时语音系统；未来与感知端整合时不该把 TTS/ASR runtime 与 memory store 混成一个服务。记忆系统接收结构化事件，语音对话的低延迟控制权留在语音引擎。

## 4. 未来 Android/手机的规划（不施工）

- 事件来源可能为 Android accessibility、应用前后台、通知、页面导航、用户触发动作、经过同意的媒体引用；计划使用 rooted Android 不代表技术上或伦理上应绕过所有应用限制。
- 需要离线缓冲、设备 ID、防重传、断线重连、准确时间、数据敏感级、同步删除。系统权限越高，越需要严格的本地过滤和访问边界。
- 手机浏览/私信的数据不能默认为 Atlas 永久存档；用户最终选择的采集策略将在未来产品设置中落实。

## 5. 两机分工候选，不当作已验证结果

- 主机：Atlas 对话/Agent runtime、原生 memory、检索/事实修正/Skill 生命周期。
- 笔记本：未来视觉/语音预处理队列、可选轻量 embedding/ASR/VLM；具体模型能否塞进 3060 6GB、Windows 运行、吞吐和温度功耗均未实测。
- 通过带身份/权限标记的 `ObservationEvent` 传结构化输出和媒体引用；不要将未经验证的推断直接远程写入全局用户事实。

**当前实施明确不包括**：后台摄屏、录音服务、Android root 管理、长期驻留 VLM、音频转写 pipeline、远程设备采集安装程序。当前允许做的是 schema/mock 事件验证。
