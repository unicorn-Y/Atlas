# 源码复用与算法吸收：以机制为单位，而不是以项目为单位

**标注约定**：A级=本轮读取了原项目源码；B级=官方代码/文档机制核实，但未通读运行链；C级=论文或第三方线索。A 级**不是**已经跑过测试、可直接 copy/paste、更不是在 Atlas 上效果最好。

## 一、记忆采集/事件归档：Claude-Mem、MIRIX、Screenpipe

### Claude-Mem（B）
`https://github.com/thedotmack/claude-mem/blob/main/docs/public/architecture/overview.mdx`

- 生命周期 hooks 捕捉用户消息/工具使用/结束事件，后台 worker 提炼成 observation；SQLite FTS 存储，search→timeline→detail 逐级检索。
- **可直接吸收**：事件驱动捕获的接口约定、渐进细节展开、工具观察标题/类别/来源/估计 token 预算；不需要复制整个独立 HTTP worker。
- **Atlas 现状**：W2 已实现 `/open` 与 UI 来源抽屉；可借该思路优化检索策略，而非再建第二套 timeline。
- **仍需确认**：上述文档不同版本存在 skill/MCP 混用；固定当前 commit 的实际 API/实现再复用。避免直接依据过期架构文档施工。

### MIRIX（A）
`https://github.com/Mirix-AI/MIRIX/blob/main/mirix/services/auto_dream_manager.py`
`https://github.com/Mirix-AI/MIRIX/blob/main/mirix/services/episodic_memory_manager.py`

- 提供 core / episodic / semantic / procedural / resource / knowledge-vault 等差异化记忆语义；本轮源码验证 `AutoDreamManager` 的窗口整理、每个 owner 互斥锁，procedural 模式按“sealed sessions → distill → mark processed”防重复。
- **该研究的真正可用处**：六类语义分类 + procedural 记忆来源处理 + 整理幂等/跨进程锁。可以把“异步梦境巩固”“Skill学习”放在同一调度体系里，但区分两个不同的结果类型。
- **不建议**现在搬整个 MIRIX 服务栈或截图采集/上载模块；后续研究桌面多模态时区分它旧 `desktop-agent` 与主线职责。

### Screenpipe（A 代码结构 / B 采集能力；商业许可）
`https://github.com/screenpipe/screenpipe/blob/main/crates/screenpipe-capture/src/lib.rs`
`https://github.com/screenpipe/screenpipe/blob/main/LICENSE.md`

- 现行 `screenpipe-capture` 代码明确分离调用触发器与 `paired_capture`（accessibility tree + JPEG frame）落盘，证明“同一帧既保留结构化 UI，也有视觉证据”是成熟可参考的设计。
- **吸收设计**：事件触发、UIA/OCR/图像三种证据关联、截图变化去重、媒体异步分析、保留精确窗体/应用时间。
- **许可证提醒**：2026-06-09 之后主仓为 Screenpipe Commercial License，源码可见但不等于通用开源可复制；将来如复制代码需专门合规审查，或选许可合适的其他来源。
- **本阶段仅研究，不实施**。

## 二、写入与巩固：ReMe、Mastra OM、MIRIX

### ReMe（A；Apache-2.0）
`https://github.com/agentscope-ai/ReMe/blob/main/reme/schema/dream.py`
`https://github.com/agentscope-ai/ReMe/tree/main/reme/steps/evolve/dream`

- `DreamUnit`: name / bucket / summary / paths；`IntegrateOutcome.action` 明确为 CREATE/CORROBORATE/REFINE/CORRECT；`DreamState` 有 changed_paths、failed_paths、checkpoint_paths、units、warnings/errors。
- **可复用到 Atlas 的核心**：按增量证据执行提炼，归入“新记忆/补充证据/改写/更正”操作，只有成功时推进对应 checkpoint。源文件身份与去重是持久状态而非一次调用中的局部变量。
- **避免**复制对 `BaseStep`/FileCatalog 宿主框架强耦合的大类；可保留 schema/prompt/test 作为内核契约，再利用 Atlas 本身的运行时实现事务。如果上游原代码小模块适合直接引入，优先原样引入并保留 license 说明。
- **针对 W2 的价值**：修 `dream.py` 可能漏处理的 group 后续重新考虑，以及重复梦境导致重写派生页面的问题。

### Mastra Observational Memory（A；需分模块复核许可）
`https://github.com/mastra-ai/mastra/blob/main/packages/memory/src/processors/observational-memory/observational-memory.ts`

- Observer/Reflector 的目标是把长上下文提炼为持续观察流。`isWorkingMemoryStateSignal` 明确过滤它自己维护的工作记忆信号，避免“观察输出 → 再作为新输入 → 污染自己”。
- **可吸收**：来源类型与“是否模型生成”标签、buffer 中间层、可重建 summary、活跃/长周期窗口分离、反思不冒充原始事件。
- **不应该**直接把观察内容视作 `MemoryClaim=verified`；需要单独的 claim gateway 和权限状态。

## 三、事实更新/关系/时间：Graphiti、Hindsight、A-MEM

### Graphiti（A；Apache-2.0）
`https://github.com/getzep/graphiti/blob/main/graphiti_core/edges.py`
`https://github.com/getzep/graphiti/blob/main/graphiti_core/utils/maintenance/edge_operations.py`

- 事实关系边同时记录 `valid_at/invalid_at`（世界有效时间）和 `created_at/expired_at`（系统获得与失效记录时间）；旧边会通过显式的 contradiction 处理失效，但仍能做历史查证。
- **可吸收**：实体/事件来源 ID、双时间模型、矛盾关系关闭逻辑、依据多个 episode 产生的边关系。可先用 SQLite/Postgres 关系表实现；**要证明跨任务多跳收益后**再考虑专用图索引。
- **注意**：“先发生 A 再发生 B”不等于“由 A 导致 B”；因果边必须受工具依赖与前后状态验证。

### Hindsight（A；MIT）
`https://github.com/vectorize-io/hindsight/blob/main/hindsight-api-slim/hindsight_api/engine/search/fusion.py`

- `cap_per_source()` 保证向量/关键词/图/时间各通道在融合前有相对公平的候选上限；`reciprocal_rank_fusion()` 汇合跨索引排序并带每通道排名元数据。
- **可复用**：Python 小函数比重写 RRF 更好，适合与 Atlas W2 的 `merge_scores()` 做同输入 A/B 对照；若可用直接保留文件和 MIT 版权声明。
- **限制**：不是仅加入 RRF 就得到 Hindsight 全部 mental models/reflect 能力；多检索通道的候选质量仍是基础。

### A-MEM（A；MIT）
`https://github.com/WujiangXu/A-mem-sys/blob/main/agentic_memory/memory_system.py`

- `MemoryNote` 具有 keywords、context、links、evolution_history、last_accessed。可借**记忆主动建立链接与更新已有节点**的思路。
- **不应全抄**其 Chroma、SentenceTransformers、Transformers 等复杂依赖链；关系表与来源指针未必需要同样物理栈。

## 四、执行中想起、因果追查、Skill

### MemOS local-plugin（A，package 声明 MIT）
`https://github.com/MemTensor/MemOS/blob/main/apps/memos-local-plugin/core/retrieval/retrieve.ts`
`https://github.com/MemTensor/MemOS/blob/main/apps/memos-local-plugin/core/skill/eligibility.ts`

- 多种召回入口：`turnStartRetrieve`、`toolDrivenRetrieve`、`skillInvokeRetrieve`、`subAgentRetrieve`、`repairRetrieve`，根据正在做什么选择要取什么层、多少条。
- Skill eligibility 要求 active policy、足够实际增益、不同 episode 的支持、失败教训至少有成功锚点、旧版本需更新才能重建。
- **可吸收**：可移植 TS 函数、条件判定和测试用例（不必重造一整套内核）；将触发点接回 Atlas runtime，避免只做新的 memory_search 工具。
- **与 Atlas SkillOpt 的关系**：SkillOpt 负责已有候选技能 replay/gate/adopt；MemOS eligibility 适合做进入候选池前的证据门槛。不要并行写两个最终“发布 Skill”系统。

### ReasoningBank（A；Apache-2.0）
`https://github.com/google-research/reasoning-bank/blob/main/WebArena/induce_memory.py`

- 研究脚本可借成功/失败轨迹→策略表达和正/反例聚合；这是经验提炼上游而不是最终 Skill 注册表。
- 研究用途的 pickle/实验脚本和提示词可复用思想，但不应直接作为 Atlas 后台服务。

### AMA-Agent（**本轮新增 A**；所在仓库 MIT，复制具体代码仍保留声明）
`https://github.com/AMA-Bench/AMA-Bench/blob/main/src/method/ama_agent_core/construct.py`
`https://github.com/AMA-Bench/AMA-Bench/blob/main/src/method/ama_agent_core/retrieve.py`

- 构造：保留原始 trajectory，形成 LLM 压缩状态摘要 `state_mem`，按需生成 `causal_graph` 和逐轮 embedding。
- 召回：向量/词法拿 seed steps，然后 LLM 判断是否 `SUFFICIENT`，否则分流 `NEED_GRAPH`（补邻居/区间/指定步骤）或 `NEED_CODE`（程序化精确搜索），最后组装证据。
- **特别值得移植**：证据充分性判断 + 根据问题逐步扩大时间邻域；当 Atlas 回忆“某行配置为什么改”时，先确定有无足够引用，不足就继续追溯，不要只输出一个相似摘要。
- **风险**：其 `NEED_CODE` 分支会生成并执行搜索脚本，必须在只读、资源受限、可审计的环境下使用；低延迟日常场景不应每次触发高成本 LLM 检查。论文精度是作者 benchmark 环境指标，非 Atlas 实测。

### LongMemEval-V2 AgentRunbook-C V2（**本轮新增 A**）
`https://github.com/xiaowu0162/LongMemEval-V2/blob/main/memory_modules/agentrunbook_c_v2.py`

- 已有结构化 `LEARNED_RETRIEVAL_STRATEGY.md`；当前任务不能拿历史 `directly_supported` 结论当新任务的证据，必须重新检查当前来源。
- **可吸收**：记住“找答案更有效的路径”，但将其作为检索策略线索而非事实；区分 `directly_supported`、`contradicts_premise`、`near_match_only`、`insufficient`。
- **意义**：给 Atlas 提供元记忆演化的方向，不等于自修复代码的 Skill。

## 五、未来多模态但暂缓实施

### MIRIX 的桌面采集
旧版桌面行为与当前主线已分岔，不应直接推断 2026 主线代码功能。设计最有价值的是六类记忆路由、多模态来源时间和异步 image upload / archive 的契约；未来实施前锁具体版本。

### Qwen3-VL-Embedding（官方 Apache-2.0）
`https://github.com/QwenLM/Qwen3-VL-Embedding`

- 官方说明统一文本、图像、截图、视频和混合模态 embedding/reranker。未来用“视觉查询找截图/视频片段”很合适；但 **3060 6GB** 是否能在目标延迟和并发下运行具体型号、是否需要量化/卸载，尚未评估。
- 只是模型研究候选，**不在当前路线安装**。

### OpenViking（AGPLv3）
`https://github.com/volcengine/OpenViking`

- 借其分层 L0/L1/L2 语义导航、虚拟路径、按需读取思想。当前主仓许可证是 AGPLv3；除非明确接受和履行相应条件，不直接复制其核心代码。

## 六、总体对比和现实约束

| 能力 | 主对照方案 | 优先吸收方向 | 是否现在实现 |
|---|---|---|---|
| 消息/工具原始采集 | Atlas existing vs Claude-Mem | 事件原生入口、稳定引用、低干扰写入 | 是 |
| 跨任务活动与经历 | Atlas W2 vs AMA-Agent vs MIRIX | 目标-操作-观察-结果；时间/来源链 | 是 |
| 巩固与更新 | W2 Dream vs ReMe vs MIRIX auto_dream | 增量分组、幂等 checkpoints、结构化更正 | 是 |
| 事实纠错和知识关系 | Graphiti vs Hindsight vs A-MEM | 双时间 + 证据 + 适度图邻域 | 是 |
| 检索 | Atlas W2 hybrid vs Hindsight RRF | 直接 A/B 对照，保留胜出者 | 是 |
| 执行中召回 | MemOS 五入口 vs Atlas W2 pre-turn | 运行时触发策略、场景预算、负例 | 是 |
| 深入调查证明 | AMA-Agent sufficiency vs 仅 top-k | 按需追查原始时间线 | 是（先小样本） |
| Skill 晋升 | Atlas SkillOpt + MemOS eligibility + ReasoningBank | 一套候选池与验证/回滚 | 是 |
| 跨设备 | 统一事件协议 + 设备同步队列 | 可离线、去重、scope 强制 | 契约现在；手机采集以后 |
| 电脑视觉/音频 | Screenpipe/MIRIX/OpenViking/Qwen3-VL | 采集-处理-认知解耦、媒体引用 | **只规划** |

**不推荐**把全部项目装成常驻服务叠加；也不推荐只为了获得单个纯函数就重写几千行旧代码或给 Atlas 加三个新数据库。
