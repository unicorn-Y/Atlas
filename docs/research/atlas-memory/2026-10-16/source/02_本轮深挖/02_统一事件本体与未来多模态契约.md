# Atlas 原生认知记忆：统一事件本体 v0.1（架构草案）

**阶段分离**：本文件对“聊天/任务/电脑/浏览器/手机/音频/视觉”的长期数据语义一次性规划；近期实施仅对聊天、任务、现有工具事件接入。**暂不开发屏幕、手机、语音的实际采集器或推理模型**。

## 1. 非功能口号，必须满足的契约

- 同一真实任务可跨 Claude/Codex/Atlas、电脑/手机形成统一 `task_id`，但允许不同设备离线、事件延迟。
- 原始观察可追溯、摘要可以重算；派生事实不是原始事实。支持纠错、过期、删除及“当时真实情况”和“当时 Atlas 知道什么”两种时间查询。
- 记忆可以用于回答与行动，但使用前受角色范围、时效、来源质量和任务条件约束。
- 视觉截图和音频文件可用不可变内容寻址 blob 保存，长期记忆实体存引用、时间段及派生结构，不需要每条事实复制原始二进制。
- **屏幕观察到一个窗口，并不等于用户同意了窗口内容**；浏览到某个广告，也不代表用户喜欢这个产品；模型识别的情绪也不是用户确认的事实。
- 防止来自模型自身回答/旧记忆/工具回显的重复总结被误计为新独立证据。

## 2. 核心实体：事件、证据、解释、行动必须分开

| 层 | 实体 | 用途 | 真源关系 |
|---|---|---|---|
| Capture | `ObservationEvent` | 某设备/应用/Agent在时间 T 实际观察到的文本、状态和工具结果 | 证据或指向证据的不可变事件 |
| Activity | `ActivitySegment` | 一段连续活动，如编辑项目、浏览页面、手机消息、会议讲话 | 由一组事件聚合，边界可调整 |
| Experience | `Episode` | 目标、环境、行动、尝试、结果、验证；跨数个 segment | 派生、可再处理 |
| Semantic | `MemoryClaim` | 某项可修正的事实、偏好、决定、状态、推断、关系 | 派生、有出处且有双时间 |
| Entity | `MemoryEntity` | 用户/项目/机器/软件版本/人物/文件/网址等规范化身份 | 带作用域的身份节点 |
| Relation | `MemoryLink` | 前置条件、包含、依赖、造成、支持、反驳、继承、同一事件 | 不把时间先后自动归因果 |
| Learning | `MemoryPolicy` / `Procedure` / `Skill` | 经验策略和可执行经过验证的行为资产 | 追溯不同独立 episode 和验证 |
| Control | `MemoryScope` / `ConsentRule` / `RetentionRule` | 谁能看/写、何时捕获、何时删 | 不允许靠 LLM 自由解释 |
| Feedback | `MemoryUseTrace` | 哪次检索激活了哪段记忆，实际用于什么决策、结果如何 | 优化检索和复盘，不能反向冒充事实 |
| Prospective | `Commitment` | 已承诺未来要做的事情及触发时间/条件 | 应纳入可靠调度，不可只保存在向量库里 |

## 3. 事件统一协议（示意 JSON，不是已实现 API）

```json
{
  "schema_version": "0.1",
  "event_id": "01JC_example_ulid",
  "trace_id": "task-run-A",
  "parent_event_id": "01JC_example_parent",
  "actor": {"type": "atlas|worker|human|external_agent", "id": "agent:atlas"},
  "origin": {"device_id": "desktop-primary", "source": "agent_tool", "app_id": "editor", "window_id": null, "workspace_id": "repo:atlas", "session_id": "sess-A"},
  "time": {"occurred_at": "2026-10-16T01:00:00+09:00", "received_at": "2026-10-16T01:00:01+09:00", "duration_ms": 0, "clock_quality": "local_ntp"},
  "kind": "tool.result",
  "payload": {"content_type": "application/json", "text": "status=verified", "structured": {"exit_code": 0}, "media_refs": []},
  "provenance": {"source_message_id": "msg-12", "tool_call_id": "call-3", "capture_method": "agent_runtime", "is_model_generated": false, "content_sha256": "sha256:..."},
  "policy": {"scope_id": "private:owner", "purpose": "agent-task", "capture_rule_id": "rule-2", "sensitivity": "ordinary", "retention_class": "event-ledger"},
  "annotations": {"is_test": false, "is_redacted": false}
}
```

实际落库建议：`event_id` 稳定且全局唯一，`occurred_at/received_at` 兼存，`source_message_id/tool_call_id` 精确指针，`blob_id`、`sha256` 保障后续校验。`origin` 包含设备、应用、浏览器页面/窗口（在已有权限条件下），可保存设备和程序的稳定标识，但不要把浏览器页面标题当主键。媒体内容以引用形式连接；同一事件可有多个延迟产生的解析版本。

### 时间模型不可偷懒

- `occurred_at`：事件发生时间。跨设备可能不可信，附 `clock_quality` 和源时间区间。
- `received_at`：Atlas 接收时间，非事实发生时间。
- `valid_from/valid_to`：某一外部状态实际上何时有效（可未知）。
- `asserted_at/superseded_at`：Atlas 何时学习、认可或撤回该说法。
- `sequence_in_run`、`caused_by_event_ids`：“发生顺序”不等于“因果”，因果边需由工具依赖、操作前后状态和证据支持。

## 4. 事实和经历的语义契约

```text
MemoryClaim:
  claim_id, scope_id, subject_id, predicate, object_value, confidence_basis
  epistemic_status: candidate|supported|disputed|rejected|superseded|stale
  stated_by: user|model|document|device_sensor|agent_tool|external_agent
  valid_from, valid_to, learned_at, superseded_at
  evidence_refs[], counterevidence_refs[], inferred_from_claims[]
  correction_group_id, dedupe_key, extraction_version

Episode:
  episode_id, scope_id, task_id, activity_segment_ids[]
  goal, environment_snapshot_ref, preconditions, attempts[]
  key_decisions[], failures[], actual_outcome, verification_refs[]
  known_unknowns[], next_actions[], start_at, end_at, related_episode_ids[]
```

`epistemic_status` 是可信状态而非浮点自信度；`stated_by` 让“用户亲口确认”与“模型推测”不同权。多个重复摘要如果归根到底引用同一个源事件，不能算 5 次独立 corroboration。`counterevidence_refs` 记录不成立的原因，避免反复建议失败路径。episode 的“结果”要标记 `claimed_by`，工具返回 `ok`、模型说完成、系统测试验收成功是三个不同等级。

## 5. 存储不是必须统一物理引擎

**推荐先比较两条路径**，而不是立即决定 PostgreSQL:

A. `事件 ledger + SQLite（关系表+FTS+按需向量）+ blob`：本地轻、易回放、离线，扩设备时可通过签名 envelope 和同步队列扩展；注意跨进程写入并发、唯一事件和失效索引。

B. `事件 ledger + PostgreSQL/pgvector + blob`：统一事务、更强并发和复杂查询；适合多代理写入和长期高吞吐，但要求服务部署与维护。可沿用用户本机已有 PostgreSQL 的经验，却不能只凭“已经装了”判断最佳。

C. `深度吸收某开源内部模型`：只有直接复用更多已验证机制，且比 A/B 实现和长期维护更省时，才值得选；禁止保留两套用户/项目真源互相同步。

不需要再另设计一个抽象数据库框架。只需定义最少的稳定跨来源契约（事件写入、证据读取、Claim 更正、Episode 生成、Recall、遗忘传播）。

## 6. 从聊天到未来多模态的统一映射

| 来源 | 输入事件样本 | 后续语义活动 | 数据是否本阶段采集 |
|---|---|---|---|
| Atlas 聊天 | user.message / assistant.final | 对话事实、承诺、主题 | **本阶段** |
| Agent 工具 | tool.request/result，执行路径，版本，报错，test.result | 任务经历、解决方案、反例 | **本阶段** |
| 外部 Claude/Codex | 外部会话和工具轨迹，用来源标记 | 项目事实、决策史、协作经过 | **设计共享方式，实际导入分阶段** |
| PC 操作 | window.focus, UIA.node.change, action, screenshot.keyframe | 一段真实桌面活动/视觉观察 | **仅规划** |
| 浏览器 | navigation, tab, URL/document, DOM change, downloaded item | 网站工作流、页面状态变化 | **仅规划** |
| Android | app.foreground, accessibility node, notification, user interaction | 手机活动、跨设备任务 | **仅规划** |
| 语音 | audio.segment, asr.partial/final, speaker turns, vad boundary | 交谈、决定、可引用证据 | **仅规划** |
| 图像/视频 | frame event, keyframe, visual region, OCR/VLM output | 媒体场景、时空观察 | **仅规划** |

视觉语音来源需保留 `modality`、`media_ref`、`segment_time`、`speaker` 或 `region_bbox`；这些信息不能在早期直接丢弃到一段纯文本描述里。可以使用 OCR/UIA 文本帮助索引，但不能把 OCR 当成全部视觉真相。

## 7. 数据保护和控制（架构能力，不是强迫当前实施）

屏幕与语音属于持续感知。长期方案应支持设备级开关、应用允许/拒绝列表、暂停采集、明显状态指示、敏感内容过滤、按来源删除、源文件与派生索引联动删除、离线加密和有限保留周期。抓取浏览器/手机内容时尤其要防止密码、支付、医疗聊天、他人消息和第三方隐私自动升级为模型对用户的长期画像。

用户仍可选择最终配置为更全面的采集，但“能够覆盖一切”不等于“未经区分永久存一切”。这不是保守兼容旧框架，而是避免错误信息和敏感数据长期累积导致系统质量恶化。

## 8. 决策与例子

例：2026-10-15 在聊天中提到修 Atlas 命令，随后 Atlas 工具执行失败，用户从手机打开对应 GitHub issue，未来语音说“先恢复旧配置”。

- 同一个 `task_id`，四个不同设备/来源事件和各自精确证据。
- 一条 `Episode`：目标→尝试→失败→阅读→新的决定（不是四条零散用户画像）。
- 一条 `MemoryClaim`：当前决策“恢复旧配置”；`stated_by=user`，生效期与先前决定的撤销记录关联。
- 一条候选 `Policy`：“该类配置破坏时先核对旧兼容性”，需要多个独立经验且真实验证后才能晋升 Skill。
- 在下一次相似报错中 RecallRouter 查到此经验，返回源引用与未验证部分，而不是直接按含糊的摘要执行破坏性命令。

## 9. 不在这轮实施的明确范围

不写 Windows 视频/音频采集器，不采购或部署持续屏幕记录服务，不在 3060 6GB 上部署多模态模型，不开发安卓后台监控，不把音视频 embeddings 生成加进目前的运行时。该部分只保留接口、时间线、权限/容量预算、研究代码路径和以后验收样例。
