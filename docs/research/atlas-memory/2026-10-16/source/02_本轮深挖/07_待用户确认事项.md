# 研究中真正影响方案的未决问题

**当前研究并不依赖这些回答才能继续，暂按下面标明的默认假设进行。** 只有实施前遇到不可逆选择时再确认，避免反复打断。

## Q1（本轮建议优先确认）：多 Agent 长期记忆共享/写入权

你此前希望 Atlas、Codex、Claude 参与同一项目，讨论和执行能互相看到结果。现在要明确的是**记忆的写权限**，不只是是否能共享聊天：

- **A. 共享可读，写入由 Atlas 统一核对**：Codex/Claude 把任务轨迹与候选经验送回 Atlas，Atlas 决定它们是否成为全局事实/Skill。**默认推荐**，防止多模型误判争相修改个人画像。
- **B. 授权 Agent 可以直接写共享项目经历/状态，但个人事实仍通过 Atlas 确认**：协作更灵活，要求来源隔离、幂等和冲突治理。
- **C. 全部 Agent 对全局知识有同等写权限**：同步最直接，但错误互相强化、冲突和删除传播风险最大，不推荐无边界采用。

如果你要的是多个 Agent 共同学习同一套知识，A/B 都可达到；C 不等于更高级。

## Q2：未来常驻视觉/语音/手机感知边界

虽然暂不实施，但未来的长期行为差别很大：

- 默认仅 Atlas 任务期间 + 用户选定的应用/设备（推荐原型起点）；
- 未来全天候感知，但允许逐应用排除和快速暂停；
- 或保留全部原始媒体直至用户删除（磁盘、隐私和纠错成本更高）。

**暂定** schema 支持各模式，实施时默认明确授权/允许的范围，而不是替用户决定 24 小时录屏。

## Q3：跨设备用户画像

当来自声音/截图/外部 Agent 的推断与用户亲口确认的事实矛盾时，我建议前者只能生成 `disputed` 候选，不可直接覆盖 `user-confirmed`。如果你未来想让 Atlas 在日常行为中自主更新性格、习惯、偏好，也应该保留人工可查看和改正的能力。

## Q4：能力、时延、成本的优先级

暂按“正确性/能力优先，但对话前检索尽量轻，重处理放后台”作为默认；不因某数据库已安装就锁死选型。
