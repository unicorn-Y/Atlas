# Atlas 记忆系统 V4.2 — 可派给 Codex 的原生施工任务书与接口契约

> **日期 2026-10-16。状态：研究任务书，尚未执行代码施工。** 与 `V4_1_源码级原生移植裁决与替换矩阵.md` 配套。先以 V4 统一总纲的用户决议为最高前提。既不是安装几个记忆插件，也不是让 Codex 重新写一整套。开发者可自由读写 Atlas、提交代码和执行命令；下文所述来源/证据校验是质量需求，不是新增用户审批或执行权限控制。

## 一、架构先定“谁是核心、什么是可替换”，别过早锁数据库

```text
                     Atlas唯一规划/决策主体
               ┌──────────┼────────────┐
               ↓          ↓            ↓
          任务运行状态  ContextBroker   RecallRouter
               │          ↕            ↕
               │      Codex/Claude   Fact/Claim/Skill/Policy
               │      任意worker          ↑       ↓
               └───────┬───────────事件巩固/检索
                       ↓
             Atlas 自己的 SourceEvent 链
                 ↕         ↕       ↕
           SessionDB   工具日志   未来多模态ref
                 └─────┬──────┘
                 SQLite/Index/Markdown read-view
```

**只有 SourceEvent + 可验证的 canonical 原始来源成为证据基准；Episode/Claim/Skill 是它的衍生解释，不是另一个 Agent 的私有库。** 迁移原有 Markdown 记忆可保留用户明确写的条目及来源，但不能把旧总结复写成“用户亲口说的”。SQLite 暂定作为轻量实现，不锁死长期存储后端。未来 UI/媒体/手机同步仅复用统一事件 ID 与 payload_ref，不启动模态采集。

### 最少原生领域结构（概念结构，不要求严格按五个 Python package 拆）

**SourceEvent**（行为事实，不是 LLM 猜测）
```python
@dataclass(frozen=True)
class SourceEvent:
    event_id: str           # 已存在 message_uid / 确定性工具日志键，不重发随机 id
    source_kind: str        # session_message / tool_call / tool_result / git / file / future_media
    actor: str              # atlas / codex / claude / user / other: 源头身份，不是记忆所有权
    occurred_at: str        # 源事件发生时间
    recorded_at: str        # Atlas 捕获时间
    session_id: str | None
    task_id: str | None
    run_id: str | None
    project_id: str | None
    parent_event_id: str | None
    payload_ref: str        # SessionDB uid、run log offset 或文件绝对/相对 URI
    content_sha256: str | None
    source_claim: str       # observed_tool / user_statement / agent_report / inferred
```

**MemoryClaim**（结构化提炼结论）
```python
@dataclass
class MemoryClaim:
    claim_id: str
    subject_id: str
    predicate: str
    object_value: str
    valid_from: str | None     # 事实世界何时开始成立
    valid_until: str | None    # 事实世界何时停止成立
    asserted_at: str          # Atlas 何时提取/得到这个断言
    retracted_at: str | None  # Atlas 何时认定该断言失效
    status: str               # active / superseded / disputed / forgotten
    evidence_event_ids: list[str]
    extractor_version: str
```

**TaskMemoryBundle**（瞬态编排物，**不可**回灌为证据事件）
```python
@dataclass
class TaskMemoryBundle:
    bundle_id: str
    task_id: str
    goal: str
    constraints: list[str]
    current_plan: str | None
    project_id: str | None
    relevant_claims: list[dict]
    prior_episodes: list[dict]
    relevant_skills: list[dict]
    known_failures: list[dict]
    evidence_refs: list[str]
    omitted_refs: list[str]    # 能继续 request_more，不代表禁止访问
    context_version: int
```

实际最少字段可复用 `dict/Pydantic` 而非为了模仿样例强建复杂类层；保留类型含义即可。

**工作中主张（provisional claim）**不能和已确认事实写成相同状态。用户纠正、可复核工具日志、Agent 自报任务完成具有不同证据语义；不需要为每次读取审批。

### 数据持久化建议（实施时允许和现有表合并）

```sql
CREATE TABLE IF NOT EXISTS source_events (
  event_id TEXT PRIMARY KEY, source_kind TEXT NOT NULL, actor TEXT NOT NULL,
  occurred_at TEXT NOT NULL, recorded_at TEXT NOT NULL,
  session_id TEXT, task_id TEXT, run_id TEXT, project_id TEXT,
  parent_event_id TEXT, payload_ref TEXT NOT NULL,
  content_sha256 TEXT, source_claim TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS ix_event_task_time
  ON source_events(task_id, occurred_at);
CREATE TABLE IF NOT EXISTS processed_events (
  event_id TEXT NOT NULL, processor TEXT NOT NULL, processor_version TEXT NOT NULL,
  stage TEXT NOT NULL, attempts INTEGER NOT NULL DEFAULT 0, last_error TEXT,
  next_retry_at TEXT, updated_at TEXT NOT NULL,
  PRIMARY KEY (event_id, processor, processor_version)
);
CREATE TABLE IF NOT EXISTS memory_evidence (
  claim_id TEXT NOT NULL, event_id TEXT NOT NULL,
  relation TEXT NOT NULL, PRIMARY KEY (claim_id, event_id, relation)
);
```

**精确来源优先**：读取聊天原文采用已有 `core/atlas/engine/session_sync.py::latest_session_message_id`、`session_message_evidence` 及 SessionDB 原有 `message_uid`。需要扩展一个 `read_by_message_uid` 精确读取入口（别硬写 timestamp nearest）。工具日志若有 `run_id + tool_call_id + event-type` 组合确定性键，就把它规范化为 `event_id`；没有稳定 tool_call_id 的日志以 `run_id+record ordinal+payload hash` 组成确定性键，禁止每次复处理生成新随机 ID。

## 二、施工分波：先抢救真源，再搬成熟内核，最后串使用闭环

### 工单 A0 — 基线、备份、重用确认（必先做，尽可能半天内）

**目的**：停止之前反复“已做又重造”、防止覆盖最新别人刚写的代码。

**阅读**：`main`、`memory-v1`、`memory-w2-api`、`memory-w2-ui` 与用户本机 `D:\Atlas`；检查当前工作树及 `core/atlas/memory/library/`、`core/atlas/evolution/skill_sleep.py`、`core/atlas/kernel/subagents.py`、`core/atlas/engine/session_sync.py`。

**动作**：
1. 查看现用 engine/data path 与本地数据库 schema；备份实际库和 Git 工作区（保留用户数据）。
2. 列 `已跑通 / 已写代码未合并 / 旧方案需替换 / 缺失` 对照，不从自己的空目录开工。
3. 记录可复用 `message_uid`、W2 `FTS5 trigram+CJK bigram`、已有 SkillOpt 入口、Timeline UI。
4. 将接口/目标文件映射与本地实际版本差异发入施工分支计划文件；**无需向用户征求一个个授权/同意**，自行继续 A1。
5. **只跑 1 轮 smoke**：原记忆库能打开、搜索、编辑、回滚；旧数据完整。

**验收**：一页现状差异表 + 旧数据库可读备份 + 本地可继续施工。*原研究分支保持只读证据归档，真正施工放独立开发分支*。

### 工单 A1 — 核心 SourceEvent 和单一来源证据（Python，第一技术前置）

**主要移植参考**：AMA `tool.py::traj_get/traj_find`、LongMemEval-V2 `trajectory_store.py` 指纹，Atlas `session_sync.py` 稳定 ID。

**计划修改/新增**：
- `core/atlas/memory/library/sources.py`：保留 `open_ref` 兼容旧 ID；新增 `open_event_ref` 优先 message_uid / tool_event_uid，旧 `session@timestamp` 仅作 legacy fallback。
- `core/atlas/engine/session_sync.py`：复用现有 UID 查证，必要时新增精确按 UID 读取原始消息，不做另一套对话数据库。
- `core/atlas/memory/native/events.py` **建议新建**：确定性 `event_id`、归档适配、EvidenceRef。
- `core/atlas/memory/native/trajectory.py` **建议新建**：`get_steps`, `find_steps`（移植 AMA）和 `content_fingerprint`（借 LongMemEval-V2，排除随机运行 ID）。
- `core/atlas/agent/run_phases.py::_note_tool_step`：保留旧 30x200 摘要作 prompt view，但原始工具调用/结果必须由**现有 SessionDB/日志**归档，不能把摘要数组当唯一 source。复用已落盘事件，避免再次把全部巨型结果存入记忆 SQLite。

**核心规则**：原始文件内容不因被提炼就被复制成很多“原话”；`event_id` 冲突的重复写变成同一次处理，不因生成时间不同而产生两个 episode。

**验收样例**：同秒两条消息可分别精确打开；一条工具调用返回长日志，提示只看 200 字但通过 ref 可打开全部原始结果；重复导入 2 次事件/episode 不增长；跨不同 run 的相同逻辑轨迹可识别“同内容”而不抹掉原始来源。

### 工单 A2 — 记忆处理队列与 Dream 原生重构（ReMe 源码移植）

**主要源实现**：
- `agentscope-ai/ReMe@514ca643.../reme/schema/dream.py`：DreamUnit、DreamState、IntegrateOutcome。
- `.../reme/steps/evolve/dream/extract.py::DreamExtractStep.execute`
- `.../reme/steps/evolve/dream/integrate.py::_integrate_one`
- `.../reme/steps/evolve/dream/finish.py::DreamFinishStep.execute`

**Atlas 目标**：
- `core/atlas/memory/library/queue.py` 或新的 `native/jobs.py`：原生 per-event claim/processing/done/retry 状态，SQLite 事务 `BEGIN IMMEDIATE` + 条件更新获取消费权，少量重试和恢复扫描。不要为此引入 Redis/Celery。
- `core/atlas/memory/library/__init__.py::_drain, observe_turn`：未配置模型时不要删除待提炼条目；日记写入幂等；失败时不抹掉 source。
- `core/atlas/memory/library/dream.py::run_dream`：以 ReMe 的 Extract→Integrate→Finish 流程**替换当前全局时间水位线算法**，每条来源的每个 processor_version 独立推进。避免 `_episode_groups` 把不到三天的 group 永久跨过去。`trigger` 不再直接作为 project_id，应该用任务/工作区/Repo identity。
- `core/atlas/memory/native/consolidation.py` **建议新建**：基于 DreamUnit 和 IntegrateOutcome 的结构化整合 `CREATE|CORROBORATE|REFINE|CORRECT`，源证据挂 stable IDs。源项目 prompt 模板可随适配一并移植，保留版本/来源，不强制重写。
- Markdown `项目.md` / `事实.md` 可保留**可重建的呈现视图**，但不再作为证明来源。换模型失败不会掩盖用户原话和现有状态。

**冲突/重试场景**：
1. 同一天项目只有 1 条事件，第三天增长至 4 条，应仍能在当天或满足窗口时被消费，绝不因为全局 checkpoint 漏掉。
2. 两实例同时处理同条来源，应最多一份处理状态。
3. Dream 生成 Markdown 并写 Git 后程序崩溃，恢复之后不得再新增内容相同但随机 ID 不同的条目；靠确定性 unit/result key 与 upsert，不把 Git commit 当数据库事务。
4. 模型 API 连续失败 3 次后可显式恢复消费；无模型时不假装成功并删除候选队列。
5. 时间同秒的多条 user/assistant 消息全部保持来源准确。

**验收**：只跑以上有针对性的失败/恢复检查。产出迁移映射 + 新版巩固来源账本和一个真实 Dream 示例；**不要只把旧全局 checkpoint 改大到 7 天**。

### 工单 A3 — 原生 RecallRouter 与证据回溯（MemOS + Hindsight + AMA）

**源实现**：
- MemOS `core/retrieval/retrieve.ts` 5 类场景入口、`tier2-trace.ts` 候选评分/episode 归并。
- Hindsight `engine/search/fusion.py::cap_per_source`, `reciprocal_rank_fusion`。
- AMA `ama_agent_core/retrieve.py::memory_retrieve` 中不足证据时的邻域扩展逻辑。

**Atlas 目标**：
- `core/atlas/memory/native/recall.py` **建议新建**：`recall(query, scene, task_id, max_tokens, seen_ids) -> RecallResult`。scene `turn_start/tool_error/subagent_handoff/skill_invocation/repair/fact_check`；输出 evidence refs+confidence/source_type 与摘要。
- `core/atlas/memory/library/index.py` 与 `hybrid.py`：**保留已有 CJK bigram/FTS5 trigram/向量搜索**，补缺失的向量后台调度点（已有 `_schedule_embeddings` 依赖 running loop，部分调用来自 `asyncio.to_thread`）。按真实检索对比选 Hindsight RRF 还是 W2 weighted+MMR；不要先删掉能工作的搜索。
- `core/atlas/memory/library/embed.py`：初始化失败重新尝试须有明确重载或重试机制；不应在启动偶发失败后永久 unavailable。
- `run_phases.py::_merge_library_recall`：改为调用统一 RecallRouter 轻召回，已有 resident/相关记忆展示继续可用。
- `native/trajectory.py`：召回不够时从原始事件按稳定 step_id 邻接展开；如需更深分析，再调用 LLM 检查充分性，不是每个轻问题耗额外模型判断。

**验收**：在同一组 20~50 个来自真实 Atlas 的中文任务与修复记录上，比较原 W2 vs 新候选：evidence hit、错误引用、p95 延迟/Token。短错误码/代码路径必须可由 lexical 命中；事实已纠正后不能默认旧事实；只给摘要时能一跳打开原始证据。未胜出则保留旧融合器。

### 工单 A4 — ContextBroker 接入 Atlas 原生委派（Atlas 专属少量开发）

**关键代码事实**：
- `core/atlas/agent/run_phases.py::_phase_context` 对 `request.worker` 显式清空 state.history/context，主会话才自动 `_merge_library_recall`。
- `core/atlas/kernel/subagents.py::SubagentManager.run` 当前已接管子任务的 `goal/context/cwd/subtask_id/atlas_options` 和 hook、完成事件；不要另建任务执行器。
- `core/atlas/engine/tool_registry.py::bind_atlas_tools` 是 Atlas 工具注册适配入口，但**各个外部 Codex/Claude 实际运行桥接点还需本机静态查完整调用链**，不能凭子 Agent 文件推断全部已接好。
- `run_phases.py::_phase_finalize` 目前 `request.worker` 不执行 `_schedule_library_write`；委派完成**由 Atlas 统一收集 Episode**，避免外部 Agent 建永久分库。

**建议文件**：
- `core/atlas/memory/native/context_broker.py`：`prepare_context`、`request_more`、`collect_result`，复用 RecallRouter 和 SourceEvent。
- 在既有 Delegate/Task/Workflow 启动通道增加 **一处共享调用** `prepare_context`（将 bundle 编入已有 `context` 或工具返回，避免四处重复拼 prompt）。
- 按现有 tool registry 模式提供 `atlas_memory_request({task_id, query, seen_ids, max_tokens})`，回复为有 ref 的文本与可追加读取的证据。对于外部 CLI 不支持工具注册的情况，先用 Atlas 本地工具/CLI 轻桥接，不重新运行一个独立记忆服务。
- 完成 `collect_result(task_id, run_id, result_refs, logs, diffs, verification_refs)`，实际取已有事件日志、文件变更、Git commit 生成 Episode 和经验候选；**不把执行器自报 done 当成已验证完成**。
- 外部 Codex/Claude 的开发/执行权限仍遵循已有 `full_access` 配置，不增加按记忆域 ACL、身份令牌或额外审批。

**交互协议示例**：
```json
{
  "op": "atlas.memory.request_more",
  "task_id": "task-42",
  "query": "之前为什么弃用旧的 Dream 全局 checkpoint？",
  "seen_ids": ["event:abc"],
  "max_tokens": 1800
}
```
```json
{
  "task_id": "task-42",
  "context_version": 2,
  "summary": "旧版本按全局时间推进；不足阈值的 group 可能永久漏掉",
  "evidence": [
    {"event_id": "event:def", "kind": "code", "ref": "repo:Atlas@aa14c317:core/atlas/memory/library/dream.py:154-210"}
  ],
  "more_available": true
}
```
*例子中的 task/event ID 是样例值，**不是生产已存在的记录**。请求的 source type 必须从真实数据源落地。*

**验收**：同一任务交给 Atlas 子执行器再交给 Codex/Claude（先取当前支持的 2 种运行器），可首次自动携带相关错误历史；执行中调用 `request_more` 找原文；换执行器后项目进度仍由 Atlas 保存；回收不少于源码变更和命令执行证据；不会为每个子 Agent 建一份独立长期记忆。无法实际验证某个外部 runner 时逐个标记待接，不冒充全覆盖。

### 工单 A5 — 时间事实、纠错/遗忘与主动任务召回（Graphiti 机制）

**源实现**：Graphiti `graphiti_core/edges.py::EntityEdge` + `edge_operations.py::_apply_temporal_invalidation/resolve_edge_contradictions`。将这两个函数中依赖最少、可表达的时间比较和状态转移提取为 Atlas 可读代码，配对上游反例测试。

**目标代码**（建议）：`core/atlas/memory/native/claims.py` + `native/links.py`；旧 `library/forget.py`、`cleanup.py`、`_apply` 的用户原话/纠错语义需兼容迁移或替换，保证 legacy 条目仍可搜索。

**必须防的逻辑漏洞**：
- 同一个说法改为新值，旧说法保留历史但不当当前值；在 2025 年发生的事实到 2026 年才获知，查询两个时间轴能区分。
- 一条用户“忘记”请求需对派生 Fact/Claim、向量、倒排索引和 Markdown 投影生效，不允许索引 rebuild 使旧内容复活。
- 不同来源矛盾时保留证据状态，不能凭 LLM 自信度随意替用户改个人事实。
- “代码编译过了”“工具 exit=0”“用户认为目标完成”三种证据要分层。
- 任务型 prospective memory 不只是事实条目。明确期限/未来条件的承诺关联原有 Atlas 任务调度器；**不用为本工单新造定时服务**。

**验收**：5 条人工审定的时间冲突/纠错/遗忘案例和 1 个任务完成认知回写案例；查询现在/当时分别准确。

### 工单 A6 — 从任务经历学成可用 Skill（MemOS eligibility + 已有 SkillOpt）

**上游**：MemOS `skill/eligibility.ts` `evaluateEligibility` + `hasSuccessAnchor`；`skill/evidence.ts`；`skill/verifier.ts`；ReasoningBank 作为正负轨迹策略写法参考；SkillOpt 已被 Atlas 集成。

**Atlas 目标**：
- `core/atlas/evolution/skill_sleep.py::harvest_atlas` 当前只采 `source IN ('desktop','cli')` 的用户会话摘要，不收 cron/subagent；添加来自 Atlas Canonical Episode / 真实 tool-step evidence 的**增量适配**，不要把同任务多会话重复算成多个成功证据。
- 借 MemOS 的 eligibility 先挑重复出现的、有**客观工具结果或用户有效反馈**的成功模式；生成 Skill 草案，交回现有 SkillOpt replay/gate/adopt，不移植第二个 Skill publisher。
- 一个 Skill 包含触发条件、前置依赖、失败/反例、操作步骤、环境版本、关联 evidence IDs、实际运行反馈；调用后再把成败写回 SourceEvent/Episode。
- 若 SkillOpt API 与原外部库版本不合或 replay 太贵，优先修其已有导入/调用，实测成本与通过率后再决定是否保留这个最终发布器。不因 V4 总纲既说“保留 SkillOpt”就强制保护一个不起作用的组件。

**验收**：挑 2~3 类真正重复的 Atlas 修复/调试任务，验证至少一个 Skill 经候选→验证→注册→再次调用→反馈闭环；失败/旧版本过期可回退。不要把输出 100 个技能当成功。

### 工单 A7 — UI 与未来跨设备的少量接线（不做感知）

- 先把 `memory-w2-ui` 已有 Timeline/检索和来源抽屉对接 stable refs、双时间事实和任务 Episode，不另建新记忆 UI 大工程。
- 统一事件 envelope 预留 `device_id/source_kind/payload_ref/media_sha256`，真正采集截图/语音/Android 后再讨论延迟同步、权限、模型调度；不为此拉通 Screenpipe、VLM 或语音模型。
- UI 只暴露对用户有用的：为什么记住、原话证据、何时改过、哪些 Skill 从哪次执行学到；幕后指数/分级数值不必全部做开关。

**验收**：从 UI 点一条事实可打开真实来源消息；纠错后历史可看、当前搜索不混；不调用视觉/手机/语音后台服务。

## 三、最少接口和运行约束（供不同 Codex worker 并发使用）

```python
# 概念 API，具体模块名在 A0 对照原仓之后确定。
class AtlasMemory:
    async def ingest(self, event: SourceEvent) -> str: ...
    async def recall(self, query: str, *, scene: str, task_id: str | None,
                     max_tokens: int, seen_ids: list[str] = []) -> dict: ...
    async def open_event(self, event_id: str) -> dict: ...
    async def consolidate(self, *, changed_event_ids: list[str] | None = None) -> dict: ...
    async def prepare_context(self, task_id: str, goal: str, executor: str) -> TaskMemoryBundle: ...
    async def request_more(self, task_id: str, query: str,
                           seen_ids: list[str], max_tokens: int) -> dict: ...
    async def collect_result(self, task_id: str, run_id: str,
                             result_refs: list[str], verification_refs: list[str]) -> dict: ...
```

注意 Python 实现不应使用上面样例中可变默认值 `seen_ids=[]`；用 `None` 并在内部归一化。这里只说明接口形状。

### 一致性关键细节（不是繁琐安全工程）

- `ingest` 支持相同 event_id 幂等；`processed_events` 只有成功才标 done；多个进程用 SQLite 原子 claim。
- `MemoryClaim.evidence_event_ids` 可打开原文；模型给的 inference/摘要不能自动伪装为 source_user。
- `collect_result` 保存原始事实和实际运行状态，不以 worker `done` 字符串一键晋升 Skill。
- `ContextBundle` 可重建/过期，只需持有原始 event refs；**不得因为反复生成 bundle 而循环重写库形成“100 个来源支持一条假事实”**。
- 真正的 TaskState 按 Atlas 任务体系保存；记忆索引挂 `task_id`，不要求每次对话做向量搜索才能找当前任务进度。
- 老 `session@timestamp` 可以保留兼容映射，精确 UID 作为新格式；老资料没有稳定 ID 的则明确表示 nearest/fuzzy，禁止误标 exact。
- Task 写入和媒体事件保持可扩展，但这波先只做 chat/task/tool，不把未来特性偷偷纳入代码。

## 四、并行工作与最小验收（速度优先）

**依赖拓扑**：
```text
A0 ─→ A1(源事件与精确证据) ─────────┬─→ A2(ReMe巩固)
                                   ├─→ A3(召回/证据)
                                   ├─→ A4(ContextBroker)
                                   └─→ A5(Claim/时间)
        A3 + A4 + A5 ────────────────┬─→ A6(Skill)
                                     └─→ A7(UI/未来接口)
```
可以并行让 Codex 分别做 `A2` ReMe Dream、`A3` MemOS/Hindsight、`A5` Graphiti 纯逻辑，但它们必须共享 A1 的 `event_id/evidence_ref` 语义，不要同时各自建三个 `MemoryStore`。A4 可并行追查 worker 接口，但最后一起整合到单一 RecallRouter。

**每工单只交以下 5 件东西**：
1. 移植说明 `UPSTREAM_PORT.md`（原 commit、文件、函数、许可证、删改内容、源项目对应测试）。
2. 真正修改的 Atlas 源码及必要 DB migration。
3. 一两条能证明该能力的运行实例；关键边界增量小测试即可。
4. 未集成部分/已知失败（不能写“全部完成”）。
5. Git commit 与变更范围；按用户以往工作流由执行器在允许的独立施工分支主动推送。

**阶段 Gate（尽量少）**：
- G0 基线：本机代码/数据库可恢复、已有码表准确。
- G1 原始证据：稳定 uid 可点击、重复 ingest 不增重复行。
- G2 记忆生命周期：Dream 3 天补处理、模型故障恢复、不重复。
- G3 召回/委派：与 W2 实比，外部执行中可 request_more，实际结果回流。
- G4 长期效果：时间纠错不复活、Skill 真能被再次调用成功、UI 来源准确。

不要为了每小改动加完整云服务、MCP、RBAC 或测试平台；**但不能因为嫌麻烦跳过源证据正确性和旧数据迁移**。
