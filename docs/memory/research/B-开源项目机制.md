我在给自己做一个个人 AI agent 的长期记忆系统（只服务我一个人，跑在我自己的电脑上，Windows，中文为主）。我想从开源项目里挑最强的做法拿来用，所以需要知道**每个项目在代码层面到底是怎么实现的**，而不是它的宣传语。

请联网调研下面这些项目，优先读它们的 GitHub 源码、文档、论文和 issue：

MemOS（MemTensor）、Hindsight（vectorize-io）、Supermemory、MemPalace、EverOS（EverMind-AI）、claude-mem、graphiti（getzep）、mem0、Letta（原 MemGPT）、cognee、memU、Memori、agentmemory（rohitg00）、basic-memory，以及 SillyTavern 的"世界书 / World Info"和总结插件。你认为同样重要、但我没列出来的项目也请加上。

## 每个项目请按下面这些问题回答（没有就写"没有"）

1. **记什么、谁来记**：自动从对话里提炼，还是需要显式调用？用什么模型提炼？提炼用的提示词大概是什么样（有原文就贴）？
2. **怎么存**：存的是原文、摘要、事实三元组、图谱，还是 Markdown 文件？用什么数据库？
3. **时间**：事实有没有生效时间 / 失效时间？新旧信息冲突时怎么处理（覆盖、保留历史、标记过期）？
4. **认人认事**：同一个人的不同叫法怎么合并？合并错了能不能拆开？
5. **怎么想起**：向量检索、全文检索、图遍历、关键词触发，还是按时间？怎么排序（相关度、新近度、重要度怎么加权）？每次带入多少？
6. **淡忘和删除**：有没有衰减或淡忘机制？删除是真删吗？
7. **巩固 / 反思**：有没有后台整理，把经历提炼成认识或技能？多久做一次？怎么做？
8. **来源和可信度**：每条记忆有没有出处？会不会区分"用户说的"和"模型推断的"？有没有防投毒的机制？
9. **透明可改**：用户能不能直接查看和修改记忆？是不是人能读懂的格式？
10. **中文支持**：分词和检索对中文好不好用？
11. **资源占用**：能不能纯本地跑？需要什么模型？大概占多少内存和 CPU？检索有多快？
12. **效果证据**：在 LongMemEval、LoCoMo 这类评测上的成绩（附出处），以及 issue 里用户反映的真实问题
13. **许可证**、维护活跃度

## 输出格式

1. 每个项目一节，按上面 13 个问题写，**关键结论附源码路径或链接**
2. 一张对比总表：行是项目，列是上面 13 个维度，每格一两句话
3. 按维度分别给出"做得最好的是谁、具体是哪段代码 / 哪个机制"
4. 把你看到的**设计上的坑**单独列出来（比如某个项目因为某种设计导致记忆混乱）

请用中文回答。不确定的标"未证实"，不要编。

## 搜索要求（必须遵守）

不要只看官网、GitHub README 和大媒体。真实情况和用户抱怨大多散在各种论坛、社区和小平台上，这些地方是本次调研的重点。

**1. 必须覆盖的来源类型，每类至少尝试搜一次：**

- 中文社区：知乎、V2EX、贴吧、小红书、B 站（视频简介和评论区）、即刻、掘金、CSDN、博客园、少数派、NGA、微信公众号（可以用搜狗微信搜索）、魔搭社区、语雀和飞书的公开文档
- 英文社区：Reddit（r/LocalLLaMA、r/ClaudeAI、r/ChatGPT、r/OpenAI、r/singularity、r/replika、r/CharacterAI、r/SillyTavernAI、r/AI_Agents、r/ChatGPTPro 等）、Hacker News（包括评论区）、X/Twitter、Lobsters、dev.to、Medium、Substack、YouTube（视频和评论）、Product Hunt 评论
- 日韩：Qiita、Zenn、note.com、Naver
- 应用商店评论：App Store、Google Play，以及国内各大应用商店
- 开发者内部讨论：GitHub 的 **issues 和 discussions**（不是 README）、Hugging Face 的讨论区、各项目的 Discord 或论坛公开存档
- 学术：arXiv、OpenReview（包括审稿意见）、Semantic Scholar、Papers with Code

**2. 搜法：**

- **按问题搜，不只按名字搜**。例如"AI 记忆 混乱""AI 忘记 我说过""陪伴 AI 人设崩""ChatGPT memory wrong""companion app forgets""agent memory hallucinated memories"
- **多种语言都搜**：中文、英文，必要时日文
- **顺着链接再走两步**：看到一篇好帖子，就去翻它引用的链接和评论里提到的项目
- **不要只看大项目**：star 很少的小仓库、个人博客、一次性的实验报告都要看，经常能找到别人没注意的好办法
- **时间优先最近 12 个月**，更早的经典内容也可以收

**3. 进不去的地方如实说：**

需要登录、被屏蔽、打不开的平台，请在结尾单独列一份"没能访问的来源"清单，写明你本来想在那里找什么。我会自己去查。

**4. 每条信息都要附来源链接，并标注来源类型**（官方 / 社区 / 用户评论 / 论文 / 源码）。拿不准的标"未证实"。
