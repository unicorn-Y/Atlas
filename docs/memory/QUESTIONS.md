## 现状（2026-10-14 实查）

- 每轮对话的记忆读写走的是旧 MemoryOS（`D:/MemoryOS`，端口 8099，`[memory.unified]`）。启动时在 CPU 上预热 embedding，常驻约 1.5 核。
- MemOS 原本作为 Hermes 插件接入。内核换成 Atlas 自研之后，就没有地方再调用它了，所以它不再进数据。「记忆」页显示的是 MemOS 里的旧数据，和实际使用的记忆脱节。
- 教训：记忆挂在某一种循环上，换掉循环就会断，而且断了也没人发现。

## 已经定下的原则

1. **像人一样自然，但比人可靠**：学人脑"怎么想起来"（联想、按时机触发、睡觉整理），不学它的会编、会丢。每条记忆都能追到原话和出处。
2. **淡忘只降优先级，不删除**：原始经历永远保留；不常用的就不主动想起。只有用户说"忘掉"才真删。
3. **不找一个引擎包办一切**：Atlas 自己定记忆的分类、规则和给内核的固定插槽，每一类挑最强的实现，以后换实现不用动内核。
4. **透明记忆库**：事实层是普通文本文件，用 git 管版本。每次变动用户都能看到、能改、能回退。用户亲手改过的内容优先，系统只能提建议。
5. **想起来的时机由系统保证，不赌模型自觉**：常驻 → 线索触发 → 场景触发 → 模型主动回想（这一层只是补充）。
6. **验收靠用户的"下午考试法"**：用一段时间后挑细节提问。分当天、隔天、隔一周考；换新会话考；用没发生过的事考它编不编；用改过主意的事考它会不会更新。每次一句话记下结果。
7. **它自己写记忆，不用用户确认**（10-14 定）：用户每天能看到记忆变动就行，发现不对自己会改。推测类记忆照样直接写，但必须标明是推测、写清楚依据。
8. **"它自己"那部分用户也能改**（10-14 定）。
9. **记忆库要有外观，不是一堆文本文件**（10-14 定）：底层仍是文本加 git，用来保证透明和能回退；Atlas 里呈现的是可视化界面。草案是卡片墙作为首页，加上关系图、时间线、今日变动三种视图，样式待用户定。

## 记忆的分类（草案）

| 类别 | 是什么 | 现有材料 |
|---|---|---|
| 经历 | 发生过什么（对话、工具调用、看到的东西） | `engine/state.db` 已经完整记录，缺带时间感的检索 |
| 事实 | 关于你、关于人和事、偏好、当前状态 | 缺，透明记忆库的主体 |
| 技能 | 会做什么、怎么做 | 已有技能系统 |
| 要做的事 / 没说完的事 | 提醒、待跟进 | 已有定时和提醒；"没说完的事"缺 |
| 工作记忆 | 眼下在干什么 | 对话上下文 + 计划 / todo |
| 关于它自己 | 它表过的态、犯过的错、和用户之间的事 | 缺 |

## 一、关键问题（要先想清楚）

### 1. 来源与可信度【待拍板】
- **为什么**：用户亲口说的、模型推断的、网页上的、别的 agent 声称的，可信度差很多。网页里藏一句话就能污染记忆（投毒）。
- **建议**：每条记忆标来源。只有用户亲口说的直接当事实；推断出来的只算"猜测"，要么用户确认，要么多次观察到才转正；网页和工具内容永远不能直接变成关于用户的事实。

### 2. 时间
- **为什么**：没有时间维度一定会乱。"这周想安静"要自动过期，搬家后旧地址变成历史而不是被删掉。
- **建议**：事实带"从何时成立 / 何时失效"，查询默认取当前有效的，问历史时再带出旧的。参考 graphiti 的双时间模型。

### 3. 认人认事
- **为什么**："老王""王总""他"是不是同一个人，认错就张冠李戴。这是最难的部分之一。
- **建议**：人和事都有固定 id 和别名表。拿不准的时候先问，不硬合并；合并错了能拆开。

### 4. 分区【待拍板】
- **为什么**：工作和生活、不同项目、普通模式和专家模式不能串。子代理、工作台挂件、被调用的 Codex 能读写到哪里也要有规矩。
- **建议**：按"生活 / 工作 / 每个项目 / 专家模式"分区，用的时候只带当前场合相关的。专家模式的内容只在专家模式里读写。外部 agent 默认只读，而且只读当前任务相关的分区。

### 5. 两台电脑【待拍板】
- **为什么**：笔记本和主机都在用。记忆放在哪、怎么同步、两边同时改了怎么办。
- **建议**：透明记忆库本身就是 git 仓库，像同步代码一样同步。主机作为主库，冲突时以用户手改的为准，其余按时间新的为准，并在变动流里提示。

### 6. 真删除与 git【待拍板】
- **为什么**：git 会保留所有历史，只删当前文件不算真忘。
- **建议**：用户说"忘掉"时连同历史一起清掉（改写历史），并在一个不含内容的删除登记里记一笔，防止从旧备份里复活。硬规矩：密码、密钥、令牌永远不进记忆文件，写入前自动拦截。

## 二、实施问题

### 7. 中文检索
默认全文检索按空格分词，中文基本搜不到。需要中文分词或 trigram，再配合向量检索。

### 8. 速度和资源
每轮都要取记忆，必须快。不能接受 40 秒预热、常驻 1.5 核。检索要在百毫秒级；embedding 只在写入时算，或者用轻量模型。

### 9. 谁来写记忆
用户经常切换模型，弱模型写出来的记忆质量差。建议写入和整理固定用一个靠谱的模型，跟当前聊天用的模型脱钩，并且可以配置。

### 10. 图片、截图、语音、文件
记描述 + 指向原件的链接，原件按需再看。

### 11. 和上下文压缩的关系
长对话会被压缩成摘要。哪些内容该从摘要转成长期记忆，压缩前要不要先"存一下档"，需要定规则。

### 12. 几年以后
记忆越积越多，事实文件怎么归档、合并，检索会不会变慢。

## 三、更高一层

### 13. 知道自己不知道
记不清就说"好像是……不太确定"或"这个我没记住"，绝不编。比多记一百条都重要。

### 14. 从纠正里学
用户纠正一条记忆时，不光改这一条，还要找出当初为什么会记错，把那个环节也修了。

### 15. 经验什么时候变成技能
做几次算熟练、技能怎么验证、过时了怎么发现。

### 16. 旧数据【待拍板】
MemoryOS 和 MemOS 里已有的数据：导入、筛选后导入，还是从头开始。

### 17. 记忆有没有被用上
系统自己统计取出来的记忆是否被用到、用得对不对，配合用户的下午考试一起看。

## 四、"像人"的部分（从陪伴类 AI 得到的启发）

### 18. 没说完的事
单独记"进行中、还没结果"的事，比如面试、生病、项目上线。到了时间点，或者碰到相关话题时，主动跟进。这是"被记住、被在乎"的感觉里最核心的机制。

### 19. 它自己的记忆
它表过什么态、犯过什么错、和用户之间发生过什么、对事情怎么看。没有这一层就没有连续的"自己"，只会一问一答，或者顺着用户说。

### 20. 主动开口的分寸
已有心跳机制（`core/atlas/heartbeat`）。什么时候值得打扰、什么时候该闭嘴，需要设计。主动太多会烦，太少不像人。

### 21. 情绪也是记忆
记事的同时记下当时的情绪，用来判断重要程度，也用来调整之后怎么说话。

### 22. 关键词触发
SillyTavern 的"世界书"：每条记忆配几个关键词，对话里出现这些词才带入。这是线索触发的成熟做法，值得看它的实现。

**提醒**：陪伴类产品的目标是让人上瘾，有的会刻意讨好、制造依恋。Atlas 要的是懂你，但不讨好你。

## 五、后来补充的

### 23. 记忆指向的东西本身要持久
- **怎么发现的**（2026-10-14）：Claude 的记忆里写着"有个 gpt_cdp.py 能驱动网页 GPT"，但脚本放在上一次会话的临时目录里，已经没了。结果是"记得以前有办法，却找不到那个办法本身"，只能从头再造。
- **建议**：做过的工具、方法、脚本要落进仓库等不会丢的地方。记忆里存"在哪、怎么用"，不只存"做过"。整理记忆时检查记忆指向的文件、路径还在不在，不在就标记失效。
