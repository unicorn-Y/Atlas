## W3 findings

The two confirmed findings are in [W3-issues.json](./W3-issues.json). The process source root is confirmed as `D:\Atlas`; exact loaded-file bytes and disk-change chronology remain unobserved. The queue finding is on a clean file at the confirmed HEAD; the error-card mapping file has only the unrelated dirty tool-label addition described above.

- **W3-001 (P1):** failed runs enter the same terminal handler as successful and cancelled runs, then call `dispatchQueue`. A failure does not set `queuePaused`, so the next queued prompt is removed and started automatically. This can continue work after a model failure and contradicts the taskbook’s required pause-and-preserve behavior. W1 owns the smallest correction: mark the conversation queue paused on `run.failed` before dispatch and retain its queued items for explicit resume.
- **W3-002 (P1):** the failure timeline conversion reduces the event to `detail ?? code`; the alert card renders that single string. Provider/model/status/request ID/attempt count and retry policy metadata are not displayed by this path, even though a separate manual retry button exists. W1’s error event contract and this projection need to agree; preserve/render structured diagnostics with safe redaction.
