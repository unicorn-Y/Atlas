### W1 模型故障策略（唯一授权立即改代码，专属 worker）
范围：core/atlas/kernel/model_call.py、kernel/loop.py、agent/run_phases.py、models/router.py、engine/hermes_runtime.py、凭据池/上游 Hermes 入口、API 事件映射、前端失败 UI 与队列调度。只改当前实际生效的调用路径，必要时修其他路径保持一致；不要重写整个模型引擎。

预期行为与优先级：

- 瞬时连接异常、连接重置、HTTP 500/502/503/504（以及确有临时意义的 408/529）：首次失败最多**补重试 2 次**，同一模型累计 HTTP 请求最多 3 次。建议短退避 0.5s、1.5s（可因已有代码接口轻微调整）；一切重试受取消信号控制。
- HTTP 429：若上游给 Retry-After 且等待时间不超过 15s，可在同模型的累计 3 次上限内等候重试；超过 15s 直接终止并提示预计恢复时间；没有 Retry-After 时用短退避有限重试。不要几十分钟自动守候限流。
- HTTP 400/401/402/403/404/413/422、密钥缺失、余额不足、模型不存在、上下文超限、内容过滤、请求参数非法：直接报错，不重试（如 HTTP 状态和正文冲突，依据实际分类并说明）。不要通过提示词改写来“绕过”过滤错误。
- 流式请求中途失败：若本次尝试已显示文本、reasoning 或工具调用 delta，**不盲目重发该请求**，防止重复文本、混合输出或重复工具副作用。保留可见部分与失败说明；工具已执行的事实不能抹去。即使未输出但已执行工具，亦不可自动重跑副作用。
- 严格保持本次任务选择的 model_id 不变。去掉主会话 fallback_models 自动候选与 models/router.py complete_for 隐式追加 deepseek-v4.1-flash、deepseek-v3 的策略。显式配置给“记忆提炼/压缩/标题”等不同功能的模型本身不是“故障自动切换”，允许保留；但若该模型失败，不能退到别的模型。
- 注意 Hermes/SDK/多层重试和凭据池。总请求次数不得因多层重试被乘起来。同模型多个 API key 的正常凭据管理不是自动换模型；若凭据池会绕开总请求次数上限，则最小化修正。绝不为此实现一整套新路由抽象。
- 成功则正常继续；失败时运行状态变为 failed，保留会话与已做结果。错误卡应显示：友好中文分类、model_id、provider、HTTP status（若有）、原始错误说明（脱敏）、request_id（若有）、尝试次数、是否允许手动重试，且无“已自动换模型”误导文案。
- 若因模型故障终止运行，**暂停该会话待执行队列**，但保留排队内容；由用户手动恢复或重试。保留后台启动/普通 GET 读取接口的适度重试，不要因本任务删除应用可用性逻辑。
- 当前代码中必须重点查：model_call.py 默认 10 次且连接失败存在无界分支；run_phases.py 读取 fallback；models/router.py complete_for 硬编码两个 DeepSeek 备用模型；前端事件结束后 dispatchQueue；Hermes/credential_pool 可能有上游自动恢复。此前旧测试通过不得视为新策略有效。

W1 测试只做最小且有意义的针对性检查，最好用本地假 HTTP 网关，不花真实 API token：
1. 网络瞬断一次后，同模型第二次成功；
