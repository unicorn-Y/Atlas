## User-visible goal

Atlas controls native Windows applications and authenticated browser tasks through one stable runtime. It reuses an explicitly selected persistent browser profile, targets a named window, observes state through UI Automation or DOM/accessibility snapshots, falls back to screenshots/vision when semantics are missing, checks action results, recovers after process/runtime failure, and can pause for the user to complete login or CAPTCHA in the same profile. Repeated demonstrated browser workflows become editable, safely replayable **drafts** in the existing Atlas skill library.

## Scope and exclusions

Include one lifecycle-owning `ComputerBrowserRuntime`, Windows UIA/desktop adapter, persistent browser/CDP adapter, profile registry and locking, per-task workspace downloads, safe upload rules, dialog/tab lifecycle, foreground escalation/human handoff, screenshot and vision fallback, action readback, restart recovery, telemetry, and the narrow existing-session/tool/frontend wiring below. Demonstration capture/replay is X2 and writes only a reviewable candidate to the current Atlas SkillManager.

Exclude connector/channel work (X1), cross-device pairing/sync/A2A (X3), skill registry/install/update ownership (X4), upstream learning/promotion pipelines (X5), persistent-agent autonomy (X7), a second session/policy/plugin registry, browser cookies or passwords in prompts/logs/events, automated CAPTCHA solving, broad browser scraping, and video. Do not create or run X implementation as part of PREP.

## Data, interfaces and events

`ComputerBrowserRuntime` protocol: `health()`, `open_session(session_id, device_id, profile_id|None, mode)`, `observe(session_id, target)`, `act(session_id, action, target_ref, args, idempotency_key)`, `attach_cdp(session_id, endpoint_ref)`, `handoff(session_id, reason)`, `resume(session_id)`, `close_session(session_id)`. Public tools stay compatible through adapters, not duplicate implementations.

Persistent non-secret records: `runtime_session_id`, `atlas_session_id`, `device_id`, `backend`, `profile_id`, `window_ref`, `browser_context_ref`, `state`, `last_event_sequence`, `started_at`, `last_seen_at`, `handoff_reason`, `error_class`. Browser profile data/cookies remain in a local OS-protected profile/vault; only opaque handles are logged. Action record has `action_id`, target reference, expected state, `idempotency_key`, state-before/after digest, result and timestamp. Download artifact links to Atlas task artifact with normalized MIME, digest and access scope.

Events are versioned and carry `session_id`, `device_id`, `runtime_session_id`, monotone `sequence`, `occurred_at`: `computer.runtime_state`, `computer.window_list`, `computer.observation`, `computer.action_started`, `computer.action_completed`, `browser.profile_state`, `browser.tab_changed`, `browser.download_ready`, `browser.upload_started`, `browser.dialog_pending`, `computer.handoff_required`, `computer.resumed`, `workflow.draft_ready`. Screenshots are artifacts/references, never unredacted base64 in event logs by default.

## Windows requirements

Run the desktop driver in the logged-in interactive Windows session; a Windows Service/session-0 process is not allowed to click the user's desktop. A background-preferred action can use app-native/DOM/UIA APIs while the target window is idle; foreground escalation is explicit, visibly announced, and returns focus when safe. Record HWND/process identity and revalidate it before every action. Detect multi-monitor geometry and per-monitor DPI; normalize screenshot coordinates then map to physical display coordinates. Handle UAC secure desktop by stopping for user action. Browser user-data directory is exclusive-locked; never run two Chrome owners against it. On runtime crash, reap only processes Atlas launched and reattach only to profiles Atlas owns. Preserve safe behavior under lock, RDP disconnect, sleep/resume and user desktop switch; measure rather than infer.
