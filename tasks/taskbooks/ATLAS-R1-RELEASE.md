# ATLAS-R1：成品化（稳定性、安装包、升级、文档、清理）

> 取代 `ATLAS-W14-FINAL-ACCEPTANCE.md`。前提：X1–X6 完成。
> 先读 ROADMAP-TO-PRODUCT、EXECUTION-GUIDE，以及 `ATLAS-W14-FINAL-ACCEPTANCE.md` 原文作参考。

## 1. 安装包（Python 3.14 + Hermes 内核）

- 现有的一体化打包：`npm --prefix frontend run dist:win` 生成 NSIS 安装包，里面带 PyInstaller 冻结的后端和固定版本的 Node。
- 要改的：
  1. PyInstaller 换成支持 Python 3.14 的版本；
  2. 把 Hermes fork（固定提交号的那个依赖）和它的数据文件（提示词、技能、模型元数据等）完整打进去，用 `--collect-data` / `--collect-submodules` 逐个核对，不能运行时缺文件；
  3. ripgrep、Git Bash 的检测和提示（不自动装）；
  4. 安装包大小、首次启动时间都写进结果文件。
- **验收**：在一台干净的 Windows 虚拟机或新用户账户上，从安装 → 首次向导 → 配模型 → 跑一个任务，全程不需要装 Python 或 Node。要用户配合时先问。

## 2. 升级不丢数据

- 数据有两处：Atlas 的数据目录，和 `<数据目录>/engine`（Hermes 的会话库）。
- 写版本迁移：旧版本的数据库结构自动升级，升级前先备份；降级时提示，不破坏数据。
- **测试**：用 W06 时期的数据目录、C1 时期的数据目录各升级一次，对话、记忆、配方、检查点、用量都在。

## 3. 稳定性

- 连续 24 小时的浸泡测试：后台常驻、定时任务、长对话、子 Agent、MCP 断线重连，一起跑。假模型和少量真实模型调用混着用（真实的部分先问用户）。
- **指标**：

| 项目 | 要求 |
| --- | --- |
| 崩溃 | 不崩 |
| 内存 | 增长不超过 20% |
| 句柄和进程 | 没有泄漏，没有孤儿进程（LSP、MCP、终端、子 Agent） |
| 日志 | 大小有上限，会轮转 |

- 断网、模型服务宕机、磁盘满这几种情况下，界面要给出白话提示，数据不坏。

## 4. 文档

- `docs/user/`：中文使用说明。内容包括：安装、配模型、日常用法（对话、改代码、撤回、子 Agent、计划、Goal）、扩展（技能、插件、Hooks、MCP）、外部功能（渠道、触发器、浏览器、电脑操作、跨设备）、常见问题。配截图。
- `docs/dev/`：架构说明（界面 → 适配层 → Hermes 内核）、怎么合并 Hermes 上游、怎么从别家搬东西、怎么跑测试。
