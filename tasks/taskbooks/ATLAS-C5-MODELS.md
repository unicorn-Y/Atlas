# ATLAS-C5：模型与成本

> 先读 ROADMAP-TO-PRODUCT、CORE-PARITY（M 系列各行和 L8）、EXECUTION-GUIDE。前提：C4 验收通过。

## 本波目标

主流模型服务商（尤其是国内的）都能用原生参数接入，思考、缓存、用量都要准确；支持多个密钥轮换；思考量能按阶段分配；能告诉用户这次缓存为什么没命中；可以编辑已经添加的模型。
做完以后，CORE-PARITY 里 M1、M2、M5、M6、L8 都是 ✔。

各家的参数要查**当月**的官方文档，不要凭记忆。

## 1. 服务商全套（M1）

- **来源**：Hermes `providers/`、`agent/provider_registry.py`、`agent/models_dev.py`（模型元数据）、`agent/reasoning_params.py`；Pi 的统一模型接口 `packages/ai`。
- **做法**：
  1. 设置里「添加模型」改成先选服务商：Anthropic、OpenAI、Google、OpenRouter、DeepSeek、Kimi（Moonshot）、智谱 GLM、通义 Qwen、MiniMax、阶跃 Step、小米 MiMo、硅基流动、火山方舟、本地（Ollama / LM Studio），以及「OpenAI 兼容的自定义地址」。
  2. 每家用自己的原生参数，按 Hermes 已有的适配来；没有的就照官方文档补：
     - 思考的开关和强度（例如 DeepSeek 的推理内容、Qwen 的 `enable_thinking`、GLM 的 `thinking`、Kimi 的思考模型）；
     - 上下文窗口和输出上限、是否支持看图、是否支持工具调用；
     - 用量字段里的缓存命中数、价格。
  3. 模型元数据优先读 models.dev，读不到就用内置表，再不行就让用户手填。
  4. 思考内容在界面里可以折叠查看。
- **测试**：每家一个假服务用例，覆盖请求参数和用量解析；用户现在用的中转地址（OpenAI 兼容，模型 `openai/deepseek-v4.1-flash`）不倒退。

## 2. 多密钥轮换（M2）

- **来源**：Hermes `agent/credential_pool.py`、`credential_pool_admin.py`、`credential_pool_model_cooldowns.py`。
- **做法**：一个服务商可以填多个密钥；遇到限流或额度用完自动切到下一个，被限的那个冷却一段时间；设置里能看到每个密钥的状态、今日用量和冷却剩余时间。密钥存在系统凭据库（keyring）里，接口永远不返回密钥原文。
- **测试**：第一个密钥返回 429 后切到第二个；冷却到期后恢复使用。

## 3. 分阶段思考量（L8）

- **来源**：LangChain 的「推理三明治」：规划和验收用最高档，执行用高档。只做这一个改动，Terminal-Bench 的分数就是 66.5，对比 53.9。
- **做法**：设置 → 模型加「按阶段分配思考量」，默认关闭。打开后：
  - 第一轮和计划模式用「规划档」；
  - 中间执行用「执行档」；
  - 完成前自检（Hermes 的 stop gate）用「验收档」。

  三档都可以设置。在 Hermes 的 `agent/reasoning_effort.py` 里按阶段切换。
- **测试**：三个阶段发出去的请求带不同的强度参数；关闭时保持不变。

## 4. 缓存未命中原因（M5）

- **对标**：Claude Code 9 月新增的「可能的缓存未命中原因」。
- **做法**：每次请求记下前缀的哈希，按层记：系统提示词、工具定义、历史。缓存命中率突然下降时，比较这次和上次哪一层的哈希变了，在用量页和那一次调用的详情里写明原因，比如「工具定义变了（MCP 服务器重连）」「系统提示词变了」「超过缓存有效期」。
- **测试**：人为改一次工具定义，能正确报出原因。

## 5. 编辑已有模型（M6）

- **来源**：W06 遗留，原 W07B 第 2.5 节。
- **做法**：已添加的模型可以修改：名称、地址、密钥（只能重新填，不显示旧的）、参数、价格、能力标记。改完立即生效，正在跑的任务不受影响。

## 6. 测试和交付

- 每节各自的测试；端到端：多个密钥的服务商，第一个被限流 → 自动切换 → 打开分阶段思考量跑完一个任务 → 用量页显示缓存原因。
- 结果文件里附一张服务商对照表：每家支持什么、参数怎么映射、文档链接和查阅日期。
- 更新 CORE-PARITY、PARITY（F002、F164–F166、F108）。

## 验收清单

1. 服务商对照表完整，每家的参数都有文档出处。
2. 密钥从不出现在接口返回、日志和前端里。
3. 已有功能不倒退，特别是用户现在用的中转地址。
