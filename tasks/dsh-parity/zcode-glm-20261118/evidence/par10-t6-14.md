## 3. UI 入口与数据路径

入口：`frontend/src/renderer/App.tsx:3627` 的 `sheet === 'extensions'` 设置页，现有 `ExtensionCatalogPanel` + `ExtensionPackagesPanel`。

版本区（每个 `kind === 'extension'` 行内）：
- 行内徽标 `版本 <version>`；面板标题 `当前版本`，非 SemVer 时显示“不是语义化版本，无法读取升级”并禁用检查。
- `检查升级` 展开：`注册表 URL`、`回退注册表（可选）`、`读取版本`。
- 成功结果显示：`当前安装`、`目标版本`（预发布徽标）、实际应答来源、`registryPlan` 顺序；`可用升级` 为 `newer_versions` 逐项可选（预发布带标签，点击会用 `version=` 重读该版本 facts）；facts 展示 `预发布`/`peerDependencies`/`deprecated`/`dsh`（bundle 与 entry）。
- 操作：`安装所选版本 <x>`、`取消安装`、`允许构建 <package>`；安装完成回调 `load()` 刷新扩展目录。
- 失败：检查失败保留输入与上一次成功结果并标注；安装失败展示后端脱敏的 `failureSummary`/`failureKind`/`failureAttribution`；注册表输入被改动后禁用安装，防止用检查时的旧来源安装。

请求路径（全部经产品 `BackendAdapter`，渲染层从不直连 registry）：

| UI 动作 | 方法 | 路由 |
|---|---|---|
| 读当前版本目录 | `ExtensionCatalogPanel` 既有 `api()` | `GET /api/plugins` |
| 读取/重读版本 | `pluginVersions.checkPluginVersions` → `BackendAdapter.getPluginRegistryVersions` | `GET /api/plugins/registry/versions?name=&registry=&installed=&version=&fallbackRegistries=...` |
| 安装所选版本 | `installPluginVersion` | `POST /api/plugins/install`（`source: name@version`, `sourceType: npm`, `registry`, `fallbackRegistries`, `requestId`） |
| 等待/取消 | `waitPluginInstall` / `cancelPluginInstall` | `GET /api/plugins/install/{id}?wait_ms=` / `POST …/cancel` |
| 构建批准 | `grantPluginBuildApproval` | `POST /api/plugins/script-approvals` |

T6-6 语义保持：registry 选择与安装共用 `build_install_plan`；仅配置主源或显式 `fallbackRegistries` 可回退；私有/显式单源不回落；取消检查贯穿 attempt；输出先脱敏；requestId 幂等；审批不换源。

安装操作并发/取消（返工后）：
- `installGuard` 同步 ref 在首次点击立刻置位，挂起中的创建请求不会因双击重复 POST；终态与错误经 `settle`/`releaseOperation` 释放。
- 忙碌状态拆为 `starting`/`following`/`cancelling`/`approving`。安装按钮在操作期间禁用；`queued`/`running`/`awaiting_approval` 都可以取消，取消按钮仅在取消请求在途（`cancelling` 或状态 `cancelling`）时禁用。
- 每次安装/取消/批准/查询都递增 `generation` 并替换 `AbortController`；取消会中止当前 follow，旧轮询响应因 generation 不匹配而丢弃，不会覆盖终态。
- 取消 HTTP 直接返回终态时立即清忙/释放守卫，不依赖 follow 的 `finally`。
- 轮询 120×1s 超时后显示“查询安装状态”，调用 `GET /api/plugins/install/{id}?wait_ms=0` 的无等待入口继续核对；不再提示不存在的刷新动作。
