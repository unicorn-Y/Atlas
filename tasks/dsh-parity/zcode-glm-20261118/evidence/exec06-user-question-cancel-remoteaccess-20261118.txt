B3 差距(相对 DSH)
G1 无协议级取消通知:Atlas app_server 取消 pending question 时不发
   user-question.cancelled{requestId,sessionId};客户端只能等 run/task 终态。
G2 取消语义丢失:ask_user 取消返回 ""(B2),工具层无法区分“用户取消”(DSH ASK_ABORTED)
   与“用户提交空字符串”;DSH 明确规定取消不是回答、不是 provider failure。
G3 桌面面无问题级取消帧:只有 run.cancelled;question 卡不会收到自己的终态,
   取消后 answerInput 仍显示已回答(store 乐观写入 answers),wire 侧静默丢弃。
G4 无请求身份关联:desktop event_id 内含 run_id+call_id,但取消时不按该 id 发通知;
   app_server 有 request_id,但不外发。
G5 Atlas 的 durable pending 审计是本地记录(appserver.request),不是可观察 wire 契约;
   DSH 的通知是 server→client 的显式协议帧。

E. 结论
================================================================================
- user-question.cancelled:DSH 是协议级“请求已停止等待”通知,发射点唯一、两套 SDK 均消费、
  测试覆盖取消与通知失败包含。Atlas 有实际取消路径(app_server/task cancel/进程重启),
  但(1)不发该通知,(2)取消被折叠成空回答,(3)桌面只有 run 级终态。状态:部分。
- remoteAccess:DSH 是完整的分资源访问控制服务 + 快照流 + 条件 UI。Atlas 仅有
  短期 bearer 令牌与布尔 origin 闸。状态:部分(粗粒度)。
- 实施受在途文件归属限制(app_server.py/run_drive.py),本批只落精确引用、差距与
  可复验验收;实现项登记 blocked-on-author。
