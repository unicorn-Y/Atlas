## 3. 根因（隔离单进程试验收敛）

环境事实：Python 3.14.7、PyInstaller 6.22.3、onnxruntime 1.31.0、rapidocr 3.10.0、
opencv-python-headless 5.0.0.93、winrt-runtime 3.2.1。

最小复现（每个场景独立子进程）：

| 场景 | 退出码 |
|---|---|
| `import onnxruntime` | 0（对照组） |
| `import winrt.runtime; import onnxruntime` | **3221225477** |
| `import winrt.runtime`（观察已加载的 msvcp140 路径） | 0；加载 `D:\Atlas\core\.venv\Lib\site-packages\winrt\MSVCP140.dll` |
| 预加载 `C:\Windows\System32\msvcp140.dll`（14.51.36247）后再 `winrt.runtime` + `onnxruntime` | 0 |
| 预加载 winrt 私有 `msvcp140.dll`（14.29.30157，同名）后再 `import onnxruntime` | **3221225477** |

结论：`winrt-runtime 3.2.1` wheel 在包目录内自带旧版 `MSVCP140.dll`（14.29.30157.0），
任何 `winrt.*` 子模块导入都会把它装入进程；之后加载 onnxruntime 1.31 的
`onnxruntime_pybind11_state.pyd` 时绑定到该旧运行库，`_pybind_state.py:32` 处
0xC0000005。系统 `msvcp140.dll` 为 14.51.36247.0，先加载它则 winrt 复用系统副本，不再崩溃。

与 PyInstaller 收集顺序的关系：

- `winrt` 来自 `--collect-all hermes_cli` 收录的 `hermes_cli/windows_store_update.py` /
  `windows_appinstaller_update.py` 内的函数级 `from winrt...` 导入；Atlas backend 自身不使用 winrt。
- PyInstaller 在 `find_binary_dependencies()` 中把全部 collected 包按顺序在同一个隔离子进程导入；
  本次顺序里 `winrt.runtime` 第 1321 位，`rapidocr.inference_engine.onnxruntime` 第 1483 位，
  因此 winrt 的旧运行库先被加载。
- 按同一 1915 包顺序单进程重放：第 1483 位崩溃；去掉 6 个 `winrt*` 条目后 1909 个包全部导入通过
  （57 个可选依赖导入失败被跳过，均为可选依赖缺失，非本问题）。

证据：`.par10-t6-13/logs/rootcause.txt`、`collected_packages_fresh.txt`。

## 4. 修复

`frontend/scripts/build-backend.mjs` 增加一个排除项（放在 PyInstaller 参数末尾）：

```js
  // winrt-runtime 3.2.1 (pulled in by hermes_cli's Windows Store helpers)
  // ships its own MSVCP140.dll (14.29.30157), older than the system runtime.
  // PyInstaller's dependency scan imports every collected package in one
  // process; importing any winrt module first loads that private runtime, and
  // onnxruntime 1.31's pybind module then dies with 0xC0000005. The Atlas
  // backend never imports winrt (Hermes' Store helpers run under the separate
  // bundled payload Python), so keep it out of the bundle.
  '--exclude-module', 'winrt',
```

理由：Atlas backend 不导入 winrt；Hermes 的 Store/AppInstaller 助手按源码注释由独立的
bundled payload Python 运行，不依赖 backend 包。排除后 Analysis TOC 的 excludes 为
`['winrt', '__main__']`，PYZ 与 `_internal` 均无 winrt，候选包不再把旧 `MSVCP140.dll`
带进依赖扫描或运行时。未改依赖版本、未改系统运行库、未使用安装器/卸载器。
