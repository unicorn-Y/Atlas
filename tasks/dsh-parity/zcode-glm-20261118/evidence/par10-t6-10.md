## 2. 槽 API

新模块 `frontend/src/renderer/slots/SlotRegistry.ts`：

| API | 行为 |
|---|---|
| `declareSlot(name, { kind, scope?, description? })` | 声明 `single` / `list` 槽；同 kind/scope 重复声明是 no-op；kind 或 scope 冲突直接抛错。`scope` 默认 `app`。 |
| `registerSlot(name, { id, component, order? })` | 注册组件并返回幂等 disposer。未声明槽抛 `Unknown slot`。 |
| `unregisterSlot(name, id)` | 精确移除一个注册；未知 name/id 返回 `false`（disposer 可重复调用）。 |
| `unregisterScope(scope)` | 级联卸载该 scope 下所有注册，返回移除数量；声明保留，允许重新注册。 |
| `renderSlot(name, props?)` | 当前快照的命令式渲染；未声明槽抛错，空槽返回 `null`；`list` 顺序为 `order` 升序、再按注册序号。 |
| `slotSnapshot(name)` / `listSlots()` | 只读快照，供自检与测试。 |
| `SlotRegistry` | 上述函数的命名门面（`declare/register/unregister/unregisterScope/render/snapshot/list/subscribe`）。 |
| `SlotOutlet`（`SlotOutlet.tsx`） | 订阅版出口；注册/卸载后立即重渲染，`fallback` 仅在空槽时显示。 |

单槽重复注册的确定裁决：

1. **先注册者占用**，不同 id 第二次注册抛错：`Slot "..." is single and already occupied by "<id>"; unregister it first`。
2. **同 id 原地替换**，用于 HMR / 扩展重载，不会因重复导入而失败；替换为不同组件类型时 React 卸载旧实例。
3. `list` 槽允许多 id，互不影响；同 id 替换保留原位置。

## 3. 真实接入点

1. **应用根（`app.root`，single/root）**
   - `App.tsx` 默认导出改为 `<SlotOutlet name="app.root" />`，App 根只渲染 root 槽。
   - 原根包装 `ErrorBoundary label="应用"` + `AppContent` 整体移入 `AppRoot`，在 App 模块求值末尾注册：`registerSlot('app.root', { id: 'atlas.app-root', component: AppRoot })`。
   - 布局、样式、错误边界与启动行为不变；`main.tsx` 未改。
   - 第二个不同 id 注册 `app.root` 会被注册表拒绝，不能静默遮蔽 Atlas。

2. **现有组件 `DiagnosticsFloatingOverlay`（`shell.diagnostics`，single/root）**
   - 原来在 `AppContent` 里的直接渲染：
     ```
     <DiagnosticsFloatingOverlay apiBaseUrl={store.apiBaseUrl} />
     ```
     改为：
     ```
     <SlotOutlet name={BUILTIN_DIAGNOSTICS_SLOT} props={{ apiBaseUrl: store.apiBaseUrl }} />
     ```
   - 注册在 `slots/builtinSlots.ts`，组件仍是同一个 `DiagnosticsFloatingOverlay`，`apiBaseUrl` 透传。
   - 原有 Ctrl+Shift+D / `atlas:toggle-debug-overlay` 事件监听和“关闭”按钮行为未改。

3. **卸载**
   - `registerSlot` 返回 disposer；`SlotOutlet` 订阅注册表版本。卸载后该 id 从渲染列表消失，React 卸载对应实例；`unregisterScope` 做作用域级联。
