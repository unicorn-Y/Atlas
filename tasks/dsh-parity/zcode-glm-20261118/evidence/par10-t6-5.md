## 3. package:backend 阻塞（具体阶段与实际错误）

- 崩溃点：PyInstaller Analysis 的二进制依赖发现阶段 `find_binary_dependencies()`。
- 错误：`PyInstaller.isolated._parent.SubprocessDiedError: Child process died calling import_library() with args=('rapidocr.inference_engine.onnxruntime',) ... exit code was 3221225477`（0xC0000005 ACCESS_VIOLATION）。
- 调用栈：`onnxruntime/capi/_pybind_state.py:32`；发生在导入 `onnxruntime_pybind11_state.pyd` 时。
- 确定性复现：从失败日志导出 PyInstaller 自己的 1915 个 collected package 导入顺序，在单一进程按序导入，1482/1915（`rapidocr.inference_engine.onnxruntime`）处同样 0xC0000005，faulthandler 栈指向同一行。
- 最小探针（仅 `--collect-all rapidocr --collect-all onnxruntime`）退出 0，说明是更大 collected 包集合中的 DLL/运行时冲突，而非 Atlas 源文件或 T2 清单接线。
- 环境：Python 3.14.7、PyInstaller 6.22.3、onnxruntime 1.31.0、rapidocr 3.10.0、opencv-python-headless 5.0.0.93。
- 依赖缺口：未重跑 `pip install -e core[release,channels]`（会改主树共享 venv）；候选树无自己的 venv。按任务书“缺依赖写具体阶段与实际错误”，以现有真实 0.1.0 backend 副本继续。证据：`par10-t6-5-backend-blocker.txt`、`par10-t6-5-dist-win.txt`。

**证据缺口影响**：本包未证明“backend 从本树 HEAD 源码重新生成与打包”；其余应用/清单/Node/NSIS/安装链均在真实产物上验证。backend 副本与候选树源码版本同为 0.1.0，exe sha `13d8511e…` 与 0.1.0 发布清单一致。
