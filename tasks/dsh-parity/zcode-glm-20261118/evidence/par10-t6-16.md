## 3. 清单契约

### 3.1 线格式（构建期注入 `window.__ATLAS_BOOT_MANIFEST__`）

```ts
{
  rev: string;                         // 必填、非空
  release?: { version: string; commit?: string };
  entries: Array<{
    id: string; url: string; rev: string;
    inject?: string[]; external?: string[];
    dependsOn?: string[];              // Atlas 扩展：相位内依赖边
    immediately?: boolean;
  }>;
  batches: Array<{
    phase: 'bootstrap' | 'application';
    url: string; rev: string;
    entries: string[];                 // 非空、批内不重复
  }>;
  assets?: string[];                   // Atlas 扩展：本次构建允许引用的本地资源全集
}
```

### 3.2 归一化投影

```ts
{
  rev; release?;
  modules: [{ id, url, rev, dependsOn, inject, external, initialUrl, immediately }];
  plugins: [{ id, inject, immediately }];   // 每个 entry 一行，与 DSH 两视图一致
  batches: [{ phase, url, rev, entries }];
  assets?;
}
```

- `initialUrl` 由条目所属唯一批次的 `url` 派生（与 DSH `BootModuleRow.initialUrl` 同义）。
- `plugins` 保留全部条目，`immediately` 标记第一阶段预取层，不从 modules 视图删除。
- 未知对象成员丢弃（release 内未知成员也丢弃）；数组/字符串类型严格校验。

### 3.3 拒绝面（稳定错误码）

`MANIFEST_NOT_OBJECT`、`INVALID_REV`、`INVALID_RELEASE`、`INVALID_ASSETS`、`INVALID_ENTRIES`、`INVALID_ENTRY`、`DUPLICATE_ENTRY_ID`、`INVALID_INJECT`、`INVALID_EXTERNAL`、`INVALID_IMMEDIATELY`、`INVALID_DEPENDS_ON`、`DUPLICATE_DEPENDENCY`、`SELF_DEPENDENCY`、`UNKNOWN_DEPENDENCY`、`DEPENDENCY_CYCLE`、`PHASE_ORDER_VIOLATION`、`INVALID_BATCHES`、`INVALID_BATCH`、`INVALID_BATCH_PHASE`、`INVALID_BATCH_REV`、`INVALID_BATCH_ENTRIES`、`DUPLICATE_BATCH_ENTRY`、`DUPLICATE_BATCH_URL`、`UNKNOWN_BATCH_ENTRY`、`ENTRY_IN_MULTIPLE_BATCHES`、`ENTRY_WITHOUT_BATCH`、`NON_LOCAL_URL`。

运行期错误码：`MISSING_LOCAL_MODULE`、`MISSING_LOCAL_ASSET`、`MISSING_ROOT_MODULE`、`MOUNT_NOT_REACHED`、`MODULE_INIT_FAILED`。

与 DSH `packages/client/modules/src/client/manifest.ts:229-330` 对照：两视图投影、release 形状、批次 phase/url/rev、批次 URL 唯一、条目恰属一批、未知条目/无批次 loud 拒绝均对齐。Atlas 的差异是：(a) 字符串要求非空；(b) URL 收紧为本地构建路径（沙箱要求）；(c) 增加 `dependsOn` 与 `assets` 扩展；(d) 错误携带稳定 code/path/hint，供可恢复诊断面板使用（DSH 抛普通 `Error` 文案）。

## 7. 未覆盖 / 边界

- **未启动完整 Electron 主进程**（`npm run dev`、打包版、`electron.ts` 的主窗口 `file://` 装载路径、完整 `atlas.server` lifespan、真实模型）。探针是真实 Electron BrowserWindow + 真实生产 `dist` + 真实 preload，经本地 HTTP 装载；Chromium 探针同样只覆盖生产渲染入口。
- **`immediately` 预取层未实现执行语义**：字段被严格解析并投影到 `plugins`，但 Atlas 的模块全部静态打包，没有 DSH 的 bundle transport，因此没有“提前 prefetch、失败静默、Loader 重试”的对应路径；本轮不把该字段当作可执行调度。
- **清单只在构建期注入**：没有后端/host 运行时下发清单的路径（任务允许“生成或内置”）；没有远程清单获取。
- **`assets` 可省略**：schema 为兼容手写/单测清单允许省略；产品构建始终生成 `assets`，省略时运行时不校验 URL 是否真实存在（仅跳过该门）。
- **挂载后失败**：`application` 根模块之后的模块失败（`mounted=true` 且 `atlasBoot=failed`）由单测覆盖；真实探针未制造该场景。此时“以兼容模式继续”只移除诊断并标记 legacy，不会二次挂载（避免重复 React root）。
- **rev 一致性**：manifest/entry/batch 的 `rev` 各自只校验为字符串，不校验三者相等或与资产内容哈希绑定（DSH 同样只做类型校验）。
- **未跑 macOS**；本轮为 Windows 10.0.26200。
- **未新增 CSP**：origin 边界由“URL 白名单 + 静态模块表 + 不 fetch/import 清单 URL”保证；`index.html` 原有 CSP 状态未被本包改变。
- **T6-11/T6-12 合并在本树之外**：本包 `main.tsx` 保留单一 `mountApp()`；合并时 T6-11 的 `KeybindingsProvider`/`ShortcutReferenceHost` 必须包在 `mountApp()` 内，T6-10 slots 继续由 `App.tsx` 持有。本树未引入任一其他包文件，避免交叉污染。
- **全量前端回归未在本轮重跑**；引用 08:57 的 86 files / 416 tests 日志，源码 mtime 均早于该日志且此后未改。
