默认清单候选（按优先级）：

1. `resources/atlas/release-manifest.json`
2. `release-manifest.json`

检查顺序与失败原因（全部 fail-closed，不静默继续）：

1. 安装根存在且是目录 → `install_root_missing`
2. 清单存在（缺失 → `manifest_missing`）、路径安全、可读、JSON 合法、schema=1 → `manifest_missing` / `manifest_unreadable` / `manifest_invalid_json` / `manifest_invalid` / `unsupported_schema`
3. 逐项文件存在且为普通文件 → `file_missing` / `not_a_file` / `file_unreadable`
4. 三份哈希逐项重算比对：`Atlas.exe`、`atlas_backend.exe`、`sqlite3.dll` → `hash_mismatch`
5. 版本/平台一致：app / Electron / 内置后端 `__version__` / node-runtime.json / build.platform+arch / `bundled_node.platform` → `version_mismatch` / `platform_mismatch` / `metadata_invalid`
6. 路径边界：空路径、绝对路径逃逸、`..` 段、任一路径组件为 symlink/junction、realpath 逃逸 → `invalid_path` / `path_outside_root` / `path_traversal` / `symlink`
7. `installer.file` 只接受纯文件名（拒绝 `..\x.exe`、`C:\x.exe`、`nested/x.exe`），并要求与 `app_version` 命名一致

实现特征：

- `parseReleaseManifest`（:185）完整校验现有生成器字段，未知字段忽略以保持前向兼容。
- `resolveInsideRoot`（:334）对清单和每份产物逐段 `lstat`，拒绝 symlink/junction；再做 `realpath` 包含性复核。
- `verifyReleaseIntegrity`（:574）同步执行，适合在 `app.whenReady` 中、创建窗口/启动后端之前调用；三份产物全量读入内存计算 SHA-256（真实后端 exe 的启动阻塞成本尚未实测）。
