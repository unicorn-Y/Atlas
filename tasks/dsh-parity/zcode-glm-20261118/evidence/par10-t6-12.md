- 同时接入：渲染进程 CDP（19222）、主进程 Node inspector（19223）、独立心跳 HTTP 服务（19290，主/第二窗口各自定时 fetch 打点）、PowerShell 采样各 Electron 进程 CPU 与 `Responding`/`MainWindowTitle`、Win32 顶层窗口枚举与 `PrintWindow` 截图。
- 主进程 inspector 上启用 `Debugger.setPauseOnExceptions('uncaught')`，在 Electron 默认错误对话框展开前捕获抛出栈。

复现结果（`logs/diag2-open-window-run2.txt`，构建时间早于本轮修复）：

- 触发 `window.atlasDesktop.openNewWindow()` 后约 4s：

```
DEBUGGER_PAUSED {"reason":"exception","data":"Error: 此操作仅允许 Atlas 主窗口调用。
    at assertTrustedAppSender (dist-electron/main/electron.js:897)
    at IpcMainImpl.<anonymous> (dist-electron/main/electron.js:1502)
    at IpcMainImpl.emit (node:events:514:28)
    at Session.<anonymous> (node:electron/js2c/browser_init:1)","frames":[...]}

```

- 该 built 行 1502 对应 `ipcMain.on('task-hud:update', ...)`。第二窗口加载同一个 renderer bundle，`App.tsx` 的 effect 自动发出 `updateTaskHud`；主进程 handler 走 `assertTrustedAppSender`，对非主窗口直接 `throw`。`ipcMain.on` 的抛出逃出 `EventEmitter.emit`，成为主进程未捕获异常，Electron 弹出原生模态错误框。
- 旁证同时成立：mainEval/pageEval/截图全部超时；CDP `/json/list` 停止响应；Node inspector 的 HTTP `/json/list` 仍 1ms 返回但 `Debugger.pause` 3s 不被处理（主线程在原生模态消息循环里，不在 V8 里）；主进程 CPU 增量约 0.02–0.24s/2s（空转等待，不是 busy loop）；Win32 窗口枚举出现 `#32770`、标题 `Error`、子控件 `Button("确定")`。像素证据：`diag2/open-window/shots/dialog-open-window-1771950.png`。
- 结论：**产品缺陷，非探针自伤**。旧 Playwright 探针只是同样被这个模态框挡住；换任何客户端（含不用 Playwright）都会冻结。第二窗口并非“没有创建”，而是创建后触发主进程崩溃对话框，全应用停摆。

同一模式的其余 fire-and-forget 通道（`ipcMain.on` + `assertTrustedAppSender`）也会在第二窗口首屏触发，一并修复：

`runtime:set-state`、`browser:address-shortcut-target`、`task-hud:update`、`app:set-quit-activity`、`platform:set-screenshot-context`、`window:set-title`。

`ipcMain.handle` 的抛出只形成对 renderer 的 rejected promise，不会崩主进程，保持原语义不变。

另外探针实测到一个相邻缺陷：第二窗口的自绘标题栏“关闭窗口”按钮走 `window:close`，原 handler 永远作用于 `windowRef`，结果关闭/隐藏的是主窗口（`logs/51-window-controls-check.txt`：点击第二窗口关闭后 `id=1 visible=false`，第二窗口仍在）。同批修为按发送者窗口处理。
