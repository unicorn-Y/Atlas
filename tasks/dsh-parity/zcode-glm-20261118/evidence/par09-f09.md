## 2. DSH 语义对照

### 2.1 registryPlan

DSH `registry.ts:54-75` 的规则与 Atlas `registry_plan()` 对应关系：

| DSH 行为 | Atlas 实现 |
|---|---|
| 配置首注册表 + fallback 列表构成配置集 | `RegistryConfig(registry, fallback_registries, resolved)`；顺序为配置主源优先、fallback 在后 |
| 请求注册表在配置集内 → 先问它，其余在后 | `requested` 命中 `keys` → 移到首位，其余去重后跟随 |
| 请求注册表在配置集外 → 单独问 | `decision="requested-custom"`，`registries` 长度 1，`registry_refusal="requested-registry-not-configured"` |
| pnpm 自身 registry（`null`）仅在已知公共时入集合 | `resolved` 必须是 `OFFICIAL_NPM_REGISTRY` 或已配置 fallback 之一；否则 `None` 单独问 |
| pnpm 自身为私有/未知 → 单独问，不回落公共 | `pnpm-own-private` / `pnpm-own-unknown`，refusal 分别为 `pnpm-own-registry-private` / `pnpm-own-registry-unknown` |
| 同一注册表只问一次 | 按归一化 key 去重，`None` 的 key 为 `resolved` 归一值 |
| 计划永不为空 | 配置为空时返回 `(None,)` |

Atlas 明确区分两种“未指定”：`UNSET` 表示沿用配置主源，`None` 表示 pnpm 自身 registry。DSH 用 `undefined` / `null` 表达同一区分。

### 2.2 normalizeRegistry

DSH 只做 http(s) 校验、host 小写、补尾斜杠。Atlas 的归一化规则（模块 docstring 亦写明）：

1. 只接受带 host 的 http/https URL；其余抛 `ValueError`，不从裸 host 猜测。
2. scheme 与 host 小写。
3. 去掉默认端口（http `:80`、https `:443`），保留非默认端口。
4. 路径折叠重复斜杠、解析 `.`/`..`、保留恰好一个尾斜杠；无路径变 `/`。
5. query/fragment 原样保留（不参与“同注册表”判定，除精确相等外）。
6. 归一化时去掉 userinfo（`user:token@`），保证 plan 和 install state 不存注册表凭据。归一化 URL 只用于身份/顺序/去重；真正调用 npm/pnpm 时必须使用调用方传入的原始 URL（含凭据）。

归一化幂等；相同归一化结果即视为同一注册表。DSH 的浏览器/Host 双端一致约束在纯 Python 模块中不适用。

### 2.3 attributeFailure

DSH `registry.ts:78-97` 与 Atlas `attribute_failure()`：

- 可换注册表的失败类型：`network`、`timeout`、`not-found`、`no-matching-version` → `registry`。
- 其余类型 → `other`。
- git/tarball spec 的错误行点名其 host → `spec-host`。
- 错误行识别正则沿用 DSH：`ERR_|ERROR|\berror\b|fatal:|Could not resolve|unable to access|ssh:|\bE[A-Z]{4,}\b`。
- 仅警告行提到 host、或错误行未点名 host → `registry`。
- Atlas 增量：可选 `registry=` 参数；若错误行点名“本次尝试的注册表”host，则按 `registry` 归类，避免误判为 spec host。
- Atlas 增量：spec 无法解析时 → `other`（DSH 在解析阶段就抛错）；`spec=None` 时按无 host 处理，可重试类型 → `registry`。

### 2.4 spec 解析差异

DSH `install-spec.ts` 要求本地路径绝对、HTTP URL 必须是 git 仓库或 tarball。Atlas `PluginRuntime` 的实际行为更宽：

- 相对 `./`、`../` 路径按本地路径处理；任意 `http(s)` 非 tarball URL 由 runtime 当 git clone 目标处理。
- `owner/repo` 由 runtime 规范化为 GitHub；Atlas `parse_install_spec()` 对应返回 `git`、host `github.com`。
- 因此 Atlas 模块对任意非 tarball http(s) URL 返回 `git` + host，而不是拒绝。该差异已写进模块 docstring。

## 3. 模块契约

### 3.1 公开面

```text
OFFICIAL_NPM_REGISTRY = "https://registry.npmjs.org/"
NPMMIRROR_REGISTRY  = "https://registry.npmmirror.com/"
RETRYABLE_FAILURE_KINDS = {network, timeout, not-found, no-matching-version}
UNSET
RegistryConfig(registry, fallback_registries, resolved)
InstallSpec(kind, spec, name, host)
RegistryPlan(registries, requested, decision, registry_refusal, spec_kind, spec_host, direct_source)
normalize_registry(url) -> str
parse_install_spec(raw) -> InstallSpec
registry_plan(requested=UNSET, *, configured, spec) -> RegistryPlan
attribute_failure(kind, log, spec=None, *, registry=None) -> "registry" | "spec-host" | "other"
```

`RegistryPlan` 方法/属性：

- `fallback_allowed`：`len(registries) > 1`，只表示存在后续 registry。
- `retry_allowed(attribution)`：仅 `attribution == "registry"` 且存在后续源时为真；`spec-host`、`other`、单源均为假。这是“spec 自带 host 不得静默回落公共源”的执行判定。
- `to_dict()`：稳定 JSON 字段 `registries/requested/decision/registryRefusal/specKind/specHost/directSource/fallbackAllowed`。

`decision` 稳定代码：

```text
pnpm-own-public          配置主源是 pnpm 自身且已解析为公共源
pnpm-own-private         pnpm 自身指向私有源 → 单独问
pnpm-own-unknown         pnpm 自身 URL 未知 → 单独问
pnpm-own-not-configured  请求 pnpm 自身，但它不在配置集 → 单独问
configured-primary       使用配置主源
requested-configured     请求源属于配置集 → 前置
requested-custom         请求源不在配置集 → 单独问
requested-private-own    请求的 URL 等于私有的 pnpm 自身源 → 单独问
```

`registry_refusal` 稳定代码：

```text
requested-registry-not-configured
pnpm-own-registry-private
pnpm-own-registry-unknown
pnpm-own-registry-not-configured
```

`spec_kind`：`registry | git | tarball | path | unknown`。
`direct_source`：`registry | local | git | tarball | unknown`。

### 3.2 关键不变量

1. `registries` 永不为空；`None` 仅表示 pnpm 自身 registry。
2. 私有或未知的 pnpm 自身 registry 永远单源，后面不追加公共 fallback。
3. 显式请求且不在配置集的 registry 永远单源，`registry_refusal` 给出原因。
4. spec 自带 host 时 `direct_source` 为 `git`/`tarball`，`retry_allowed("spec-host") == False`；依赖解析的 registry 列表仍保留，但 direct source 失败不能换公共 registry。
5. 仅 `registry` 类归因能推进到下一注册表；`other` 与 `spec-host` 都不能。
6. 纯函数，无网络、无文件、无账号、无凭据；输入本地数据即可断言。
