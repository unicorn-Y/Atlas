### 3.1 runtime 适配要点（不盲打旧 T1 补丁）

- `start_install_operation(..., fallback_registries: list[str] | None = None, ...)`：先 `build_install_plan()`；非法 registry 抛不带原始 URL 的 `ValueError("registry configuration is invalid")`。
- 快照新增 `registryPlan`（归一化 URL，无 userinfo）；requestId 摘要仅在 fallback 非空时追加 fallback 元组，空 fallback 保持旧 requestId 摘要兼容。
- npm pack / pnpm 依赖 install / 审批后二次 install 全部经 `run_registry_attempts`：只有 `attribution == "registry"` 且存在下一源才回退；`ERR_PNPM_IGNORED_BUILDS` 保持审批流而非换源；取消检查在每次 attempt 前后；attempt 输出先脱敏再入 `registryAttempts/dependencyAttempts/approvedBuildOutcome`。
- git/marketplace clone 失败写 `failureKind/failureAttribution/failureSummary` 并脱敏；`spec-host` 不触发回退。
- 审批、取消、`too_late`、Unknown/PreviousRuntime、状态快照字段与失败错误码映射未改。
- AST 复核：`registryPlan` 位于 `start_install_operation` 函数体顶层；`registryOutcome` 位于 `source_type == "npm"` 分支；`dependencyOutcome` 位于依赖安装 `try`；`approvedBuildOutcome` 位于 `if blocked` 内，均无缩进落错分支。

### 3.2 router 适配要点

- `/api/plugins/install` 与 `/api/plugin-marketplaces/{name}/install` 校验并转发 `fallbackRegistries`（list、≤8、元素字符串，否则 422）。
- 新增 `GET /api/plugins/registry/versions?name=&registry=&installed=&version=&fallbackRegistries=...`：
  - registry 选择直接调用安装链同一个 `build_install_plan()`，响应回显 `registryPlan`；私有/显式请求计划始终单源，`registryRefusal=requested-registry-not-configured`。
  - `fallbackRegistries` 用重复 query 参数；每个 fallback 先过与主源相同的凭据/query/fragment/端口校验。
  - 仅 http(s)、拒绝 userinfo/query/fragment/非法端口；包名白名单（含 scoped）；15s 超时；8 MiB 上限；15s/8MiB 为模块常量。
  - 重定向只允许同 scheme+host+port；跨源 302 直接拒绝（502），响应最终 URL 再次核对 origin。
  - 不发送 Authorization/Cookie；错误 detail 不回显 registry URL/异常文本/私有路径。
  - 读取失败按 `attribute_failure` 判定是否换源：public/已授权源可回退，私有单源不回落；404 全失败→404，其余→502。
