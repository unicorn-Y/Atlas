## 3. 修复

### 3.1 补丁携带：`.originals` 跟随新版本刷新

`patch_layer.carry_over` 现在：

- 先把旧 `patches/files/**` 合并进新树（新发行版自带补丁的同路径优先，不覆盖）；
- 再按新树中实际存在的补丁 key，用 `new_root/<key>`（尚未 materialise，仍是新上游字节）重写 `patches/.originals/<key>`；
- 新上游删除了该文件时移除旧 `.originals`，使该补丁按“新增文件”报告，而不是在 revert 时复活 v1。

对应测试：`test_carry_over_refreshes_the_original_to_the_new_upstream`、`test_carry_over_drops_an_original_when_upstream_removed_the_file`；端到端见 §4。

### 3.2 Windows 文件锁：rename 交换 + 有界重试 + 终态不被清理污染

`runtime.py`：

- `_FS_RETRY_DELAYS=(0.05,0.1,0.2,0.4,0.8,1.6,2.0)`（约 5s）；只重试 `WinError 5/32/33` 或 Windows `PermissionError`。
- `_rmtree`、`_copy_tree`、`_replace_path` 全部走重试；`_copy_tree` 每次重试先清掉半成品目标。
- 安装提交顺序改为 **staging → prepared → rename 旧 target 到 transaction backup → rename prepared 到 target → 成功后再删 backup**；任何一步失败时旧版本仍在原位或 backup，可读且可安全重试。
- `.sources` checkout 的 `.prepared → <name>` 提升同样走重试；失败时恢复 `previous-source`。
- rollback 每一步单独 try/except 并把失败写 `operation["rollbackErrors"]`，不会因为回滚异常丢掉终态。
- `finally` 清理改用 `_rmtree_quiet`：清理失败只记 `plugin.cleanup_deferred` 日志，不改写 `completed/failed/cancelled` 终态；已完成的安装不会因删 backup 失败被降级为失败。
- `incoming/previous` 全部点号前缀（`.<name>.incoming` / `.<name>.previous`），延迟清理的目录不会被 `discover()` 当成插件；`_copy_replace` 发现 target 缺失而 `.previous` 存在时先恢复它，避免 crash 后删掉唯一完整副本；`incoming` 在交换失败时也清理。
- `_rmtree` 保留 Python 3.11 `onerror` / 3.12+ `onexc` 分支，Python 3.14 交叉跑覆盖。

### 3.3 pnpm 参数位置

`_run_package_manager` 把全局参数放在子命令之前：

```
node <pnpm.mjs> --ignore-pnpmfile --store-dir ... --state-dir ... [--registry=...] install --reporter=append-only
```

避免部分 pnpm 版本把 `--store-dir` 当成 `install` 的未知参数；真实 pnpm 12.4.1 夹具通过。新增 `test_pnpm_global_options_precede_the_subcommand` 固定这一顺序。
