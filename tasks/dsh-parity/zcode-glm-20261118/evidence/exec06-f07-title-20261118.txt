D. 差距(相对 DSH)
================================================================================
G1 AgentOrchestrator.run / app-server / SDK 路径无自动标题(仅 AtlasRuntime 桌面运行路径有)。
G2 无 `session/title-llm-request` 精确辅助请求事件(DSH 记录 route/system/messages/
   maxTokens/reasoningEffort,可重建请求);Atlas 只发最终 session.title。
G3 无 provider 插件面(first-prompt/all-prompts)、无可配 targetWords/targetCjkCharacters、
   无 maxTitleBytes/fallbackMaxBytes;Atlas 提示与 48 字/3-7 words 为硬编码常量。
G4 无 title-invalid 错误码;无效输出仅回退 derived。
G5 all-prompts 语义缺失:Atlas 只取当前 message(+preview),不聚合多条人类消息;
   虽在前 3 个用户回合可重试,但输入集合不同。

E. 验收标准(二值)
================================================================================
A-1 AgentOrchestrator.run 路径:首条可命名消息后发 derived title 事件并持久化;
    配置开启 LLM upgrade 时再发 llm 事件;标题任务不阻塞 run.completed。

    payload 可重建实际请求。

    maxTitleBytes 生效;超时→SESSION_TITLE_TIMEOUT 或 fallback,工具调用输出拒绝。

    事件契约三真源(test_event_contract)随新事件更新。

blocked-on-author;可先在 agent 层新增独立 title hook 模块,但接线点冲突,不并写。
