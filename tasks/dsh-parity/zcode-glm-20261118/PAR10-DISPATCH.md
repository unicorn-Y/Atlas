# PAR-10 · 逐包验收与接续

继续当前 Atlas ZCode 会话，保留当前模型与 PAR-09 MCP。SDK E 保持暂停。先读 D:\Atlas\AGENTS.md、QUEUE.tsv、PROGRESS.md 与本包指定证据。按下面顺序并发启动 T1–T4，算上旧 MCP 最多五个原生后台 Agent。T5 只等 MCP 释放其工作树。提交每个新任务后记下子代理 ID。主会话持续审核已交付证据，禁止全员 join。

## 双通道回执与自动接续

- 每个子代理有独占工作树。交付时写 evidence/par10-<包号>.md，包含工作树、基线、功能入口、修改文件、可重跑命令、退出码、失败及未覆盖项。最后一行写 `PAR10_RECEIPT <包号> READY|PARTIAL|BLOCKED`，立即向 ZCode 主会话报告同一标记和回执路径。失败、断线及需接管的包同样要及时汇报已有产物。
- 主会话收到任一完成事件或发现新回执就收件。先确认对应子代理已经停止写该工作树，再查实际 diff 并复跑该包关键路径。两条通道按批次和包号去重。只有主会话更新 QUEUE.tsv / PROGRESS.md。状态区分候选工作树、验证通过、链路待接、阻塞。主会话每次在当前对话立即写一条 `PAR10_REVIEW <包号> <结论> <证据路径> <已派的包号或阻塞>`，供 Codex 观察。
- 空出工位时立即派发已解依赖的包，随后继续复验。已有包出现可独立复现的缺陷时，使用同一包的新尝试编号派发定向修复，保留上次回执。外部阻塞仍未解除时落盘最后现场，先跑可推进的其他包。Codex 当前会话会独立监看事件和证据。ZCode 主会话继续执行本任务书里的派发和验收，无需等 Codex 在线应答。若 Codex 发来验收或接续编号，按编号合并记录，避免重复启动。
- 沿用现有未提交边界。保留原作者在途文件。需要使用旧工作树产物时，先确认源树写者结束，把明确文件或最小 diff 移到新的隔离候选树，记录基线和摘要。消费已有功能时尽量调用现有入口，无关文件和用户数据不写。无主树合并、提交或推送。测试只用临时项目、测试数据库、回环服务；沿用现有隐私与凭据约束。

## 首发四包

1. **T1 注册表策略接入实际插件安装。** 新候选树 `zcode-par10-registry-runtime`。从 `zcode-par09-plugin-registry` 移入已复验策略，参考 `evidence/par09-f09.md` 和 wiring patch。对真实安装入口接入计划、回退、失败归因。在本地模拟 registry / package manager 下验证正常安装、公共源失败后的允许回退、私有及显式源失败时不切到公共源、包 spec 自带 host 和输出脱敏。实际安装链有冲突时报告文件、行及替代测试范围。
2. **T2 在隔离发行产物接入启动完整性校验。** 新候选树 `zcode-par10-release-startup`。参考 `evidence/par09-f01.md`，将已验证模块接入实际打包清单生成和 packaged Electron 启动入口，清单与安装/升级用的实际路径及构建时序保持一致。验证正常产物、缺清单、受检文件损坏、开发态启动及一次已有安装的兼容验证。使用临时打包目录或复制的发布产物。真实打包若缺本机依赖，留可复现命令和错误，区分真实 packaged 启动和测试夹具。
3. **T3 工作区技能源从桌面会话连到列表和调用。** 新候选树 `zcode-par10-skill-runtime`。参考 `evidence/par07-c.md`（如文件名有变化按 QUEUE.tsv 定位）与 PAR-08-C 最新回执。从 `zcode-exec06-skill-sources` 保留已验证的 per-run workspace 作用域，补核 `use_skill` 和 skills router / Desktop 列表是否使用同一工作区视图。用两个含同名技能的临时工作区，从桌面或等效正式产品入口验证列出、调用、优先级及跨工作区隔离。涉及事件变更时同步三个真源。
4. **T4 桌面与工作树集成候选。** 新候选树 `zcode-par10-desktop-recovery-candidate`。逐项拿取已验 CSV/TSV、快捷键 B2 与工作树恢复 D2 的最小差异和基线，组合成一个供主控复审的候选。复跑 A 的空文件 / 空字段 / TSV，B 的真实双窗初次保存和同 action 裁决，D 的临时仓库回滚、恢复与路由快照。任何组件基线冲突都单独留证，其他互不依赖项继续验证。交付可转移的最小 diff 和逐项证据。

## 后续槽位

5. **T5 MCP 子进程退出状态和恢复。** PAR-09 MCP 回执存在且旧写者结束后，使用新候选树 `zcode-par10-mcp-recovery`。以 `evidence/par09-mcp-lifecycle.txt` 和 MCP 最终回执为基线，先核实 DSH 可观察行为和 Atlas 现有重试策略。复现工具可调用后子进程退出，检查连接状态与工具索引、健康事件及是否有界重连。实现已验有缺口的最小补齐，明确用户停止、配置禁用、并发 stop/restart 的语义，不让已停用实例被拉起。用真实本地 stdio 测试异常退出、重连或有证据说明的真实恢复入口、多服务器互不影响。旧的打包 Node 证据要对应产物路径、版本和实际调用。
6. **T6 当前差距队列接续。** 任一工位空出且上述可执行包已派完，从最新的 QUEUE.tsv/PROGRESS.md 挑与现有写者无冲突的具体已证实产品缺口。先把选中的行、实际入口、工作树、验收命令写进单独任务书，再发新包。逐包编号为 T6-1、T6-2 等，继续沿用收件规则，任一时刻最多五个。优先对现有工作树产品接线和真实入口闭环，保留 SDK E 的暂停状态，将需用户授权、私有云端或本机无法验证的项记录为对应阻塞。仅当当前已授权队列确实没有可继续的独立工作时收尾，并留下待解除的具体依赖。
