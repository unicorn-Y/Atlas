# 统一协议：Atlas 竞品实物逆向研究（2026-10-19）

**本协议约束本目录每份独立会话任务书；它是必读的工作要求，不是功能分类边界。**

## 任务的真正目标
以实际发行物、源码、运行行为、官方更新、插件生态为材料，**主动发现产品全部可观察、可追踪的能力**，不只查用户举过的例子，不拿既有功能矩阵当上限。前端、运行时、会话管理、子代理、动态消息与界面扩展、上下文、模型路由、工具、搜索、检索、文件与终端、后台任务、恢复、观测、成本、权限、更新、兼容层、插件及网络协议都要从实际证据中发现；这个枚举只是提醒，不是必须填满的封闭目录。

不要主观先认定“这是小功能不值得查”。发现某个入口，沿**交互→状态/事件→接口/工具→宿主和执行引擎→存储与恢复**追踪完整调用链。发现底层机制时，反查它服务哪些用户能力。真正的未知要标注，不要补想象。

## 调研路径（必须真正做，而不是只按以下分类列菜单）
1. 识别全部包形态和上游版本：Desktop, CLI, engine/runtime, 插件/扩展, Web UI，分辨官方与社区、公开与闭源；确认包的关键入口/模块文件树。
2. 基于真实资源逆向探索：实际可读源码、前端路由和组件、资源、菜单 action、命令注册、快捷键、网络/IPC/RPC/事件、状态存储、工作循环、子任务执行、流式协议、任务恢复。必要时机械提取 ASAR、MSIX、VSIX、TGZ、JS/CJS、二进制字符串/符号等。涉及压缩或混淆需标明确认级别。
3. **双向发现**：从所有入口寻找实现；从引擎源头反向寻找用户可见功能；从版本变更寻找新增行为；从插件生态寻找可嵌入宿主的能力；从启动到正常、异常、中断、恢复完整追踪生命周期。
4. 把每项能力拆到**行为与机制层**，不止写“支持子代理”。对于关键能力，标注触发条件、输入输出、谁保存状态、执行时序、状态错误/恢复、相关 UI 与源码路径。
5. 横向查漏：与官方 changelog/issue/文档、源码字符串与路由、内置实验开关、扩展入口相互对照。新增发现继续扩展领域，不受过去矩阵限制。
6. 对照 Atlas 当前 main **相关真实代码**：给出等价实现/部分实现/缺失/未知，区分“有按钮”“有接口”“后端接线”“真实能用”；给缺失的成熟机制可移植来源、许可和建议文件锚点。**不要在研究阶段就直接施工或大范围重构**。

## 证据等级与可检验性
每个有价值发现指定 ID `<SLUG>-001` 等；记录产品版本、包名+SHA/commit、精确源码路径及符号/行号、UI 入口与行为、对应技术链路、证据等级：
- **S**：源码/包内明确代码或符号及调用链（须给文件+位置）
- **R**：当前版本实际运行、操作和观察（须给复现步骤/截图描述/日志）
- **D**：官方文档或 changelog，只能证实声明，不代表本包实现
- **I**：有限推断，标注理由，不能写成已确认
- **U**：无法验证，列解锁所需的最小材料/操作。

插件能力一定单独注明是官方宿主原生、官方扩展、社区扩展还是外部服务。客户端内部存在协议不意味着服务器端实现已知。静态字符串出现不等于功能可用。竞品可用不等于 Atlas 可用。
