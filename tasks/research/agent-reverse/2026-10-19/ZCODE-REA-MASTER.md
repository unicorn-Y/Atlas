# ZCode + DSV4.1 Flash：Agent 全量解剖总协议（2026-10-19）

## 任务定位（最高优先级）
执行者：**ZCode**，模型使用用户在 ZCode 中配置的 **DeepSeek V4.1 Flash**。逆向工具主力 **REA (morluto/rea)**，其他合适的解包、反编译、动态调试和截图工具按实际需要配合。一个 **ZCode 独立会话只研究一个 Agent 产品**（同产品的 Desktop/CLI/Runtime 若属于相同产品体系可在该会话完整覆盖；不同社区项目分开会话）。

**不是 Atlas 改造，不是竞品功能筛选，不是只读 README，不是写几份总结报告。**
目标是把目标产品的完整实物尽可能“解剖”成可查找的原始提取物、逐项代码/资源/模块索引、前端视觉与交互图鉴、后端和运行机制的通俗解释、证据链。所有发现（包括看似小、旧、隐藏、实验性和不适合 Atlas 的功能）都纳入图鉴；由用户在最终图鉴里亲自挑选，不能由执行 Agent 提前过滤。
原则：**先拆完一个、归档一个、做成可以看的图鉴，再换下一个；最后统一整理全部产品**。

必须实际补采可获得的缺件、本地落盘、GitHub push，并生成 `READY-TO-REVERSE.md`。**全目标预检记录建立前，不得进入任何产品的逆向执行。** 预检完成后，只能对 READY 产品开独立拆解会话；不齐则先补采，不把旧采集文档的 COMPLETE 当当前最新版证明。已知仅在厂商服务器运行、未公开发布的内部代码须标注不可取得边界。

## 每个会话的固定执行顺序

### A. 完整标本登记（先全量盘点，再解释）
1. 锁定产品、版本、发行包、源码快照、官方/社区来源、平台架构、对应 SHA256；不同版本各自独立登记。
2. 对给定安装包逐层解包：安装器、MSIX/ZIP/ASAR、应用目录、可嵌套压缩、JavaScript bundles、DLL/EXE、native addons、数据库、资源、插件、脚本、配置等。对于无法展开的压缩/加密/未知数据，也登记实际偏移、大小、哈希、原因。重复文件可按哈希去重，保留每个来源路径。
3. 为**每个叶子文件**建立 machine-readable 清单：ID、来源包、容器路径/完整嵌套路径、哈希、字节大小、类型、作用分类、对应解析输出、处理状态、是否第三方/生成物、是否尚未解释。不能只列目录前两层或只收主模块。
4. 以原始文件清单对照解包产物与分析产物，检查丢失/漏扫项。原始安装包保留，不以提取物代替。

### B. 每项文件与代码分析
1. 可读代码：提取、格式化，扫描全部模块、导入导出、函数/类、命令和路由注册、资源引用、配置与运行入口；索引到文件+行/符号。不能仅阅读搜索命中的几十行就宣称“全代码已分析”。
2. 编译/混淆代码：用 REA 与相关工具反汇编/反编译，输出符号/函数列表、伪代码、交叉引用及调用图；可分析的产品相关函数逐项追踪；无名称函数用地址+哈希+所在二进制标识。
3. 每个重要产品实现都要用通俗中文解释“是什么 / 在哪里 / 为什么存在 / 输入输出 / 怎么运行 / 与什么关联 / 能从哪里调用 / 失败和恢复怎样处理”；低价值第三方库也必须在文件层全量登记并标出依赖关系，而不是静默删除。
4. 不能恢复为原始源代码的，保留机器码/字节或容器原件、反编译结果、不可恢复原因。**逐字节盘点 != 每一行原始源码恢复**，两项覆盖率分开统计。
5. 隐藏 feature flag、实验性 UI、废弃代码、未显示注册项、IPC 通道、内部工具、配置开关、后台进程入口均主动发现，不以预定功能目录为边界。

### C. 前端——让用户能亲自看到
1. 针对真实可运行版本，完整遍历可发现的每个页面、弹窗、右键菜单、快捷键触发界面、状态组件、工具消息、子代理面板、设置项、切换状态。记录 UI 入口、动作、输出和运行条件。
2. **真实截图优先**；能录屏录 GIF/MP4；能从安装包抽取的 UI 图片、SVG、字体、主题、CSS、icon、布局及动画资源建立独立图鉴；能单独运行交互的做本地 HTML Demo。
3. 每个可交互 Demo 与真实产品截图分别标注。Demo 若只是外观/逻辑复刻，必须写清“重建演示、非原应用”，不得用生成图冒充真实截图。
4. CLI/TUI 记录实际交互录屏、命令帮助、输出状态、错误流程；Web UI 记录页面和动态状态。
5. 每项界面元素支持从图鉴点击跳转到：截图/视频→真实资源或组件→触发事件→API/IPC/进程→后端实现。

### D. 后端 + 中间运行层——让用户理解看不见的
从每一项入口双向追踪：启动/更新/退出、窗口和进程、前后端 IPC/RPC/WebSocket/HTTP、消息和事件协议、model gateway、LLM 请求/流式消费、Agent loop、任务规划、子代理创建/并发/委派/消息、工具执行、终端/文件/浏览器/Computer Use、Skills/MCP/插件、上下文/压缩/Token、Session/Thread/branch、存储/恢复/重试/异常/超时、队列/后台工作、UI 更新。只要标本里存在其他子系统，继续发现并纳入。
所有重要链路均写出：用户操作或触发源 → 前端事件 → 通信 → 宿主/引擎 → 工具/模型/存储 → 返回事件 → UI；从后端入口反查其所有上层调用者，防止漏掉隐藏能力。关键结论须能定位包/文件/函数/行/地址及相应运行证据。

### E. 主动补漏直到有明确覆盖统计
维护四张自动更新的总账：
- FILES：所有文件/容器成员及每个处理状态。
- SYMBOLS：源代码函数、类、路由、事件、原生函数及其位置/调用关系。
- UI：页面、组件、入口、状态、截图/录屏/Demo 和实现映射。
- FLOWS：业务功能与端到端运行链。
所有未知区域都保留条目和理由，不得靠删掉未知项提高完成率。覆盖指标至少分别给出：**文件登记覆盖率、文件内容解析覆盖率、符号/函数枚举覆盖率、深度机制解释覆盖率、动态验证覆盖率、界面可视化覆盖率**，提供分子/分母和计算范围。目标是文件登记 100%，其余指标按实测如实报告，不准假报 100%。
不要用大量无意义测试耗费时间；验证直接围绕真实功能、提取正确性、可浏览产物与阻塞点。

## 阶段完成与终结条件
只要仍有未登记文件、未枚举的产品代码符号、可追的未知链路、待访问的 UI 入口，就继续拆，不要“写完报告就宣布完成”。阶段性 push 和本地 checkpoint 可用 STATUS=IN_PROGRESS/NEEDS_INPUT，**不是 FINISHED**。缺真实运行权限或缺关键包，标明 BLOCKED 并继续其他可执行工作；禁止虚构。
标注静态源码证据 S、运行观察 R、官方声明 D、推断 I、未知 U。远程服务器无法直接取得的内部实现列为 U，不能声称它存在于本地包里。遵守合法许可，不采集或提交用户的 Cookie/Token/私密数据，也不尝试绕过登录或付费系统来取得服务端源码。
回报格式：ZCODE REA | 产品 | 版本 | 分支 | commit | 本地 viewer 路径 | GitHub 图鉴入口 | 文件登记覆盖率 | 机制解释覆盖率 | REMOTE_NOT_SYNCED | 阻塞项。
**没有实际 push、没有本地完整材料、没有可打开的 viewer 时，不得宣称该 Agent “拆完了”。**
